# 面试自测：20+ 问与参考要点

用法：先遮住答案自答，再对照。**只要求"要点命中"**，不要求背原句；答不出的题回到对应文件/教程单元。

> 诚实提示：下面所有回答都以"代码里确实这么做"为前提。凡是本仓库没验证过的（真实模型、并发、性能数字），回答里必须带上"未验证"。

## A. 项目定位与取舍

**1. 用一句话介绍这个项目。**
经营数据分析助手：自然语言问题 → 规则解析口径 → 知识库检索 → SQLite 取数 → **程序计算** → 带来源的 Markdown 报告 → 人工审批 → 本地导出。模型可选，数字不依赖模型。

**2. 为什么不用 `create_agent` 让模型自己选工具？**
业务口径要求可审计、可复现：同一问题必须得到同一数字。固定工作流（`workflow/graph.py`）保证步骤与口径稳定；Agent 路线保留在 `agent/` 作为对照，适合探索型问题，不适合出正式经营报告。

**3. LangChain 和 LangGraph 在这个项目里各负责什么？**
LangChain：模型适配（`init_chat_model`）、消息、`@tool`、结构化输出、`create_agent`、文档加载/切分/检索组件。LangGraph：状态图编排、条件路由、循环与预算、检查点、`interrupt` 人工审批、恢复。

**4. 什么时候你会说"这里不需要 LangGraph"？**
单次调用、无多步状态、无中断/恢复、无循环时——一个函数加 `try/except` 更简单。图的价值在"多步 + 状态 + 可恢复"。

**5. 为什么不用多 Agent？**
子任务共享同一口径且要求数字唯一，多 Agent 只会引入不一致与调试成本。多 Agent 适合目标不同、工具不同、可独立评估且允许不确定性的任务（如研究+审查）。

## B. 状态与编排

**6. `AssistantState` 里哪些字段有 reducer？为什么？**
`messages` 用 `add_messages`（多轮追加）；`trace`、`errors` 用 `operator.add`（跨节点/跨轮累加）。`sources` **没有** reducer——这是已知权衡，靠节点自读旧值，漏读会静默丢来源（见 limitations.md）。

**7. 一条路由是怎么决定的？**
`route_after_understand` 看 `status` 是否终态与 `route` 合法性；`route_after_data` 看最近一条 `node="data"` trace 的 `ok`/`retryable` 与已修复次数；`route_after_review` 看审批结论。

**8. 怎么防止图无限循环？**
状态里维护 `budget`（默认 steps=12、tool_calls=8），节点进入前 `_guard_step`、工具前 `_guard_tools`；超限写 `budget_exceeded` 交给 `fail` 出口。`recursion_limit` 只是最后保险。

**9. repair 节点做什么？**
处理可重试的数据查询错误（如 SQLite 临时锁）：修正参数/重建预期后回到 `data`，最多重试一次（`MAX_REPAIR_ATTEMPTS`），仍失败则 `fail`。

**10. 状态字段为什么不能每轮全清空？**
追问依赖上一轮 `last_spec`（当前/对比月份、地区）。`initial_state` 故意不包含 `last_spec`，否则每轮输入会把它覆盖成空。

## C. 持久化与 HITL

**11. `InMemorySaver` 与 `SqliteSaver` 各自适合什么？**
测试/实验用内存（快、无残留）；演示与生产用 SQLite（重启可恢复）。`AppRuntime.create(..., use_memory_checkpointer=True)` 切换。

**12. 重启后为什么还能继续审批？**
状态写在 `data/checkpoints.db`；`read_thread` 从检查点读回 `awaiting_approval` 与 interrupt 载荷，`resume_turn` 用 `Command(resume=...)` 继续。

**13. `interrupt()` 恢复时节点为什么重跑？副作用怎么办？**
LangGraph 从节点开头重新执行，`interrupt()` 之前的代码会再跑一遍。所以 `review_node` 之前只做纯读/纯算，落盘放在独立的 `export_node`。

**14. 怎么保证导出幂等？**
固定文件名 `report-<thread_id>.md`；临时文件 + `os.replace` 原子写；`resume_turn` 发现无待审批且已导出时直接返回既有结果。

**15. `State` / `Checkpointer` / `thread` / `Store` / `Runtime Context` 的区别？**
State 是图内传递的数据；Checkpointer 持久化图状态；thread 是会话键；Store 是跨会话长期记忆；Runtime Context 是调用时注入的依赖（连接、知识库、模型），不写检查点。

**16. 你们的 Store 是官方实现吗？**
不是。`PreferenceStore` 是 SQLite 鸭子类型适配器（`get/put/search`），只覆盖本项目用到的语义，文档里标为**教学简化**。

**17. 审批"编辑"怎么防止改数字？**
`_edited_report_or_draft` 校验原报告中的数字是否仍全部存在，并拒绝新增数字；不通过则回退原草稿并写 `REVIEW_WARNING`。它防不住同义改写级别的措辞篡改（已知限制）。

## D. 数据与检索

**18. 退款算在哪个月？为什么？**
按 `refunds.refund_date`（退款发生月），只统计 `status='approved'`。这样"9 月退款"影响 9 月净额，而不是原订单月。

**19. 上期为 0 时变化率怎么处理？**
`pct_change=None`、`base_zero=True`，并在 notes/报告里说明"以 0 为基期无定义"，绝不输出 `inf` 或 `0`。

**20. "无记录"和"真零"怎么区分？**
`MonthSales.has_orders` 为 False 是无记录；有订单但 `gross == refund` 且 `net == 0` 是真零。报告「数据边界」小节分别说明。

**21. 怎么保证地区差额之和等于总差额？**
`compare_months` 统一按地区明细计算并 `region_delta_sum_cents` 校验；独立标准答案脚本再算一遍，`region_delta_sum_matches` 必须为 True。

**22. 检索为什么先用关键词基线？**
可解释、无依赖、可离线复现，能作为向量检索的对照基线；哈希向量是确定性词面向量，**不是语义模型**，同义改写会漏召回。

**23. 模型编造引用怎么处理？**
`_validate_citations` 要求引用 id ⊆ 本次命中块，否则回退模板答案；引用必须能在索引里查到。

**24. 资料不足时怎么回答？**
`answer_from_knowledge` 在最高分 < 0.15 或没有命中时返回 `insufficient=True`，明确写"现有资料不足以回答"并列出已检索文档。

## E. 工程与评估

**25. 为什么坚持"数字由程序算"？**
可审计、可复现、可测试。模型算数不可靠且无法解释；本项目让模型最多润色**不含数字**的段落，报告数字由模板注入。

**26. 你怎么测试的？**
`tests/`：真实 SQLite（不 mock 数据库/计算）、独立标准答案交叉验证、审批与重启恢复、API 契约；`eval/cases.jsonl` 覆盖正常/澄清/边界/预算/审批三态；模型行为单独评估（当前未做）。

**27. `status_matched` 是准确率吗？**
不是。它只比较工作流状态是否符合用例预期；模型行为（工具序列、答案质量）未评估。

**28. 为什么没生成 `uv.lock`？**
环境无法启动进程，`uv lock` 跑不了。仓库钉死了 LangChain/LangGraph 四个包的精确版本，锁文件由学习者首次 `uv sync` 生成并入库；我不会伪造锁文件。

**29. 这个项目能直接上线吗？**
不能。缺鉴权、审计、并发隔离、真实数据接入；单 worker + 本地 SQLite。它是"工程约束"的演示，不是生产系统。

**30. 如果给你两周，你优先做什么？**
①真实 embedding + 召回评估集（检索质量是最大短板）；②`sources` reducer（消除静默丢来源）；③并发审批幂等与审计；④LangSmith/本地追踪补齐模型行为评估。按风险×收益排序。

## 附：60 秒项目介绍（可直接背）

> 我做了一个经营数据分析助手：用户用中文问"九月比八月销售额变化多少、按地区分解"，系统解析口径、检索指标定义与退款归属的知识库、查 SQLite、用程序算差额，生成带来源的 Markdown 报告，然后停下来等人工审批，批准后才落盘。
> 核心设计是数字全部由程序计算、模型只做可选润色且不允许出现数字，所以无 API Key 也能跑通全链路。
> 用 LangGraph 固定工作流而不是让模型自由选工具，因为口径要可审计、可复现；同时保留 Agent 路线做对比。
> 我验证了确定性路径的测试与评估脚本，但环境限制没跑真实模型调用，这点写在 verification 文档里。

## 附：设计权衡速查

| 选择 | 放弃了什么 | 换来了什么 |
| --- | --- | --- |
| 固定工作流 | 灵活性 | 可审计、可复现、可测试 |
| 程序算数 | "自然语言直接出结论"的顺滑感 | 数字可信、可追溯 |
| 哈希向量 | 语义召回 | 离线、确定性、零依赖 |
| 单 worker + 锁 | 并发吞吐 | 实现简单、状态一致 |
| 本地文件导出 | 协作与权限 | 演示成本低、无外部依赖 |
| 审批前不落盘 | 一步到位的体验 | 人工兜底、避免错误报告外流 |
