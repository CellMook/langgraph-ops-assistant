# 退款规则与归属口径（演示口径）

> 本文件是演示项目「经营数据分析助手」的知识库文档之一，**全部为演示口径**，不代表真实财务政策。数据范围 2025-01 至 2026-09，金额在数据库中一律以「分」存储。

## 1. 退款算在哪个月

- 退款按 `refunds.refund_date`（退款发生日期）所在月份归集，**不按原订单月份**。
- 示例：订单 `order_date = 2026-08-25`，退款 `refund_date = 2026-09-05` 且状态 `approved`，该笔退款计入 2026-09 的退款额，只降低 2026-09 的净销售额，**不会回头修改 2026-08 的数据**。
- 因此同一张订单可能同时影响两个月份：8 月体现销售，9 月体现退款扣减；回答“退款算哪个月”时必须说明这一点。

## 2. 三种退款状态

| 状态 | 含义 | 是否计入退款额 |
| --- | --- | --- |
| approved | 已批准 | 计入 |
| pending | 待处理 | 不计入，但报告中提示“存在待处理退款” |
| rejected | 已拒绝 | 不计入 |

演示数据生成规则：退款概率 8%，状态权重 approved 0.7 / pending 0.2 / rejected 0.1；同一订单可能对应多条退款记录。

## 3. 净额为零、负净额与零基数的区别

- **真零**：当月毛销售额与已批准退款恰好相等，净额为 0，但订单数大于 0，应写“净额为 0（有订单，退款冲抵）”，不能说“没有销售”。
- **负净额**：退款大于毛销售额，净额为负，属于正常展示；只有在资料支持时才解释原因，否则写“可能相关，需进一步验证”。
- **零基数**：上期净额为 0 导致变化率无定义，这与“本期净额为 0”是两件不同的事。

## 4. 数据里的已知边界事实

- R_SW 西南在 2026-09 的已批准退款合计恰好等于该地区当月毛销售额，净额为真零。
- R_NORTH 华北在 2026-07 至少有 2 笔退款且全部为 `pending`：退款记录存在，但金额不计入退款额。
- 至少 3 笔跨月退款：订单在 2026-08、退款在 2026-09 且状态 `approved`，其中 1 笔的金额写入标准答案。
- 2026-03 至少有一个地区退款大于毛销售额，净额为负。

## 5. 常见错误与对应纠正

- 把 `pending` 当作已退款扣减 → 低估净销售额；纠正：只对 `approved` 求和。
- 按订单月份归集退款 → 跨月退款归错期间；纠正：一律取 `refund_date`。
- 用商品目录价代替订单成交价 → 毛销售额偏高；纠正：用 `orders.unit_price_cents`。
- 用浮点数存钱 → 出现分位误差；纠正：全程整数分，只在展示前换算。

## 6. 已知缺口与限制

- 退款原因字段 `reason` 只作展示，不参与任何指标计算。
- 演示数据由固定随机种子 20260901 生成，不是真实业务数据，不能据此推断真实退款率或经营结论。
- 不提供退款时效、退货物流、客服工单等数据，因此无法回答“退款为什么发生”这类因果问题。
