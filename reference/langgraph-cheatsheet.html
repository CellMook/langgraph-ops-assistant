1. 最小图：State → 节点 → 边

from typing import TypedDict
from langgraph.graph import END, START, StateGraph

class State(TypedDict, total=False):
    question: str
    answer: str

def understand(state: State) -> dict:
    return {"answer": f"收到：{state['question']}"}

builder = StateGraph(State)
builder.add_node("understand", understand)
builder.add_edge(START, "understand")
builder.add_edge("understand", END)
graph = builder.compile()

result = graph.invoke({"question": "九月销售额是多少？"})
print(result["answer"])
  • 节点返回 状态增量（dict），不是完整状态。
  • START/END 是特殊节点；没有边指向 END 的图不会结束。
  • total=False 表示字段可缺省，适合"逐步补齐"的状态。

2. reducer：多节点写同一字段

import operator
from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class State(TypedDict, total=False):
    messages: Annotated[list, add_messages]      # 追加消息
    trace: Annotated[list[dict], operator.add]   # 追加轨迹
    sources: list[dict]                          # 无 reducer：整体覆盖
  • Annotated[..., reducer] 决定"同一字段被多个节点写入时怎么合并"。
  • 没有 reducer 的字段：后写的会覆盖先写的（并行时尤其危险）。
  • 本项目 sources 没有 reducer，靠节点自读旧值，是已知权衡。

3. 条件边与 Command

def route(state: State) -> str:
    return "clarify" if not state.get("month") else "data"

builder.add_conditional_edges("understand", route, {"clarify": "clarify", "data": "data"})

# 另一种写法：节点内直接返回 Command 指定去向
from langgraph.types import Command

def gate(state: State) -> Command:
    if state.get("ok"):
        return Command(goto="compute", update={"status": "running"})
    return Command(goto="fail", update={"status": "failed"})
  • 条件边适合"路由函数集中判断"；Command 适合"节点自己决定下一步 + 顺带更新状态"。
  • 同一个图里两种都用会难以排查，建议二选一为主。

4. 检查点与 thread

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.checkpoint.sqlite import SqliteSaver
import sqlite3

# 测试 / 实验：内存检查点，进程结束即丢
graph_mem = builder.compile(checkpointer=InMemorySaver())

# 演示 / 生产：SQLite 检查点，重启可恢复
conn = sqlite3.connect("data/checkpoints.db", check_same_thread=False)
saver = SqliteSaver(conn)
saver.setup()
graph = builder.compile(checkpointer=saver)

config = {"configurable": {"thread_id": "demo-001"}}
graph.invoke({"question": "..."}, config=config)
snapshot = graph.get_state(config)
print(snapshot.values, snapshot.next)
  • thread 隔离：不同 thread_id 互不可见；同 thread 才有历史。
  • get_state 读当前状态，get_state_history 读历史快照（时间旅行）。
  • 没有 checkpointer 就不能 interrupt、不能恢复。

5. 人工审批：interrupt 与恢复

from langgraph.types import Command, interrupt

def review(state: State) -> dict:
    payload = {"type": "approval", "report_markdown": state["draft"], "options": ["approve", "reject"]}
    decision = interrupt(payload)          # 图在此暂停，返回给调用方
    return {"status": "approved" if decision == "approve" else "rejected"}

# 第一次调用：会停在 interrupt
turn = graph.invoke({"question": "..."}, config=config)

# 提交审批：用 Command(resume=...) 继续
turn = graph.invoke(Command(resume="approve"), config=config)
  • 恢复时节点从头重跑：interrupt() 之前的代码会再执行一次。
  • 所以：副作用（写文件、发消息）必须放在 interrupt 之后，或放到独立节点，并做幂等。
  • interrupt 的载荷必须可 JSON 序列化（会写入检查点）。

6. 运行时上下文与 Store

from typing import TypedDict
from langgraph.runtime import Runtime

class Context(TypedDict):
    conn: object
    settings: object

def node(state: State, runtime: Runtime[Context]) -> dict:
    conn = runtime.context["conn"]        # 注入的依赖，不写进检查点
    return {"answer": "..."}

graph.invoke({"question": "..."}, config=config, context={"conn": conn, "settings": settings})

# Store：跨 thread 的长期记忆（命名空间 + 键）
store.put(("users",), "u1", {"amount_unit": "万元"})
item = store.get(("users",), "u1")
  • Runtime Context：本次调用的依赖（连接、配置、模型），生命周期=一次调用。
  • Store：跨会话记忆（偏好、用户画像），和检查点是两套东西。
  • 本项目 Store 用 SQLite 鸭子类型适配器，属教学简化。

8. 预算、循环与失败出口

def guard(state: State) -> dict:
    budget = dict(state.get("budget") or {"steps": 0, "max_steps": 12})
    budget["steps"] += 1
    if budget["steps"] > budget["max_steps"]:
        return {"status": "budget_exceeded", "budget": budget,
                "errors": ["BUDGET_EXCEEDED: 预算用尽"]}
    return {"budget": budget}

def route_after(state: State) -> str:
    return "fail" if state.get("status") == "budget_exceeded" else "next"
  • 自己数步数并在业务层停下，比等 recursion_limit 抛异常更可控。
  • 统一 fail 出口：所有失败分支收敛到一个节点，便于日志与 UI 处理。

9. 常见坑（按出现频率排序）

现象原因修法
消息被覆盖，只剩最后一条字段没加 add_messages reducer用 Annotated[list, add_messages]
并行分支丢数据字段无 reducer，后写覆盖先写加 reducer 或只让一个分支写
重启后读不到会话用了 InMemorySaver换 SqliteSaver 并 setup()
interrupt 报错"没有 checkpointer"编译时未传 checkpointer 或缺少 thread_id补 checkpointer 与 config
恢复后文件写了两次副作用在 interrupt() 之前移到 interrupt 之后/独立节点 + 幂等
图跑成 GraphRecursionError循环没有终止条件加预算与失败出口
节点返回值把状态清空返回了完整状态而非增量只返回要更新的键
中断载荷序列化失败载荷里有 Path/dataclass/NaN先转成 JSON 友好结构

10. 排查顺序（遇到问题照这个顺序）

  1. graph.get_state(config)：状态停在哪？next 是什么？
  2. stream(..., "updates")：每个节点实际返回了什么增量？
  3. 看 trace/日志：哪个节点 ok=False，错误码是什么？
  4. 单独测节点函数（纯函数直接调用），排除图的问题。
  5. 最后才怀疑框架版本；先把 pip show langgraph 的版本记下来。
