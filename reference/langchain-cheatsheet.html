1 消息（Messages）

类角色常用字段谁产生
SystemMessagesystemcontent你的代码（规则/人设）
HumanMessageusercontent, id用户输入
AIMessageassistantcontent, tool_calls, usage_metadata模型返回
ToolMessagetoolcontent, tool_call_id, name你的工具执行结果
 
from langchain_core.messages import AIMessage, HumanMessage, SystemMessage, ToolMessage

messages = [
    SystemMessage(content="你是财务分析助手，金额一律用「分」的整数。"),
    HumanMessage(content="2026 年九月销售额比八月变化多少？", id="q-1"),
]

# 模型返回带工具调用时，AIMessage.tool_calls 形如：
# [{"name": "query_month_sales", "args": {"month": "2026-09"}, "id": "call_abc", "type": "tool_call"}]
ai = AIMessage(
    content="",
    tool_calls=[{"name": "query_month_sales", "args": {"month": "2026-09"},
                 "id": "call_abc", "type": "tool_call"}],
)

tool_msg = ToolMessage(content='{"ok": true, "data": {"net_cents": 1286500}}',
                       tool_call_id="call_abc", name="query_month_sales")
  • 内容可以是字符串或内容块列表（content blocks）：多模态/多段文本用它，纯文本用 str 最省事。
  • id 是消息身份：add_messages 遇到同 id 会“替换而不是追加”，可用于“编辑上一条”。
  • 一条 AIMessage 可带多个 tool_calls：每个调用对应一条 ToolMessage，tool_call_id 必须一一对应。
  • 工具结果建议序列化成 JSON 字符串放进 content，并在 prompt 里说明字段含义。
  • 不要伪造 ToolMessage：模型没请求过的工具结果会污染上下文。

多轮对话的“记忆”不在模型里：你把历史消息（或 checkpointer 恢复出来的历史）拼进 messages 一起发，模型才“看得到”。上下文裁剪/摘要属于你的工程策略。

2 模型调用（Chat Model）

import os
from langchain_openai import ChatOpenAI

# 任何 OpenAI 兼容端点：改 base_url + model 即可
model = ChatOpenAI(
    model="deepseek-chat",                              # 例：deepseek-chat / gpt-4o-mini
    api_key=os.environ["OPS_API_KEY"],                 # 不要写死在代码里
    base_url="https://api.deepseek.com/v1",            # 官方 OpenAI 可省略
    temperature=0,
    timeout=60,
)

reply = model.invoke("用一句话解释什么是 reducer。")
print(reply.content)
print(reply.usage_metadata)  # 若端点返回用量则存在，否则可能为 None
方法行为何时用
invoke(input)同步返回一条 AIMessage脚本、单轮
stream(input)逐块产出内容块CLI/UI 打字机效果
batch([...])批量并发评测、离线跑批
ainvoke/astream/abatch异步版本FastAPI 等异步服务

端点排查顺序：401 → key 错/没加载 .env；404 → base_url 少了或多了 /v1；model not found → 模型名不是该平台的名字；连接超时 → 代理/网络/服务地址。

3 工具（Tools）

3.1 定义

from typing import Literal
from pydantic import BaseModel, Field
from langchain_core.tools import tool

class MonthArgs(BaseModel):
    month: str = Field(pattern=r"^\d{4}-(0[1-9]|1[0-2])$", description="月份，格式 YYYY-MM")

@tool("query_month_sales", args_schema=MonthArgs)
def query_month_sales(month: str) -> str:
    """查询某个月的净销售额（单位：分）。返回 JSON 字符串。"""
    return '{"ok": true, "data": {"net_cents": 1286500}, "unit": "cents"}'

print(query_month_sales.name)        # query_month_sales
print(query_month_sales.description) # 取 docstring
print(query_month_sales.args)        # 参数 schema
print(query_month_sales.invoke({"month": "2026-09"}))
  • docstring = 给模型看的使用说明，写清“做什么、参数含义、返回什么、失败返回什么”。
  • args_schema 用 Pydantic 约束参数：pattern、Literal、Field(description=...) 都会进 schema，模型更容易填对。
  • 直接调用用 .invoke(dict)；不要用 fn(**kwargs) 绕过校验。
  • 失败不要抛异常给模型：返回 {"ok": false, "error": {"code": ..., "message": ...}, "hint": ...}，模型才能自我修正。
  • 工具要幂等/只读优先：写操作必须显式确认，避免 Agent 循环里重复副作用。

3.2 绑定与执行循环

model_with_tools = model.bind_tools([query_month_sales])
ai = model_with_tools.invoke([HumanMessage(content="九月净销售额是多少？")])

if ai.tool_calls:
    results = []
    for call in ai.tool_calls:                     # [{"name","args","id","type"}]
        tool_fn = {"query_month_sales": query_month_sales}[call["name"]]
        output = tool_fn.invoke(call["args"])      # 单点执行
        results.append(ToolMessage(content=output, tool_call_id=call["id"], name=call["name"]))
    next_ai = model_with_tools.invoke([...history..., ai, *results])
阶段你负责常见坑
定义schema + docstring + 返回值契约只写 def 不写 docstring，模型不知道何时用
请求把工具绑给模型绑了工具但没把 AIMessage 放进历史
执行按 tool_calls 逐个调、逐个回填 ToolMessage漏 tool_call_id；一个调用回两条结果
收敛循环上限 + 失败出口无上限导致死循环/烧 token

工具调用是“模型请求 + 你执行”的两段式：模型不会真的执行函数，它只输出 tool_calls；执行权和校验权始终在你手里（这条同时是安全边界）。

4 结构化输出（Structured Output）

from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, field_validator

class QuestionSpec(BaseModel):
    model_config = ConfigDict(extra="forbid")     # 多余字段直接报错

    current_month: str = Field(pattern=r"^\d{4}-(0[1-9]|1[0-2])$")
    previous_month: str | None = None
    metric: Literal["net_sales", "gross_sales", "order_count"] = "net_sales"
    dimension: Literal["region", "product", "month"] = "region"

    @field_validator("current_month", "previous_month")
    @classmethod
    def check_month(cls, value: str | None) -> str | None:
        if value is not None and not ("2025-01" <= value <= "2026-09"):
            raise ValueError(f"月份超出数据范围：{value}")
        return value

structured = model.with_structured_output(QuestionSpec, method="function_calling")
spec = structured.invoke("2026 年九月和八月对比，按地区看净销售额")
print(type(spec).__name__, spec.model_dump())
做法优点边界
with_structured_output(Schema)一次调用直接得到对象小模型可能不守 schema；method 取值得看版本支持
with_structured_output(Schema, include_raw=True)同时拿到原始消息与解析结果/错误多一层处理
让模型输出 JSON 再自己 json.loads + Pydantic 校验完全可控、可重试需要自己处理解析失败与重试

schema 只是第一道门，不是业务校验：pattern 能挡住“2026-13”，挡不住“2026-01 没有数据”“前月晚于本月”“地区名写错”。业务规则（范围、顺序、枚举、缺失数据 ≠ 0）必须在你自己的纯函数里再校验一遍，并把错误码交给路由决定“澄清 / 修复 / 失败”。未验证：不同 method 取值（function_calling / json_schema 等）在你的版本里支持情况。

5 create_agent（模型 + 工具循环）

from langchain.agents import create_agent

agent = create_agent(
    model=model,                          # ChatOpenAI 或 "provider:model" 字符串（未验证字符串形式）
    tools=[query_month_sales],
    system_prompt="你是财务分析助手。金额用整数分；没有数据就说没有，不要编造。",
)

result = agent.invoke({"messages": [HumanMessage(content="九月净销售额是多少？")]})
for message in result["messages"]:
    print(type(message).__name__, message.content)

# 步数上限（防止工具循环失控）
result = agent.invoke(
    {"messages": [HumanMessage(content="九月净销售额是多少？")]},
    config={"recursion_limit": 24},
)
create_agent 帮你做它不做/你仍要做
维护消息历史与循环业务口径与数值校验
把 tool_calls 执行并回填 ToolMessage工具的权限、幂等、超时、预算
把工具 schema 交给模型报告结构、来源引用、审计留痕
无工具时直接回答澄清、失败出口、人工审批
可接 checkpointer 做多轮“记住用户偏好”等跨会话能力（需 Store）

何时该用固定步骤的 StateGraph 而不是 create_agent：步骤确定、需要可审计的中间状态、需要确定性数值计算、需要人工审批或预算控制时。原因：Agent 的循环由模型决定，你无法保证“先取数再计算再校验”的顺序；财务报告这类“算错就是事故”的场景应把关键步骤写成节点。

6 StateGraph 速记

import operator
from typing import Annotated, TypedDict
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages

class OpsState(TypedDict, total=False):
    question: str
    messages: Annotated[list, add_messages]       # 追加 + 按 id 替换
    trace: Annotated[list[dict], operator.add]    # 追加
    status: str                                   # 默认覆盖

def node_understand(state: OpsState) -> dict:      # 只返回“补丁”
    return {"status": "running", "trace": [{"node": "understand"}]}

def route_after_understand(state: OpsState) -> str:  # 纯函数路由
    return "data" if state.get("question") else "fail"

builder = StateGraph(OpsState)
builder.add_node("understand", node_understand)
builder.add_node("data", lambda s: {"status": "answered"})
builder.add_node("fail", lambda s: {"status": "failed"})
builder.add_edge(START, "understand")
builder.add_conditional_edges("understand", route_after_understand,
                              {"data": "data", "fail": "fail"})
builder.add_edge("data", END)
builder.add_edge("fail", END)
graph = builder.compile()

print(graph.invoke({"question": "九月 vs 八月", "messages": [], "trace": []}))
概念一句话
State共享状态的结构声明（TypedDict 常用），字段即通道
Nodestate -> dict，只返回自己改的字段
Edge固定边“总是去下一个”；条件边由函数决定
Reducer同字段多次写入怎么合并；默认覆盖，Annotated 声明后按你的规则
compile()校验入口/出口/边并生成可执行图，之后才能 invok
stream(updates)每个节点跑完产出一条 {节点名: 补丁}
Command节点在同一次返回里更新状态并指定下一节点（Command(update=..., goto=...)）
recursion_limit框架级循环保险，超出抛异常

7 Checkpointer 与 thread

from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "user-42-demo"}}

graph.invoke({"question": "九月 vs 八月", "messages": [], "trace": []}, config)
graph.invoke({"question": "那华东地区呢？", "messages": [], "trace": []}, config)   # 自动带上文

print(graph.get_state(config).values["status"])          # 当前状态
print(len(list(graph.get_state_history(config))))        # 历史快照数
graph.update_state(config, {"status": "manually_fixed"}) # 人工修正（谨慎）
场景选哪个原因
单元测试、演示InMemorySaver零依赖、进程内、跑完即丢
单机交付、重启继续SqliteSaver写文件、跨进程
多人服务Postgres checkpointer并发与集中管理（未验证：与你版本的兼容性）

恢复语义：interrupt() 恢复时，被中断节点会从函数开头重跑，所以 interrupt() 之前的代码必须幂等；写文件/发请求等副作用放到恢复之后或下一个节点。

8 常见错误对照表

现象高概率原因怎么修
401 Unauthorizedkey 未加载 / 用了别的平台的 key检查 .env 与 load_dotenv()；打印 key 前 4 位确认来源（不要打印全量）
404 Not Foundbase_url 缺/多 /v1按服务商文档填写，如 DeepSeek 用 https://api.deepseek.com/v1
model not found模型名与平台不一致用平台文档里的精确名字；大小写敏感
ModuleNotFoundError: langchain_openai只装了 langchainuv add langchain-openai 后 uv sync
工具没被调用没 bind_tools；docstring 太模糊；参数 schema 不可满足先确认 model.bind_tools([...])，再把 docstring 写清“何时用”
tool_call_id 相关报错ToolMessage 没带 tool_call_id，或与 AIMessage.tool_calls[].id 不匹配逐条对照 id；一个调用只回一条结果
模型重复请求同一个工具工具返回空/无关内容；结果没放回历史；预算太大返回结构化 JSON；检查是否把 AIMessage 与 ToolMessage 都加进历史
结构化输出校验失败模型不守 schema；字段太多太复杂拆小 schema、减少必填、加 Field(description=...)；失败时重试或降级规则解析
GraphRecursionError图有环且无终止条件；recursion_limit 偏低加预算与终止条件；recursion_limit 设为业务步数的约 2 倍
InvalidUpdateError / 节点返回值报错节点返回 None、返回未声明字段、就地改 state 不返回节点必须 return dict；键必须出现在 State 声明里
状态字段被覆盖/丢失没声明 reducer（默认覆盖），或节点返回了整条列表事件流字段用 Annotated[list, operator.add]；节点只返回增量
checkpoint 序列化失败State 里有连接、文件句柄、模型客户端把运行期依赖放 Context，State 只放可序列化数据
多轮对话“失忆”没传 thread_id，或每次换 thread，或没接 checkpointerconfig={"configurable": {"thread_id": ...}} 固定不变
流式输出顺序错乱混用 stream_mode；把 token 流当成状态流明确你要 messages（token）还是 updates（节点补丁）
中文乱码 / 文件写入失败Windows 默认编码不是 UTF-8读写文件显式 encoding="utf-8"

8.1 排查顺序（建议固定下来）

  1. 先证明网络与密钥：一行 model.invoke("hi") 能否成功。
  2. 再证明工具本身：直接 tool.invoke({...}) 看返回是否符合契约。
  3. 再看模型是否请求工具：打印 ai.tool_calls。
  4. 最后看循环与预算：trace、budget、recursion_limit。
