## 3. 通俗解释与精确技术定义

### 3.1 一个必须背下来的四步

```
① 你：把「工具清单」和「用户问题」发给模型
② 模型：返回 AIMessage(content="", tool_calls=[{name, args, id}])   ← 只是“申请”
③ 你：校验 args → 真的执行函数 → 得到结果
        把结果包成 ToolMessage(content=..., tool_call_id=id) 追加进消息
④ 你：把整段消息再发给模型 → 模型基于结果写答案，或继续申请下一个工具
```

**第 ③ 步永远是你的代码。** 模型没有文件系统、没有数据库连接、没有网络权限（除非你把工具交给它，并且你的代码真的执行）。

### 3.2 三个概念别混

| 概念 | 谁产生 | 长什么样 | 出错会怎样 |
| --- | --- | --- | --- |
| 工具定义（tool definition） | 你 | Python 函数 + 名称/描述/参数 schema | 定义错 → 模型根本不会用 |
| 工具调用请求（tool call） | 模型 | `{"name": "query_month_sales", "args": {"month": "2026-09"}, "id": "call_abc"}` | 参数可能非法、可能是幻觉工具名 |
| 工具执行（tool execution） | 程序 | 函数返回值（本项目是 JSON 字符串） | 异常、超时、数据为空 |

> **官方事实**：`AIMessage.tool_calls` 是结构化的调用请求列表；`ToolMessage` 必须带 `tool_call_id` 才能和请求配对。

### 3.3 为什么工具要返回 JSON 字符串，而不是直接返回 dict？

三个理由（**项目设计选择**）：

1. 模型看到的是文本，JSON 字符串是最通用的“结构化文本”。
2. 统一的 `ok/data/error` 结构让模型能区分“查到了”和“查不到”，而不是把异常当成答案。
3. 程序可以在返回前塞 `sources`（SQL 与参数），事后做审计。

代价：每次都要 `json.dumps`，且模型可能不理解嵌套结构 → 所以 docstring 要写清“返回结构的字段含义”。

### 3.4 项目工具清单（工程规格 5.5）

| 工具名 | 参数 | 返回要点 |
| --- | --- | --- |
| `list_available_periods()` | 无 | 可用月份列表与数据范围 |
| `query_month_sales(month)` | `YYYY-MM` | 毛/退/净、订单数、`has_orders` |
| `query_region_breakdown(month)` | `YYYY-MM` | 5 个地区明细 + 合计 |
| `compare_two_months(current_month, previous_month)` | 两个 `YYYY-MM` | 差额、变化率、地区分解、`region_delta_sum_cents` 与校验 |
| `calculate_change(current_cents, previous_cents)` | 两个整数 | 差额与变化率（基期为 0 → `null`） |
| `search_knowledge(query, k=4)` | 查询词 | 命中片段 + 引用 id |

注意：`calculate_change` 把“算数”单独做成工具，是为了让模型**不必心算**——即使它想算，也有一个确定性函数可用。这是**项目设计选择**：把易错的算术从模型手里拿走。

## 5. 文件、完整代码、配置与命令

### 5.1 定义第一个工具（`@tool`）

```python
from langchain_core.tools import tool


@tool
def calculate_change(current_cents: int, previous_cents: int) -> str:
    """计算两期净销售额的差额与变化率，纯算术，不查数据库。

    单位：输入输出都是“分”（整数）。
    规则：previous_cents 为 0 时，变化率返回 null（无定义），不返回无穷大。

    Args:
        current_cents: 本期净销售额，单位分，例如 1286500。
        previous_cents: 上期净销售额，单位分，例如 1190000。

    Returns:
        JSON 字符串，形如
        {"ok": true, "data": {"delta_cents": 96500, "pct_change": 0.0811,
                              "base_zero": false}, "unit": "cents",
         "sources": [{"type": "calc", "formula": "delta = current - previous"}]}
    """
    import json

    if not isinstance(current_cents, int) or not isinstance(previous_cents, int):
        return json.dumps(
            {
                "ok": False,
                "error": {"code": "INVALID_ARGUMENT", "message": "金额必须是整数分"},
                "hint": "请传整数，例如 1286500；不要传带小数的元。",
            },
            ensure_ascii=False,
        )

    delta = current_cents - previous_cents
    if previous_cents == 0:
        pct = None
        base_zero = True
    else:
        pct = round(delta / abs(previous_cents), 4)
        base_zero = False
    return json.dumps(
        {
            "ok": True,
            "data": {"delta_cents": delta, "pct_change": pct, "base_zero": base_zero},
            "unit": "cents",
            "sources": [{"type": "calc", "formula": "delta = current - previous"}],
        },
        ensure_ascii=False,
    )
```

要点：

- 函数名 = 工具名（`calculate_change`），
- docstring = 描述（模型靠它决定“什么时候用这个工具”），
- 类型标注 = 参数 schema（模型靠它决定“参数怎么填”），
- 返回字符串 = 统一 JSON 契约。

> **官方事实**：`@tool` 会从函数签名与 docstring 生成工具 schema；参数描述建议写进 docstring（Args 段）或 `Annotated` 里。
>
> **教学简化**：真实项目会为每个工具写更长的描述和更多示例；本单元只保留最小必要信息，避免 docstring 变成小说。

### 5.3 参数校验：返回 `ok:false`，不要抛异常

```python
@tool
def query_month_sales(month: str) -> str:
    """查询某个月的销售汇总。

    Args:
        month: 月份，格式必须是 YYYY-MM，例如 "2026-09"。

    Returns:
        JSON 字符串；月份非法时 ok 为 false，并在 hint 里给出可用月份。
    """
    import json
    import re

    if not re.fullmatch(r"\d{4}-(0[1-9]|1[0-2])", month or ""):
        return json.dumps(
            {
                "ok": False,
                "error": {"code": "INVALID_MONTH", "message": "月份格式必须是 YYYY-MM"},
                "hint": "可用月份：2025-01 ～ 2026-09",
            },
            ensure_ascii=False,
        )
    # 真实项目在这里调用 queries.get_month_sales(conn, month)，本单元用假数据代替
    fake = {
        "2026-09": {"gross_cents": 1400000, "refund_cents": 113500, "net_cents": 1286500,
                    "order_count": 57, "has_orders": True},
        "2026-08": {"gross_cents": 1310000, "refund_cents": 120000, "net_cents": 1190000,
                    "order_count": 61, "has_orders": True},
    }
    data = fake.get(month)
    if data is None:
        return json.dumps(
            {
                "ok": False,
                "error": {"code": "NO_DATA", "message": f"没有 {month} 的数据"},
                "hint": "可用月份：2025-01 ～ 2026-09；若该月无订单，请向用户说明“无记录”。",
            },
            ensure_ascii=False,
        )
    return json.dumps(
        {
            "ok": True,
            "data": data,
            "unit": "cents",
            "sources": [
                {
                    "type": "sql",
                    "sql": "SELECT SUM(quantity * unit_price_cents) FROM orders WHERE order_date LIKE ?",
                    "params": {"month": f"{month}%"},
                }
            ],
        },
        ensure_ascii=False,
    )
```

为什么“不抛异常”：工具是给模型用的，模型看不懂 Python 堆栈。异常会中断循环；而 `ok:false` 让模型可以**读懂原因并换参数重试**或向用户解释。

> **项目设计选择**：所有可预期错误（非法月份、无数据、未知地区、不支持维度）都走 `ok:false`；只有**程序 bug**（如数据库连接失败）才让异常上抛，交给上层 `repair` / `fail` 节点（单元 08）。

### 5.5 实验：手写工具循环（一步步搭出来）

前四小节你已经见过工具定义、schema 和"假模型"的提议（§5.1～5.4）。本实验把它们组成一个**完整的、带预算的工具循环**——不依赖 `create_agent`，让你看清楚每一圈是怎么转的。分 6 步搭出，最终与仓库 `教程/实验/04_tool_loop.py` 完全一致；前 4 步全程无密钥。

#### 步骤 1：两个工具与统一错误载荷

**这一步解决什么**：循环要转起来，先得有"被调用的东西"。工具概念 §5.1～5.3 讲过了，这里快速录入**两个**工具，并补上实验专用的假数据源。

新建 `教程/实验/04_tool_loop.py`：

```python
"""单元 04 实验（步骤 1）：工具与错误载荷。"""

from __future__ import annotations

import json
import re

from langchain_core.tools import tool

FAKE_MONTHS = {
    "2026-09": {"gross_cents": 1400000, "refund_cents": 113500, "net_cents": 1286500,
                "order_count": 57, "has_orders": True},
    "2026-08": {"gross_cents": 1310000, "refund_cents": 120000, "net_cents": 1190000,
                "order_count": 61, "has_orders": True},
    "2025-01": {"gross_cents": 0, "refund_cents": 0, "net_cents": 0,
                "order_count": 0, "has_orders": False},
}


def error_payload(code: str, message: str, hint: str) -> str:
    return json.dumps(
        {"ok": False, "error": {"code": code, "message": message}, "hint": hint},
        ensure_ascii=False,
    )


@tool
def query_month_sales(month: str) -> str:
    """查询某个月的销售汇总。

    Args:
        month: 月份，格式必须是 YYYY-MM，例如 "2026-09"。

    Returns:
        JSON 字符串；ok=false 时说明原因，不抛异常。
    """
    if not re.fullmatch(r"\d{4}-(0[1-9]|1[0-2])", month or ""):
        return error_payload("INVALID_MONTH", "月份格式必须是 YYYY-MM", "可用月份：2025-01 ～ 2026-09")
    data = FAKE_MONTHS.get(month)
    if data is None:
        return error_payload("NO_DATA", f"没有 {month} 的数据", "先调用 list_available_periods")
    return json.dumps(
        {
            "ok": True,
            "data": data,
            "unit": "cents",
            "sources": [
                {
                    "type": "sql",
                    "sql": "SELECT SUM(quantity * unit_price_cents) FROM orders WHERE order_date LIKE ?",
                    "params": {"month": f"{month}%"},
                }
            ],
        },
        ensure_ascii=False,
    )


@tool
def calculate_change(current_cents: int, previous_cents: int) -> str:
    """计算两期净销售额的差额与变化率。

    Args:
        current_cents: 本期净销售额，单位分。
        previous_cents: 上期净销售额，单位分。

    Returns:
        JSON 字符串；previous_cents 为 0 时 pct_change 为 null。
    """
    delta = current_cents - previous_cents
    if previous_cents == 0:
        pct = None
        base_zero = True
    else:
        pct = round(delta / abs(previous_cents), 4)
        base_zero = False
    return json.dumps(
        {
            "ok": True,
            "data": {"delta_cents": delta, "pct_change": pct, "base_zero": base_zero},
            "unit": "cents",
            "sources": [{"type": "calc", "formula": "delta = current - previous"}],
        },
        ensure_ascii=False,
    )


TOOLS = [query_month_sales, calculate_change]
TOOL_MAP = {item.name: item for item in TOOLS}
```

**逐行讲解**：

- `FAKE_MONTHS` 是三行的"假数据库"：两个正常月 + 一个**零基期**（2025-01 无订单）——专供无密钥环境演示，也埋了 `base_zero` 的伏笔。
- `error_payload(code, message, hint)` 是统一错误结构：**code 给程序分支用，message 给人看，hint 给下一步建议**。工具失败永远返回 JSON 字符串，不抛异常（§5.3 的纪律）。
- `query_month_sales` 的成功载荷带 `sources`（假的 SQL 与参数）——**从第一天起就让"数字有出处"成为肌肉记忆**。
- `TOOL_MAP`：按名字索引工具函数，步骤 2 的执行器靠它把"名字"变成"可调用对象"。

**运行与观察**（临时加在文件底部，之后会删）：

#### 步骤 2：执行器 `execute_tool_calls`——唯一能碰数据的地方

**这一步解决什么**：模型的"申请"（`tool_calls` 列表）到"数据"之间必须有一个**唯一的、可审计的执行点**：校验工具名、执行、把结果包成 `ToolMessage` 送回模型，并留一份 trace 给人看。

```python
from langchain_core.messages import ToolMessage


def execute_tool_calls(tool_calls: list[dict]) -> tuple[list[ToolMessage], list[dict]]:
    """真正执行工具的地方：校验 → 执行 → 包成 ToolMessage。"""
    messages: list[ToolMessage] = []
    trace: list[dict] = []
    for call in tool_calls:
        name = call.get("name", "")
        args = call.get("args", {})
        call_id = call.get("id", "")
        entry = {"tool": name, "args": args, "ok": False, "summary": ""}
        if name not in TOOL_MAP:
            content = error_payload(
                "UNKNOWN_TOOL",
                f"没有名为 {name} 的工具",
                f"可用工具：{sorted(TOOL_MAP)}",
            )
            entry["summary"] = "unknown_tool"
        else:
            try:
                content = TOOL_MAP[name].invoke(args)
                payload = json.loads(content)
                entry["ok"] = bool(payload.get("ok"))
                entry["summary"] = "ok" if entry["ok"] else payload.get("error", {}).get("code", "error")
            except Exception as exc:  # 程序 bug 才走到这里；记录而不是静默
                content = error_payload("TOOL_EXCEPTION", f"{type(exc).__name__}: {exc}", "请检查工具实现")
                entry["summary"] = "exception"
        messages.append(ToolMessage(content=content, tool_call_id=call_id))
        trace.append(entry)
    return messages, trace
```

**逐行讲解**：

- 三道防线依次是：**名字不认识**（UNKNOWN_TOOL，hint 列出全部可用工具）、**工具内部失败**（ok:false 原样转交——工具自己的事工具自己说）、**工具抛异常**（TOOL_EXCEPTION——只可能是程序 bug，记录类型与消息，绝不静默）。
- `ToolMessage(content=..., tool_call_id=call_id)`：`tool_call_id` 把结果**精确对回**某次申请——模型同时申请两个工具时靠它配对，配错就全乱了。
- `trace` 与 `messages` 分离：一份喂模型（对话继续），一份喂人（审计与打印）。**给机器的和给人的数据走两条线**。

#### 步骤 3：假模型 `fake_model_decide`——按剧本"提议"

**这一步解决什么**：没有密钥也要看到完整循环。做法：写一个**确定性**的"假模型"，按固定剧本返回 `tool_calls`（或最终结论）——它证明了一件重要的事：**循环由程序驱动，模型只是提议下一步**。

```python
from langchain_core.messages import AIMessage


def fake_model_decide(messages: list, step: int, max_tool_calls: int) -> AIMessage:
    """确定性“假模型”：按固定剧本返回工具申请，最后给结论。

    它的存在是为了证明：循环由程序驱动，模型只是“提议下一步”。
    """
    if step >= max_tool_calls:
        return AIMessage(content="工具调用达到上限，停止。请人工检查。")
    if step == 0:
        return AIMessage(
            content="",
            tool_calls=[
                {"name": "query_month_sales", "args": {"month": "2026-09"},
                 "id": f"call_{step}_a", "type": "tool_call"},
                {"name": "query_month_sales", "args": {"month": "2026-08"},
                 "id": f"call_{step}_b", "type": "tool_call"},
            ],
        )
    if step == 1:
        return AIMessage(
            content="",
            tool_calls=[
                {"name": "calculate_change", "args": {"current_cents": 1286500, "previous_cents": 1190000},
                 "id": f"call_{step}_a", "type": "tool_call"},
                {"name": "query_month_sales", "args": {"month": "2026-13"},
                 "id": f"call_{step}_b", "type": "tool_call"},
            ],
        )
    return AIMessage(
        content=(
            "2026 年九月净销售额 1286500 分，八月 1190000 分，差额 96500 分，"
            "变化率 8.11%。注意：该结论来自程序计算的工具结果，不是模型心算。"
        )
    )
```

**逐行讲解**：

- 剧本三拍：**查两个月 → 算差额（顺带申请一个坏月份 2026-13）→ 给结论**。坏月份是故意的——你会看到 `NO_DATA` 载荷怎么进循环、又怎么被"无视 ok:false 不编数据"的纪律处理。
- 返回的是**真 `AIMessage`**：`tool_calls` 字段的形状与真实模型完全一致，所以步骤 5 换成真模型时**循环代码一行不改**。
- `step >= max_tool_calls` 的提前停机在剧本层面兜底——真正的预算检查在循环里（下一步），两层各管各的。

#### 步骤 4：循环主体 `run_loop`——程序在开车

**这一步解决什么**：把"提议 → 执行 → 回传"转起来的那个圈，加上预算上限。这是本单元的核心：**循环、终止条件、预算都由程序决定，模型没有决定权**。

```python
from langchain_core.messages import HumanMessage, SystemMessage

MAX_TOOL_CALLS = 4


def run_loop(question: str, *, max_tool_calls: int = MAX_TOOL_CALLS) -> dict:
    messages: list = [
        SystemMessage(content="你可以调用工具。只使用工具返回的数字，不要自行加减。"),
        HumanMessage(content=question),
    ]
    tool_call_count = 0
    steps: list[dict] = []
    for step in range(max_tool_calls + 2):
        reply = fake_model_decide(messages, step, max_tool_calls)
        messages.append(reply)
        if not reply.tool_calls:
            return {"answer": reply.content, "steps": steps, "tool_calls": tool_call_count}
        tool_call_count += len(reply.tool_calls)
        tool_messages, trace = execute_tool_calls(reply.tool_calls)
        messages.extend(tool_messages)
        steps.append({"step": step, "tool_calls": len(reply.tool_calls), "results": trace})
        if tool_call_count > max_tool_calls:
            messages.append(AIMessage(content="预算耗尽：工具调用超过上限，转入失败出口。"))
            return {
                "answer": "预算耗尽（tool_calls > max_tool_calls）",
                "steps": steps,
                "tool_calls": tool_call_count,
                "status": "budget_exceeded",
            }
    return {"answer": "达到最大步数仍未得出结论", "steps": steps, "tool_calls": tool_call_count}
```

**逐行讲解**：

- 循环里只有两种结局：**模型不再申请工具**（`not reply.tool_calls` → 返回答案）或**预算爆了**（`tool_call_count > max_tool_calls` → `budget_exceeded`）。没有第三种"模型自己想停就停"。
- `tool_call_count` 按**次数**累计而不是按轮次：一轮申请 3 个就加 3——预算的真实含义是"花钱的次数"。
- `for ... in range(max_tool_calls + 2)` 的 +2 是**步数兜底**：即使预算没爆，步数也有硬上限（防"每轮都只申请 1 个"的拖延）。两道闸门，先到的生效。
- `messages.extend(tool_messages)`：执行结果**追加**进历史，下一轮模型（这里是剧本）能看到——这就是"回传"。

**运行与观察**（临时验证：敲 `run_loop("2026 年九月净销售额比八月变化多少？")` 并打印 steps）：

```text

    query_month_sales({'month': '2026-08'}) → ok=True summary=ok
step 1：发起 2 个调用
    calculate_change({'current_cents': 1286500, 'previous_cents': 1190000}) → ok=True summary=ok
    query_month_sales({'month': '2026-13'}) → ok=False summary=INVALID_MONTH

注意 `2026-13` 那一行：`ok=False summary=INVALID_MONTH`——坏申请被执行器**接住并报告**，循环照常前进，最终结论里也没有编造的数字。

    else:
        real = run_real_loop(model, question)
        print(f"最终回答：{real['answer']}")
        for entry in real["trace"]:
            print(f"    {entry['tool']}({entry['args']}) → ok={entry['ok']} summary={entry['summary']}")

**逐行讲解**：

- 第二段 `max_tool_calls=2`：剧本第一轮就申请 2 个、第二轮又 2 个 → 累计 4 > 2，立刻走 `budget_exceeded`——**预算不是装饰，是真能停下来的**。
- `run_real_loop` 与 `run_loop` 的唯一区别：`fake_model_decide(...)` 换成 `bound.invoke(messages)`。**循环骨架、执行器、终止条件全部复用**——这就是"模型可替换"的直接证据。
- 真实模型的 SystemMessage 更严（"禁止心算""ok=false 时不要编造"）：真模型会犯的错比剧本多，提示词要跟上。

                "order_count": 57, "has_orders": True},
    "2026-08": {"gross_cents": 1310000, "refund_cents": 120000, "net_cents": 1190000,

def error_payload(code: str, message: str, hint: str) -> str:
    return json.dumps(
        {"ok": False, "error": {"code": code, "message": message}, "hint": hint},
        ensure_ascii=False,
    )


@tool
def query_month_sales(month: str) -> str:
    """查询某个月的销售汇总。

    Args:
        month: 月份，格式必须是 YYYY-MM，例如 "2026-09"。

    Returns:
        JSON 字符串；ok=false 时说明原因，不抛异常。
    """
    if not re.fullmatch(r"\d{4}-(0[1-9]|1[0-2])", month or ""):
        return error_payload("INVALID_MONTH", "月份格式必须是 YYYY-MM", "可用月份：2025-01 ～ 2026-09")
    data = FAKE_MONTHS.get(month)
    if data is None:
        return error_payload("NO_DATA", f"没有 {month} 的数据", "先调用 list_available_periods")
    return json.dumps(
        {
            "ok": True,
            "data": data,
            "unit": "cents",
            "sources": [
                {
                    "type": "sql",
                    "sql": "SELECT SUM(quantity * unit_price_cents) FROM orders WHERE order_date LIKE ?",
                    "params": {"month": f"{month}%"},
                }
            ],
        },
        ensure_ascii=False,
    )


@tool
def calculate_change(current_cents: int, previous_cents: int) -> str:
    """计算两期净销售额的差额与变化率。

    Args:
        current_cents: 本期净销售额，单位分。
        previous_cents: 上期净销售额，单位分。

    Returns:
        JSON 字符串；previous_cents 为 0 时 pct_change 为 null。
    """
    delta = current_cents - previous_cents
    if previous_cents == 0:
        pct = None
        base_zero = True
    else:
        pct = round(delta / abs(previous_cents), 4)
        base_zero = False
    return json.dumps(
        {
            "ok": True,
            "data": {"delta_cents": delta, "pct_change": pct, "base_zero": base_zero},
            "unit": "cents",
            "sources": [{"type": "calc", "formula": "delta = current - previous"}],
        },
        ensure_ascii=False,
    )


TOOLS = [query_month_sales, calculate_change]
TOOL_MAP = {item.name: item for item in TOOLS}


def execute_tool_calls(tool_calls: list[dict]) -> tuple[list[ToolMessage], list[dict]]:
    """真正执行工具的地方：校验 → 执行 → 包成 ToolMessage。"""
    messages: list[ToolMessage] = []
    trace: list[dict] = []
    for call in tool_calls:
        name = call.get("name", "")
        args = call.get("args", {})
        call_id = call.get("id", "")
        entry = {"tool": name, "args": args, "ok": False, "summary": ""}
        if name not in TOOL_MAP:
            content = error_payload(
                "UNKNOWN_TOOL",
                f"没有名为 {name} 的工具",
                f"可用工具：{sorted(TOOL_MAP)}",
            )
            entry["summary"] = "unknown_tool"
        else:
            try:
                content = TOOL_MAP[name].invoke(args)
                payload = json.loads(content)
                entry["ok"] = bool(payload.get("ok"))
                entry["summary"] = "ok" if entry["ok"] else payload.get("error", {}).get("code", "error")
            except Exception as exc:  # 程序 bug 才走到这里；记录而不是静默
                content = error_payload("TOOL_EXCEPTION", f"{type(exc).__name__}: {exc}", "请检查工具实现")
                entry["summary"] = "exception"
        messages.append(ToolMessage(content=content, tool_call_id=call_id))
        trace.append(entry)
    return messages, trace

    print(f"累计工具调用：{result['tool_calls']}；状态：{result.get('status', 'ok')}")

    print("\n--- 第二段：预算上限压到 2 次 ---")
    tight = run_loop(question, max_tool_calls=2)
    print(f"最终回答：{tight['answer']}；累计调用：{tight['tool_calls']}；状态：{tight.get('status', 'ok')}")

    print("\n--- 第三段：真实模型（可选）---")
    model = load_real_model()
    if model is None:
        print("[跳过] 未配置 OPS_MODEL / OPS_API_KEY；假模型已经演示了完整循环。")
    else:
        real = run_real_loop(model, question)
        print(f"最终回答：{real['answer']}")
        for entry in real["trace"]:
            print(f"    {entry['tool']}({entry['args']}) → ok={entry['ok']} summary={entry['summary']}")

    print("\n[结论] 工具执行发生在 execute_tool_calls()；模型只提供 name/args。")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### 5.6 逐段解释这段代码

| 函数 | 作用 | 关键设计 |
| --- | --- | --- |
| `query_month_sales` | 查月度汇总 | 非法月份/无数据都返回 `ok:false` + `hint` |
| `calculate_change` | 纯算术 | 基期为 0 → `pct_change: null`，绝不返回 ∞ |
| `execute_tool_calls` | **唯一执行点** | 未知工具名 → `ok:false`；异常 → 记录 `TOOL_EXCEPTION` |
| `fake_model_decide` | 假模型剧本 | 证明循环由程序驱动 |
| `run_loop` | 循环 + 预算 | 每轮检查 `tool_call_count > max_tool_calls` → `budget_exceeded` |
| `run_real_loop` | 真实模型版本 | `bind_tools` + 同一套 `execute_tool_calls` |

**注意 `execute_tool_calls` 是唯一能碰到真实数据的函数**。在项目里，这个位置就是 `agent/tools.py` + 图节点 `data`；报告里的 `sources` 全部来自这里。想审计“到底执行了什么”，只需要看这个函数的入参与返回值。

### 5.7 与项目接口的对应

| 实验 | 项目契约（工程规格 5.5） |
| --- | --- |
| `query_month_sales(month)` | 同名工具，内部调用 `queries.get_month_sales` |
| `calculate_change(current, previous)` | 同名工具，返回 `delta_cents` / `pct_change` |
| `{"ok": true, "data", "unit": "cents", "sources"}` | 统一返回结构 |
| `{"ok": false, "error": {"code", "message"}, "hint"}` | 统一错误结构 |
| `execute_tool_calls` | 项目里分散在工具函数内部 + 图节点 `data` |
| `max_tool_calls` | `Settings.max_tool_calls`，默认 8 |

**差异说明**（**项目设计选择**）：项目里没有“手写循环”这一层，因为 `create_agent`（单元 05）已经提供；项目把预算检查放在图节点的 `budget` 字段里，而不是循环内部。但**执行语义完全一样**：模型请求 → 程序执行 → `ToolMessage` 回传。

### 5.8 一个真实项目里必须防的坑

模型可能：

1. **编工具名**：`query_sales_by_channel`（不存在）→ 必须返回 `ok:false` + 可用工具列表。
2. **参数类型错**：`{"month": 202609}`（整数）→ 工具里 `re.fullmatch` 会因非字符串失败，必须给出可读错误。
3. **重复调用同一个工具**：同参数连续 3 次 → 用 `max_tool_calls` 兜住，还可以做“同参数去重”。
4. **无视 `ok:false` 继续编**：在 `SystemMessage` 里明确“工具失败时不要编数据”，并在报告生成时校验“每个数字都有 `sources`”。

## 10. 复盘问题与参考答案、下一步

### Q1：模型是怎么“知道”有哪些工具的？

**参考**：你把工具列表通过 `bind_tools`（或 `create_agent` 内部）序列化成给模型的工具声明（名称、描述、参数 JSON Schema）。模型看到的是这份声明，不是 Python 源码。所以：**描述写不清，模型就用不对**；参数 schema 不严，模型就乱填。

### Q2：为什么工具失败要返回 `ok:false` 而不是抛异常？

**参考**：因为工具的使用者（模型）只能读文本。`ok:false` + `code` + `hint` 给了它纠正的机会（换月份、先查可用范围）；异常只会让循环中断，用户看到“系统错误”。但**程序 bug** 必须上抛，否则会被当成“业务失败”掩盖掉。

### Q3：手写循环都做完了，`create_agent` 还有意义吗？

**参考**：有。手写一遍的价值是“知道黑盒里面是什么”；`create_agent` 的价值是把循环、工具绑定、消息管理、checkpoint 接线标准化，减少重复代码与 bug。**项目设计选择**：单元 05 用 `create_agent` 做“第一版问答助手”，但复杂流程（审批、预算、失败出口、报告）仍用自己画的图（单元 06 起）。两者是“快速原型”和“可控产线”的关系。

### Q4：怎样证明工具真的执行了？

**参考**：三层证据——(1) `ToolMessage` 的内容与 `tool_call_id`；(2) 工具返回里的 `sources`（SQL + 参数）；(3) 日志/指标（`record_tool` 的调用次数与耗时）。本项目的报告第 8 节会把这些列出来，评审时可以逐条核对。

### Q5：工具能不能返回结构化对象而不是 JSON 字符串？

**参考**：技术上可以（LangChain 支持 `response_format="content_and_artifact"` 等）。但本项目统一用 JSON 字符串，因为：跨供应商最兼容、可直接落日志、测试可用 `json.loads` 断言。代价是模型需要读懂字段含义，所以 docstring 必须写清返回结构。
