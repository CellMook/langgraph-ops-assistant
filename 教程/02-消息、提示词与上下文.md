## 3. 通俗解释与精确技术定义

### 3.1 四种角色，一句话记住

| 角色 | 类 | 谁写的 | 作用 | 本项目例子 |
| --- | --- | --- | --- | --- |
| 系统 | `SystemMessage` | **程序** | 设定身份、规则、输出格式 | “金额单位是分；不确定要说不知道” |
| 用户 | `HumanMessage` | 用户/程序 | 这一轮的问题 | “2026 年九月销售额比八月变化多少？” |
| 助手 | `AIMessage` | **模型** | 模型的回复，可能带 `tool_calls` | 一句结论，或一个工具申请 |
| 工具 | `ToolMessage` | **程序** | 工具执行的返回值 | `{"ok": true, "data": {...}}` |

> **教学简化**：真实协议里还有更多角色/字段（如 `AIMessageChunk`、`response_metadata`、`usage_metadata`）。初学只记四种足够，但要知道“消息是一个对象，不只一段文本”。

### 3.2 上下文不是记忆

这是初学者最容易混淆的一点：

- **上下文（context）**：这一次 HTTP 请求里，你**重新发送**的全部消息。它不属于模型，模型不保存任何东西。
- **记忆（memory）**：跨请求保留下来的东西。它必须由你的程序存储（状态、数据库、checkpoint）。

因此应分别检查：历史是否发送、是否截断、相关资料是否召回、是否存在冲突信息，以及模型是否正确利用了已经提供的上下文。上下文存在并不保证模型一定使用正确。

### 3.3 上下文变长的三个后果

1. **更贵**：每次都要为全部历史 token 付费（prompt tokens）。
2. **更慢**：输入越长，首 token 延迟通常越高。
3. **更容易跑偏**：历史里的错误答案会被模型当成事实继续用。

这叫“上下文工程（context engineering）”：不是把所有东西都塞进去，而是决定**放什么、放多少、什么时候清**。

### 3.4 提示词（prompt）的结构

一条可维护的提示词通常分四块：

```
[角色]     你是一名经营数据分析助手。
[能力边界] 只允许使用给定数字；不支持的维度要明确说“不支持”。
[输出约束] 先给结论，再给数字，最后给口径；不要 Markdown 表格以外的格式。
[输入数据] 用户问题 + 已知数字 + 检索到的资料（带引用 id）
```

**项目设计选择**：本项目把“规则”写死在 `SystemMessage` 里，把“数据”放 `HumanMessage` 里，把“检索资料”拼成单独的文本块并带 `[doc_id#chunk_id]` 引用，便于程序事后校验引用是否真实存在。

### 5.3 实验：上下文窗口的“三宗罪”（一步步搭出来）

本实验观察三件事：**历史越长 token 越多（成本）**、**延迟越高**、**截断会丢信息（稳定性）**。分 6 步搭出来，前 4 步无密钥可跑（历史、估算、截断都是纯 Python），最终与仓库 `教程/实验/02_context_growth.py` 完全一致。

#### 步骤 1：用 dict 构造一段多轮历史

**这一步解决什么**：要观察“上下文增长”，先得有可控长度的历史。用普通 `dict` 而不是 langchain 消息对象来表示——这样**没密钥、没装好依赖也能做完前 4 步**，消息对象到步骤 5 才登场。

新建 `教程/实验/02_context_growth.py`（配置常量照抄实验 A 的 `REPO_ROOT`/`ENV_PATH`，加上 `mask`——本实验要用到）：

```python
MAX_HISTORY_MESSAGES = 6


def build_history(turns: int) -> list[dict[str, str]]:
    """构造多轮历史；用 dict 表示，便于无密钥时也不依赖 langchain。"""
    system = {
        "role": "system",
        "content": (
            "你是经营数据分析助手。规则：金额单位是分；只复述给定数字；"
            "不确定时说“不确定”；不要编造地区数据。"
        ),
    }
    history: list[dict[str, str]] = [system]
    for index in range(turns):
        history.append(
            {
                "role": "user",
                "content": f"第 {index + 1} 轮：2026 年九月净销售额 {1286500 + index * 1000} 分，八月 1190000 分。",
            }
        )
        history.append(
            {
                "role": "assistant",
                "content": f"第 {index + 1} 轮记录：九月 {1286500 + index * 1000} 分，八月 1190000 分。",
            }
        )
    history.append({"role": "user", "content": "那华东地区呢？"})
    return history
```

临时验证（敲在文件底部，`if __name__` 里）：

```python
if __name__ == "__main__":
    import json

    print(json.dumps(build_history(1), ensure_ascii=False, indent=2))
```

**逐行讲解**：

- 历史的形状是 `[system, (user, assistant) × turns, user]`——**system 打头、一问一答成对、最后是新问题**，这就是“多轮对话”的全部结构。
- 每轮数字加 `index * 1000`：让每条消息内容都不同，token 统计才不会骗人。
- 结尾故意问“那华东地区呢？”——**它自己不带时间与指标**，能不能答对全看前面的历史，这是步骤 4 的伏笔。

**运行与观察**：

```text
[
  {"role": "system", "content": "你是经营数据分析助手。规则：金额单位是分；…"},
  {"role": "user", "content": "第 1 轮：2026 年九月净销售额 1286500 分，八月 1190000 分。"},
  {"role": "assistant", "content": "第 1 轮记录：九月 1286500 分，八月 1190000 分。"},
  {"role": "user", "content": "那华东地区呢？"}
]
```

`build_history(1)` 是 4 条消息，`build_history(5)` 是 12 条——长度由参数控制，这就是“可控”。

#### 步骤 2：估算 token——给历史算账单

**这一步解决什么**：上下文的代价要**量化**才看得见。先写一个极简估算器，把“感觉变长了”变成数字。

```python
def estimate_tokens(text: str) -> int:
    """极简 token 估算：中文按 1 字 1 token，英文按 4 字符 1 token。

    教学简化：真实分词器（tokenizer）不同，本函数只用于展示“趋势”。
    """
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    others = len(text) - cjk
    return cjk + max(1, others // 4)


def total_tokens(history: list[dict[str, str]]) -> int:
    return sum(estimate_tokens(item["content"]) for item in history)
```

临时验证：

```python
    for turns in (1, 5, 20):
        history = build_history(turns)
        print(f"轮数={turns:>2} 消息数={len(history):>3} 估算token={total_tokens(history):>5}")
```

**逐行讲解**：

- ` "\u4e00" <= ch <= "\u9fff"` 是 CJK 统一表意文字的码位区间——中文一字一 token、英文约四字符一 token，是**够用的近似**。
- docstring 里明确标注**教学简化**：真实 tokenizer 因模型而异（有的中文 1 字 ≈ 0.6 token，有的 ≈ 1.5）。要看真数字，用步骤 5 的 `usage_metadata`。
- `max(1, others // 4)`：纯英文短串（如 `v1`）也至少算 1 个，避免“0 token”这种误导。

**运行与观察**：

```text
轮数= 1 消息数=  4 估算token=  133
轮数= 5 消息数= 12 估算token=  493
轮数=20 消息数= 41 估算token= 1946
```

**token 随轮数线性上涨**——这就是三宗罪的第一宗（成本），第三宗（窗口上限）也在同一张表里等着。

#### 步骤 3：截断策略——保留 system + 最近 N 条

**这一步解决什么**：历史不能无限涨，必须有截断规则。规则要**显式**：system 永远保留（否则规则丢失），其余“越旧越先丢”。

```python
def truncate_history(history: list[dict[str, str]], max_messages: int) -> list[dict[str, str]]:
    """保留 system + 最近 max_messages 条非 system 消息。

    规则显式：system 永远保留（否则规则丢失）；其余按“越旧越先丢”。
    """
    system_messages = [item for item in history if item["role"] == "system"]
    others = [item for item in history if item["role"] != "system"]
    kept = others[-max_messages:]
    return system_messages + kept
```

临时验证（加到上一条的循环里）：

```python
        truncated = truncate_history(history, MAX_HISTORY_MESSAGES)
        print(f"轮数={turns:>2} 消息数={len(history):>3} 估算token={total_tokens(history):>5} "
              f"截断后消息数={len(truncated):>2} 截断后token={total_tokens(truncated):>5}")
```

**逐行讲解**：

- 先把 system **摘出来**再截断其余——如果对整条列表直接切片，第 0 条 system 可能在长历史里被切掉。
- `others[-max_messages:]`：Python 切片“取尾部 N 条”，天生就是“保留最近的”。
- 截断顺序 = 丢弃顺序 = **信息价值排序**：最旧的问答最不值钱，最新的最值钱。

**运行与观察**：

```text
轮数=20 消息数= 41 估算token= 1946 截断后消息数= 7 截断后token=  327
```

41 条截到 7 条（system + 最近 6 条），token 从 1946 降到 327——**代价是第 1～17 轮的信息全没了**。如果新问题依赖被丢掉的信息，模型只能瞎猜或要求澄清。

#### 步骤 4：两种问法对照——上下文不会自己保留

**这一步解决什么**：把“上下文的作用”变成肉眼可见的对照。同一句“那华东地区呢？”，带不带历史，模型拿到的信息完全不同。

把临时验证换成正式的对照打印（这一段会保留到最终脚本）：

```python
def main() -> int:
    print("== 单元 02 实验：上下文增长与截断 ==")
    config = load_config()

    for turns in (1, 5, 20):
        history = build_history(turns)
        tokens = total_tokens(history)
        truncated = truncate_history(history, MAX_HISTORY_MESSAGES)
        print(
            f"轮数={turns:>2} 消息数={len(history):>3} 估算输入token={tokens:>5} "
            f"截断后消息数={len(truncated):>2} 截断后token={total_tokens(truncated):>5}"
        )

    print("\n== 同一问题的两种问法 ==")
    print("A 带上下文：", build_history(1)[-2:])
    print("B 不带上下文：", [{"role": "user", "content": "那华东地区呢？"}])
    print("→ A 能让模型知道“哪个月、什么指标”；B 不能。上下文不会自己保留。")
    return 0
```

（`load_config()` 照抄实验 B 的同名函数；步骤 5 会用到它的返回值。）

**逐行讲解**：

- `build_history(1)[-2:]`：只展示最后两条（上一轮问答），打印不会被 system 长文本淹没。
- “上下文不会自己保留”是本单元最重要的一句话：**API 是无状态的**，你不带历史，模型就只见一句孤立的问题。

**运行与观察**：

```text

A 带上下文： [{'role': 'assistant', 'content': '第 1 轮记录：九月 1286500 分，八月 1190000 分。'}, {'role': 'user', 'content': '那华东地区呢？'}]
```

#### 步骤 5：接真模型，亲眼看三种提问的差异

**这一步解决什么**：估算器说“token 在涨”，真实调用能让你看到**用量与回答质量**一起变。同时完成 dict → langchain 消息对象的转换（§5.1 讲的四种角色在这里各就各位）。

在 `main()` 的 `return 0` 前加：

```python

    if not enabled:
        print("\n[规则模式] 未配置模型，跳过真实调用。下面用本地确定性函数模拟回复：")

        print("\n[结论] 即使没密钥，你也能观察：历史越长 token 越多、截断会丢信息。")
        return 0

    from langchain_core.messages import AIMessage, HumanMessage, SystemMessage
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model=config["model_name"],
        api_key=config["api_key"],
        base_url=config["base_url"],
        temperature=0.0,
        timeout=60.0,
        max_retries=0,
    )

    def ask(messages: list[dict[str, str]]) -> str:
        converted = []
        for item in messages:
            if item["role"] == "system":
                converted.append(SystemMessage(content=item["content"]))
            elif item["role"] == "assistant":
                converted.append(AIMessage(content=item["content"]))
            else:
                converted.append(HumanMessage(content=item["content"]))
        reply = model.invoke(converted)
        usage = getattr(reply, "usage_metadata", None)
        return f"{reply.content}\n    [usage] {usage}"

    print("\n--- 带上下文提问 ---")
    print(ask(build_history(2)))

    print("\n--- 只发最后一句 ---")
    print(ask([{"role": "user", "content": "那华东地区呢？"}]))

```

**逐行讲解**：

- dict → 对象的转换循环就是一张**角色对照表**：`system→SystemMessage`、`assistant→AIMessage`、其余→`HumanMessage`。为什么要转换？因为 langchain 的 API 只认它自己的消息类型。
- `[usage]` 行是**真实账单**：对照步骤 2 的估算，看估算器差多少（差多少都正常，它只保趋势）。
- 三次提问的设计：带 2 轮上下文（应能答“华东”指代什么）、只发一句（应要求澄清）、截断 20 轮（看丢了什么）——**同一问题，三种命运**。

**运行与观察**：无密钥 → 假模型两行；有密钥 → 三段真实回复 + usage，对照第 6 节 §6.1 的预期输出。

```python
"""单元 02 实验：观察上下文增长对成本、延迟与稳定性的影响。

用法（在 ops-assistant 目录执行）：uv run python ../教程/实验/02_context_growth.py
无密钥时使用“本地假模型”，仍然能观察 token 估算与截断策略。
"""

from __future__ import annotations

import os
import sys
from pathlib import Path

from dotenv import load_dotenv

REPO_ROOT = Path(__file__).resolve().parents[2]
ENV_PATH = REPO_ROOT / "ops-assistant" / ".env"
MAX_HISTORY_MESSAGES = 6


def mask(secret: str | None) -> str:
    if not secret:
        return "未设置"
    return f"{secret[:4]}…{secret[-2:]}"


def load_config() -> dict[str, str | None]:
    if ENV_PATH.is_file():
        load_dotenv(dotenv_path=ENV_PATH, override=False)
    raw_model = (os.getenv("OPS_MODEL") or "").strip()
    provider_hint = (os.getenv("OPS_MODEL_PROVIDER") or "").strip()
    api_key = (os.getenv("OPS_API_KEY") or "").strip() or os.getenv("OPENAI_API_KEY")
    base_url = (os.getenv("OPS_BASE_URL") or "").strip() or None
    provider, model_name = ("openai", raw_model)
    if ":" in raw_model:
        provider, _, model_name = raw_model.partition(":")
    elif provider_hint:
        provider = provider_hint
    return {
        "provider": provider.strip(),
        "model_name": model_name.strip(),
        "api_key": api_key,
        "base_url": base_url,
    }


def build_history(turns: int) -> list[dict[str, str]]:
    """构造多轮历史；用 dict 表示，便于无密钥时也不依赖 langchain。"""
    system = {
        "role": "system",
        "content": (
            "你是经营数据分析助手。规则：金额单位是分；只复述给定数字；"
            "不确定时说“不确定”；不要编造地区数据。"
        ),
    }
    history: list[dict[str, str]] = [system]
    for index in range(turns):
        history.append(
            {
                "role": "user",
                "content": f"第 {index + 1} 轮：2026 年九月净销售额 {1286500 + index * 1000} 分，八月 1190000 分。",
            }
        )
        history.append(
            {
                "role": "assistant",
                "content": f"第 {index + 1} 轮记录：九月 {1286500 + index * 1000} 分，八月 1190000 分。",
            }
        )
    history.append({"role": "user", "content": "那华东地区呢？"})
    return history


def estimate_tokens(text: str) -> int:
    """极简 token 估算：中文按 1 字 1 token，英文按 4 字符 1 token。

    教学简化：真实分词器（tokenizer）不同，本函数只用于展示“趋势”。
    """
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    others = len(text) - cjk
    return cjk + max(1, others // 4)


def total_tokens(history: list[dict[str, str]]) -> int:
    return sum(estimate_tokens(item["content"]) for item in history)


def truncate_history(history: list[dict[str, str]], max_messages: int) -> list[dict[str, str]]:
    """保留 system + 最近 max_messages 条非 system 消息。

    规则显式：system 永远保留（否则规则丢失）；其余按“越旧越先丢”。
    """
    system_messages = [item for item in history if item["role"] == "system"]
    others = [item for item in history if item["role"] != "system"]
    kept = others[-max_messages:]
    return system_messages + kept


def main() -> int:
    print("== 单元 02 实验：上下文增长与截断 ==")
    config = load_config()

    for turns in (1, 5, 20):
        history = build_history(turns)
        tokens = total_tokens(history)
        truncated = truncate_history(history, MAX_HISTORY_MESSAGES)
        print(
            f"轮数={turns:>2} 消息数={len(history):>3} 估算输入token={tokens:>5} "
            f"截断后消息数={len(truncated):>2} 截断后token={total_tokens(truncated):>5}"
        )

    print("\n== 同一问题的两种问法 ==")
    print("A 带上下文：", build_history(1)[-2:])
    print("B 不带上下文：", [{"role": "user", "content": "那华东地区呢？"}])
    print("→ A 能让模型知道“哪个月、什么指标”；B 不能。上下文不会自己保留。")

    enabled = bool(config["model_name"]) and bool(config["api_key"])
    if not enabled:
        print("\n[规则模式] 未配置模型，跳过真实调用。下面用本地确定性函数模拟回复：")
        print("    假模型回复：本轮问题缺少时间与指标，请你补充“哪个月、哪个指标”。")
        print("\n[结论] 即使没密钥，你也能观察：历史越长 token 越多、截断会丢信息。")
        return 0

    from langchain_core.messages import AIMessage, HumanMessage, SystemMessage
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model=config["model_name"],
        api_key=config["api_key"],
        base_url=config["base_url"],
        temperature=0.0,
        timeout=60.0,
        max_retries=0,
    )

    def ask(messages: list[dict[str, str]]) -> str:
        converted = []
        for item in messages:
            if item["role"] == "system":
                converted.append(SystemMessage(content=item["content"]))
            elif item["role"] == "assistant":
                converted.append(AIMessage(content=item["content"]))
            else:
                converted.append(HumanMessage(content=item["content"]))
        reply = model.invoke(converted)
        usage = getattr(reply, "usage_metadata", None)
        return f"{reply.content}\n    [usage] {usage}"

    print("\n--- 带上下文提问 ---")
    print(ask(build_history(2)))

    print("\n--- 只发最后一句 ---")
    print(ask([{"role": "user", "content": "那华东地区呢？"}]))

    print("\n--- 截断后再问 ---")
    print(ask(truncate_history(build_history(20), MAX_HISTORY_MESSAGES)))
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### 5.5 上下文策略：先定规则，再写代码

| 策略 | 做法 | 代价 | 适用 |
| --- | --- | --- | --- |
| 全量 | 把所有历史都发 | 越来越贵、可能超限 | 短会话 |
| 滑动窗口 | 只保留最近 N 条 | 丢掉早期约定（如用户偏好） | 本项目 thread 内默认 |
| 摘要压缩 | 把旧历史压成一段摘要 | 摘要本身会失真、需要额外调用 | 长会话 |
| 结构化记忆 | 关键事实抽出成字段（如 `last_spec`） | 需要设计 schema | **本项目采用**：`last_spec` 专门存上一轮解析结果 |
| 外部检索 | 历史进向量库，按需检索 | 复杂、可能检索不到 | 高级场景 |

**项目选择**：`AssistantState` 里同时保留 `messages`（给模型看）与 `last_spec`（给程序用）。追问“那华东地区呢？”由 `understand` 节点读 `last_spec` 补全，而不是让模型从长历史里自己猜。理由：可测试、可解释、不依赖模型能力。代价：字段多、要维护一致性。

### 5.6 一个必须警惕的坑：历史里的错误会被继承

如果第 1 轮模型说“九月净销售额 1300000 分”（错的），第 2 轮你把它放进历史，模型很可能继续说这个错数。**修法不是加提示词，而是不让模型成为数字来源**：数字来自数据库与程序计算，模型只复述。

## 10. 复盘问题与参考答案、下一步

### Q1：模型到底有没有“记忆”？

**参考**：没有。模型是无状态的函数：输入 token 序列 → 输出 token 序列。你看到的“记得”，是每次请求里带上了历史。所以“记忆”永远是**程序的责任**：状态、数据库、checkpoint（单元 07、09）。

### Q2：为什么本项目不把全部历史都发给模型？

**参考**：三个原因——成本线性增长、超长会报错、历史里的错误会被继承。项目里 thread 内保留消息（给模型看上下文），但关键事实单独存字段（`last_spec`、`calculation`），需要时由程序注入。这是**项目设计选择**：用结构化数据替代“让模型自己回忆”。

### Q3：`ToolMessage` 为什么必须带 `tool_call_id`？

**参考**：因为模型可能一次发起多个工具调用，程序必须能一一对应“这条结果属于哪个申请”。没有 id 就无法配对，协议上也就无法回放。单元 04 会看到完整流程：`AIMessage.tool_calls` → 程序执行 → `ToolMessage(tool_call_id=...)` → 再 `invoke`。

### Q4：提示词里写“不要编造”有用吗？

**参考**：**有一点用，但不可依赖**。它是概率约束，不是硬保证。真正的防护是：数字来自程序计算、引用 id 事后校验、人工审批。项目把“提示词约束”当第一层，把“程序校验”当第二层，把“人工审批”当第三层。

### Q5：截断历史时，为什么 system 必须保留？

**参考**：system 承载角色与规则（单位、禁止编造、输出格式）。丢了 system，模型就退化成“通用聊天”，表现是单位写错、开始编数据。这就是练习 7.3 要你亲手体验的故障。
