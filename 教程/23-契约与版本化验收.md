# 单元 23：契约与版本化验收

建议放在 00–21 主线完成后，约 90 分钟。目标是把“能演示的助手”变成“边界行为可以解释、可以回归的求职项目”。先复习 13 的指标口径、16 的中断、17 的持久化、20 的评估。

## 1. 从需求推导可检验的契约

用户需要的是对明确期间、明确地区、明确指标给出可追溯结果，并且只导出自己批准的版本。框架帮你管理执行状态；业务正确性仍须由数据契约、校验和测试建立。

| 不变量 | 实现位置 | 验收方式 |
| --- | --- | --- |
| 不支持的指标不能偷偷算成净销售额 | `domain/question.py` | “利润变化多少”应澄清 |
| 显式输入优先于历史；无输入才继承 | `workflow/nodes.py` understand | 华东追问后说“全国”必须清除地区筛选；说“毛销售额”必须切换指标 |
| 当前值减基期值等于差额 | `domain/metrics.py` | 整数分断言，不能只比报告状态 |
| 地区分项与总量必须属于同一指标、同一范围 | queries / compute / format | gross、refund、net 各自对账；过滤地区同时过滤计数与明细表 |
| 批准的是当前那份正文 | persistence / API | 当前 report_id + interrupt_id；可附草稿 SHA256 |
| 不同报告不能覆盖历史产物 | report/export | thread_id + report_id；同版本同内容复用，内容冲突拒绝 |
| 工具预算限制实际执行量 | simple_agent / nodes | 一次请求 9 个工具、限额 2，实际只能执行 2 个 |
| 资料不足必须可识别 | knowledge/qa | 引用 ID 存在仍不够，每条引文须出自对应命中块 |

解析器是规则实现，支持范围见源码与回归测试。对任意自然语言的理解不是本项目已经证明的能力。商品/月/渠道维度尚未实现，会请求澄清；只有地区维度可算。

## 2. LangChain 与 LangGraph 的关系

LangChain 的消息、模型、工具、结构化输出和 `create_agent` 解决“模型如何与外部能力交互”。LangGraph 的状态通道、reducer、条件边、checkpointer、interrupt 解决“执行过程怎样被控制和恢复”。`create_agent` 建立在 LangGraph 运行时上。

本项目主链路用显式图和确定性程序计算；可选 Agent 演示由模型选工具。无 key 时能验收工程链路；要在简历中声称模型能力，必须另附真实模型测试结果与质量评估。

| 文档 | 本章需要核对什么 |
| --- | --- |
| [LangChain overview](https://docs.langchain.com/oss/python/langchain/overview) | create_agent 与 LangGraph 的层次关系 |
| [LangGraph overview](https://docs.langchain.com/oss/python/langgraph/overview) | durable execution、human-in-the-loop 与状态编排 |
| [interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) | 节点恢复从开头重跑；中断前副作用须谨慎 |

## 3. 完整运行与审批协议

在 `ops-assistant/` 下先执行：

```bash
uv sync --locked
uv run python scripts/bootstrap.py
uv run python ../教程/实验/14_workflow.py
```

实验使用临时数据库和检查点，依次完成混合问题、批准并导出、同线程地区追问、拒绝新稿、纯知识问答。金额来自程序，纯知识问答返回 `answered`，不要求销售月份。

HTTP 调用示例（需先启动 API；`httpx.Client(trust_env=False)` 只用于本机演示）：

```python
import httpx

with httpx.Client(base_url="http://127.0.0.1:8000", trust_env=False) as client:
    response = client.post("/api/chat", json={
        "question": "2026年9月销售额比8月变化多少？按地区分解并说明退款口径。"
    })
    response.raise_for_status()
    turn = response.json()
    assert turn["status"] == "awaiting_approval"
    pending = turn["interrupt"]
    approved = client.post(f"/api/threads/{turn['thread_id']}/resume", json={
        "decision": "approve",
        "report_id": turn["report_id"],
        "interrupt_id": pending["id"],
        "content_hash": pending["payload"]["content_hash"],
    })
    approved.raise_for_status()
    assert approved.json()["status"] == "approved"
```

待审批期间禁止覆盖当前问题。旧版本/缺失审批标识返回 409；非法编辑返回 422 并继续待审批。主项目允许原文末尾追加无数字备注，不能改正文、符号、单位、数字归属或插入新引用。数字集合比较无法阻止“金额没变，解释变了”。

导出失败可对原版本再次 approve 重试，不重新计算数字。`GET /api/threads/{thread_id}/reports` 列出已批准导出版本；`GET /api/threads/{thread_id}/report?report_id=...` 取历史版本。重复审批只对相同已导出结果作幂等返回。

本项目内部 Python runtime 保留旧调用兼容，可从当前快照补齐信息；面向客户端的 HTTP 接口强制要求版本标识。`user_id` 所属检查不能代替认证：调用方仍可自报 user_id，此项目只作本机单用户演示。

## 4. 四个必须亲手验证的框架边界

```bash
uv run python ../教程/实验/23_framework_contracts.py
uv run python ../教程/实验/23_agent_budget.py
```

第一个实验包含断言：

- 当前版本普通节点返回 `None` 表示无状态更新；末端节点没有显式 END 边也能结束；未知输出键可能被忽略。依赖你自己的 schema 和测试发现拼写错误。
- 无 reducer 的同一 superstep 两个写入抛 `InvalidUpdateError`，不能理解为“后写覆盖”。
- 深度不同的两条分支各自连 join 可能执行两次；`add_edge(["a", "b2"], "join")` 才是等待两条支路的屏障。
- 从历史检查点重放得到 6，分叉改值后得到 14；原快照值仍是 3。读取历史、重放、分叉是三种动作。

第二个实验用确定性假模型一次请求 9 个工具调用，官方 middleware 限制实际执行为 2。`recursion_limit` 限的是图执行步，不是工具数量。该实验测试真实 create_agent 调度与 middleware，不证明任何真实模型的工具选择质量。

## 5. 端到端恢复和界面验收

```bash
uv run python scripts/verify_recovery.py
uv run python scripts/verify_ui.py
```

恢复实验启动三个不同 Python 进程：生成待审批稿，退出；第二个进程审批导出；第三个进程重复批准并检查路径与文件字节一致。它比同一进程关闭/重建两个 runtime 的证明更强。

界面实验启动真实 FastAPI 服务，Streamlit AppTest 操作页面，验证批准、下载按钮、新建会话不会误选历史、编辑器绑定当前草稿以及历史会话的审批目标。结果保存在 `data/verification/`。它不覆盖浏览器渲染与多用户压测。

## 7. 对抗练习

先给期望再运行，不要看到输出才修改标准：

1. 问九月同比，确认基期是上年九月；问“从八月到九月”，确认差额方向。
2. 问华东净销售额，完成审批后追问毛销售额，再问全国，检查指标与地区切换。
3. 保存审批卡片 A，完成后生成卡片 B，发送 A 的 report_id/interrupt_id，期望 409。
4. 尝试只改负号或“元”为“万元”，即使数字都还在也须拒绝，且仍待审批。
5. 同线程批准两份报告，检查两条历史产物都存在，旧文件字节未变。
6. 模拟导出失败，恢复权限/路径后对同一版本重试，检查无需再次问问题。
7. 对纯知识问题设置无销售月份，确认直接回答；给未实现的利润指标，确认澄清。
8. 将 eval 的一个 expect_values 改错，确认退出非零，再恢复用例。
