1. 用 `float` 表示 0.1 时，实际存进去的是什么？（提示：二进制无法精确表示 1/10）

4. 如果金额用 `float` 存“元”，在第几笔累加时会开始出现 0.01 的偏差？这个偏差在“对账”场景里意味着什么？
5. `replace(obj, field=value)` 之后，原对象变了吗？

> **官方事实**（链接见上，核对日期 2026-10-19）：
> 二进制浮点无法精确表示大多数十进制小数，因此浮点运算会累积表示误差；`round()` 在两候选值等距时向偶数舍入（banker's rounding），所以 `round(2.675, 2)` 期望得到的是 `2.67` 而不是直觉上的 `2.68`。
> `dataclasses.replace()` 会调用 `__init__` 构造一个**新实例**；对 `frozen=True` 的数据类来说，这是唯一“改动”它的合法方式。
>

>
> **未验证**：`round(2.675, 2)` 的实际返回值依赖 CPython 版本与平台浮点行为，请自己跑一次 `python -c "print(round(2.675, 2))"` 确认，再和“为什么我们不用浮点算钱”对应起来。

## 3. 通俗解释与精确技术定义

### 3.1 三条公式：进账、回吐、口径

用记账比喻：

- **毛销售额**＝本月**进账**（订单成交金额之和）。注意是“成交价”，不是“价目表价”。
- **退款额**＝本月**回吐**（已批准的退款金额之和）。注意按“退款发生月”，不是“原订单月”。
- **净销售额**＝进账减回吐，是**默认口径**。这就是“销售额”在项目里默认指的东西。

精确写法（与本项目 `data/knowledge/01_指标口径.md`、`02_退款与归属.md` 完全一致）：

```
毛销售额 gross  = Σ(orders.quantity × orders.unit_price_cents)   按 order_date 所在月归集，单位：分
退款额  refund  = Σ(refunds.amount_cents)                        条件 status = 'approved'，按 refund_date 所在月归集
净销售额 net    = gross − refund                                 允许为负，单位：分
```

三条容易错的细节：

1. `orders.unit_price_cents` 是**成交价**；`products.unit_price_cents` 是**目录价**。用错列不会报错，只会每个数字偏一点点。
2. `refund` 只加 `approved`。`pending`（待处理）与 `rejected`（已拒绝）**一分钱都不加**。
3. `net` 可以是**负数**（退款大于毛额）。这不是 bug，也不该被“修正”成 0。

### 3.2 退款归属：同一笔钱，两个月份

先看时间轴（数字是**假想的**，用来说明规则）：

```
2026-08-25  订单成交 5,000 元（记在 8 月账上）
                  │
                  │  34 天后才退
                  ▼
2026-09-05  退款 approved 5,000 元（记在 9 月账上）
```

结果：

| 月份 | 毛销售额 | 退款额 | 净销售额 |
| --- | --- | --- | --- |
| 2026-08 | +5,000 元 | 0 | +5,000 元（**不受影响**） |
| 2026-09 | 其他订单 | +5,000 元 | 被这笔退款压低 |

**为什么不能“回头改 8 月”？** 因为账是**按发生期**记的：8 月发生的是“卖”，9 月发生的是“退”。如果把退款塞回 8 月，等于篡改已经结账的历史报表；而且只要下个月又退一笔，8 月的数字就会**继续变**，报表永远不稳定。

**正确表述**（单元 16 的报告里也必须这么写）：*“这笔退款的销售发生在 8 月，退款发生在 9 月；按退款发生月归属，它降低的是 9 月的净销售额，不改变 8 月的数据。”*

时间轴上的三种状态分别意味着：

| 状态 | 含义 | 计入退款额 | 报告里怎么写 |
| --- | --- | --- | --- |
| `approved` | 已批准 | 是 | 计入本月退款额 |
| `pending` | 待处理 | **否** | “存在待处理退款，若后续批准，净销售额会下降” |
| `rejected` | 已拒绝 | 否 | 不计入；一般不在报告里单列 |

`pending` 是最容易出错的一个：数据里**有记录**、金额**看得见**，但它**不是一个已经发生的损失**。所以本项目既不加钱，也不装作没看见——`MonthSales.pending_refund_count` 专门记它的**笔数**，报告里据此提示。

### 3.3 整数分与展示换算（元 / 万元）

内部一律整数分。展示是**一次性的、单向的**换算，绝不允许把“展示值”再喂回计算。

```
分 → 元   ：÷ 100       例：1,234,567 分 → 12,345.67 元
元 → 万元 ：÷ 10,000    例：12,345.67 元 → 1.23 万元
所以：分 → 万元 = ÷ 1,000,000
```

`data/knowledge/01_指标口径.md` 第 5 节给的例子就是 `1234567 分 → 12345.67 元 → 1.23 万元`，注意那里的“除以 10000”指的是**从元到万元**这一步，不是从分直接除 10000（1234567 ÷ 10000 = 123.46，那是“百元”，不是万元）。

用浮点算钱会发生什么？下面这段可以在你自己的机器上跑（**预期，未在本环境执行**）：

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> sum([0.1] * 10) == 1.0
False
>>> round(2.675, 2)
2.67
```

第一、二行是**二进制浮点表示误差**（官方文档有专门一节讲这个）；第三行是 `round()` 的**偶数舍入**。两者叠加的后果：如果你用 `float` 存“元”，几十万笔累加之后，报表和财务系统会差几分钱——而这几分钱会让一份报告“不可复核”。

### 3.4 差额、变化率与零基数

```
delta       = 本期指标 − 上期指标                      （整数分，可正可负）
pct_change  = delta / |上期指标|                       （上期指标为 0 时：无定义）
```

三条硬规则：

1. **上期为 0 → 变化率无定义**。返回 `None`，配一个布尔字段 `base_zero=True`。报告里写“基期为 0，变化率无定义”。
   绝不允许写成 `∞`、`+100%`、`N/A` 混着用，更不允许“既然除不了，就写 100% 吧”。
2. **分母取绝对值**（`abs(previous)`）。这样“本期比上期多”永远是正号、“少”永远是负号，读者不用再心算“上期是负数时符号怎么翻”。
3. **不用浮点做中间结果**。`delta` 是整数；`pct_change` 是展示用的派生值，算成 `float` 无妨，但**它不能反过来参与金额计算**。

> **口径提醒（需要你知道的措辞差异）**：知识库 `01_指标口径.md` 第 4 节写的是“`pct_change = delta / 上期净销售额`（分母为前一期净额，按项目口径保留符号）”，而代码 `domain/metrics.py` 实际写的是 `delta / abs(previous_value)`。两者在“上期为正”时完全一致；**上期为负**时结果符号相反。代码是最终口径（我想让“增长”永远是正号），但知识库那句“按项目口径保留符号”措辞含糊，建议按“分母取绝对值”理解。这一条我已记入不一致记录，交给负责知识库文档的同学统一。

### 3.5 地区差额分解与合计校验

把总差额拆到地区：

```
地区差额 = 该地区本期净额 − 该地区上期净额
Σ地区差额 == 总差额      ← 必须成立，且必须打印“合计校验行”
```

为什么必须校验？因为“拆”这个动作**太容易漏**：

- 上月有、本月完全没记录的地区（例如东北某月缺数据）如果被漏掉，它的差额（负数）就丢了；
- 某地区本月没记录、上月有，如果只遍历“本月有数据的地区”，这个地区也不会出现在报告里；
- 最后总和就对不上，而报表上**每一行看起来都正常**。

所以项目做了三件事：`get_region_breakdown` **恒返回全部地区**（单元 12 的 5.5）；`metrics.py` 补上“只在上月出现”的地区；结果里同时给出 `region_delta_sum_cents`，让报告层能打印一行“合计校验”。

补充一条容易被忽略的规则：**如果用户只要看几个地区，不能直接过滤结果行**，必须把本月/上月的**整月合计重算**成“这几个地区之和”，否则“地区差额之和 ≠ 总差额”。`metrics.py` 里 `_recompute_month` 就是干这个的。

### 3.6 术语双语表

| 术语 | 英文 | 本项目含义 |
| --- | --- | --- |
| 毛销售额 | gross sales | 订单成交金额之和（按 `order_date`） |
| 退款额 | refunds | 已批准退款之和（按 `refund_date`） |
| 净销售额 | net sales | 毛额 − 退款额，可为负；**默认口径** |
| 差额 | delta | 本期 − 上期，整数分 |
| 变化率 | percentage change / pct_change | `delta / abs(上期)`，上期为 0 时无定义 |
| 贡献占比 | share of delta | 某地区差额 ÷ 总差额；总差额为 0 时无定义 |
| 基期 | base period | 用来对比的“上期” |
| 零基数 | zero base | 基期指标为 0，导致变化率无定义 |
| 真零 | true zero | 有数据但结果为 0（如毛额恰好被退款冲平） |
| 无记录 | no records | 一行都没匹配到，与“值为 0”不同 |
| 固定单位 | fixed-point | 用整数分记账，禁止用浮点存钱 |

### 3.7 为什么这些数字必须由程序算

一节单独讲，因为这是整个项目“防幻觉”的主干（单元 01 第 850 行、单元 02 第 501 行都在讲这条）。

1. **模型没有计算能力，只有“看起来像”的能力**。你让它算“8 月净额减 9 月净额”，它会给出一个**格式完全正确、语气非常自信**的数字。它错的时候不会报错、不会崩，只是数字变了。
2. **多步运算会放大错误**。净额→差额→变化率→地区分解，每一步的错误都会被下一步当成输入。手算四步几乎必错；模型“心算”四步同理。
3. **口径必须可复核**。报告里的每个数字都要能追到**一条 SQL 或一个函数返回值**。追不到的数字，在审计意义上等于不存在。
4. **整数分不是洁癖，是能不能对账**。前面 `0.1 + 0.2` 的例子已经说明：浮点算钱会漂。漂了的数字没法解释“为什么和财务系统差 3 分”。

推论（单元 16 会强化）：**模型只负责“选口径 + 组织语言”，数字一律来自工具调用返回值**；报告中出现的数字必须能在上下文的工具结果里找到出处。

两条必须记住的分层纪律：

1. **`metrics.py` 不打印、不格式化、不调模型**。它返回 `ComparisonResult`（一个 frozen dataclass），单位仍是分。想变成“1.23 万元”是报告层的事。
2. **`metrics.py` 不写 SQL**（除了一处：`get_month_sales` / `get_region_breakdown` 这两个函数在 `queries.py` 里）。它只在拿到的数据结构上做算术——这样口径计算可以脱离数据库做单元测试（传入手工构造的 `MonthSales` 即可）。

还有一条容易被忽略的设计：`compare_months` 支持 `metric="gross_sales" | "refunds"`，而 `RegionDelta` 的字段名却固定叫 `current_net_cents` / `delta_cents`。也就是说，**切到毛额口径时，这些字段里装的是毛额**。这是命名的历史包袱（先有净额，后加口径切换），读代码时要留意，不要看到 `_net_` 就以为是净额。这一条也记入了不一致记录。

### 5.1 三条公式对应的三条 SQL

这三条就是单元 12 里 `queries.py` 的 SQL 常量，但这一遍要看的是**它们与口径的对应关系**（`?` 依次是本月的 `start`、`end`）：

```sql
-- 毛销售额：按 order_date 归集，用订单成交价
SELECT COALESCE(SUM(quantity * unit_price_cents), 0) AS gross_cents,
       COUNT(*) AS order_count
FROM orders
WHERE order_date >= ? AND order_date < ?;

-- 退款额：按 refund_date 归集，只要 approved
SELECT COALESCE(SUM(amount_cents), 0) AS refund_cents,
       COUNT(*) AS approved_refund_count
FROM refunds
WHERE status = 'approved'
  AND refund_date >= ? AND refund_date < ?;

-- 退款记录数（含 pending/rejected）与 pending 笔数：只取笔数，不取金额
SELECT COUNT(*) AS refund_record_count,
       COALESCE(SUM(status = 'pending'), 0) AS pending_refund_count
FROM refunds
WHERE refund_date >= ? AND refund_date < ?;
```

净额**不在 SQL 里算**，在 Python 里算：`net_cents = gross_cents - refund_cents`。理由：净额是“口径定义”而不是“数据属性”，定义应该只有一处；放在 Python 里还能被纯单元测试覆盖。

地区分解要多一个 `JOIN`（退款表本身没有 `region_id`，必须挂到订单上才拿得到地区）：

```sql
SELECT orders.region_id AS region_id,
       SUM(refunds.amount_cents) AS refund_cents
FROM refunds
JOIN orders ON orders.order_id = refunds.order_id
WHERE refunds.status = 'approved'
  AND refunds.refund_date >= ? AND refunds.refund_date < ?
GROUP BY orders.region_id;
```

注意这里的**关键区别**：过滤用的是 `refunds.refund_date`，`GROUP BY` 用的是 `orders.region_id`。`JOIN` 只用来“借”地区字段，**不改变退款归属月份**。一旦把过滤条件误写成 `orders.order_date`，跨月退款就会归错月（练习 7.2 让你亲手改坏它）。

### 5.2 完整代码：`src/ops_assistant/domain/metrics.py`

保存路径：`ops-assistant/src/ops_assistant/domain/metrics.py`

```python
"""指标比较：月份环比、差额分解与边界标记。

本模块只做纯计算，不打印、不写库、不调用模型。所有金额都是整数分，
``pct_change`` / ``share_of_delta`` 只用于展示，计算过程不产生浮点误差。
"""

from __future__ import annotations

import sqlite3
from dataclasses import dataclass, replace

from ops_assistant.data.queries import (
    MonthSales,
    RegionSales,
    get_month_sales,
    get_region_breakdown,
)

#: 允许的指标：净销售额、毛销售额、退款额。
_METRICS = ("net_sales", "gross_sales", "refunds")


@dataclass(frozen=True)
class RegionDelta:
    """一个地区在两个月之间的差额。金额单位：分。"""

    region_id: str
    region_name: str
    current_net_cents: int
    previous_net_cents: int
    delta_cents: int
    share_of_delta: float | None


@dataclass(frozen=True)
class ComparisonResult:
    """两个月比较的完整结果，供报告层与测试使用。"""

    current: MonthSales
    previous: MonthSales
    delta_net_cents: int
    pct_change: float | None
    base_zero: bool
    regions: tuple[RegionDelta, ...]
    region_delta_sum_cents: int
    dimension: str
    metric: str
    notes: tuple[str, ...]
    unsupported_dimension: str | None


def _metric_value(sales: MonthSales, metric: str) -> int:
    """按指标取月份汇总值。"""

    if metric == "gross_sales":
        return sales.gross_cents
    if metric == "refunds":
        return sales.refund_cents
    return sales.net_cents


def _region_value(region: RegionSales, metric: str) -> int:
    """按指标取地区汇总值。"""

    if metric == "gross_sales":
        return region.gross_cents
    if metric == "refunds":
        return region.refund_cents
    return region.net_cents


def compare_months(
    conn: sqlite3.Connection,
    current_month: str,
    previous_month: str,
    *,
    dimension: str = "region",
    region_ids: tuple[str, ...] | None = None,
    metric: str = "net_sales",
) -> ComparisonResult:
    """比较两个月的指标，并按地区分解差额。

    参数
    ----
    conn:
        已打开的 SQLite 连接。
    current_month / previous_month:
        ``YYYY-MM``；格式错误由查询层抛 ``ValueError``。
    dimension:
        目前真正支持差额分解的是 ``region``；``unknown`` 按 ``region`` 处理；
        ``channel`` 或其他值会返回 ``unsupported_dimension``，不抛异常。
    region_ids:
        非空时只分析这些地区，并把本月/上月的汇总按过滤后的地区重算。
    metric:
        ``net_sales``（默认）/ ``gross_sales`` / ``refunds``。

    返回
    ----
    ComparisonResult：包含差额、变化率、地区分解、边界说明。
    """

    if metric not in _METRICS:
        raise ValueError(f"不支持的指标：{metric!r}；可选：{', '.join(_METRICS)}")

    normalized_dimension = "region" if dimension == "unknown" else dimension
    unsupported: str | None = None
    notes: list[str] = []

    if normalized_dimension not in ("region",):
        unsupported = normalized_dimension
        notes.append(
            "当前差额分解只支持按地区；"
            f"维度 {normalized_dimension!r} 可以查询明细，但不做差额分解。"
        )

    current = get_month_sales(conn, current_month)
    previous = get_month_sales(conn, previous_month)
    current_regions = get_region_breakdown(conn, current_month)
    previous_regions = get_region_breakdown(conn, previous_month)

    # 过滤地区后，整月汇总必须重算，保证“地区差额之和 == 总差额”。
    if region_ids:
        current = _recompute_month(current, current_regions, region_ids)
        previous = _recompute_month(previous, previous_regions, region_ids)
        current_regions = [item for item in current_regions if item.region_id in region_ids]
        previous_regions = [item for item in previous_regions if item.region_id in region_ids]

    current_value = _metric_value(current, metric)
    previous_value = _metric_value(previous, metric)
    delta = current_value - previous_value
    base_zero = previous_value == 0
    pct_change = None if base_zero else delta / abs(previous_value)

    region_deltas: list[RegionDelta] = []
    if unsupported is None:
        previous_by_id = {item.region_id: item for item in previous_regions}
        for item in current_regions:
            previous_item = previous_by_id.pop(item.region_id, None)
            previous_net = _region_value(previous_item, metric) if previous_item else 0
            current_net = _region_value(item, metric)
            region_deltas.append(
                RegionDelta(
                    region_id=item.region_id,
                    region_name=item.region_name,
                    current_net_cents=current_net,
                    previous_net_cents=previous_net,
                    delta_cents=current_net - previous_net,
                    share_of_delta=None if delta == 0 else (current_net - previous_net) / delta,
                )
            )
        # 只在上月出现、本月完全没有记录的地区也要展示（例如东北缺月）。
        for region_id, item in previous_by_id.items():
            previous_net = _region_value(item, metric)
            region_deltas.append(
                RegionDelta(
                    region_id=region_id,
                    region_name=item.region_name,
                    current_net_cents=0,
                    previous_net_cents=previous_net,
                    delta_cents=-previous_net,
                    share_of_delta=None if delta == 0 else (-previous_net) / delta,
                )
            )

    region_deltas.sort(key=lambda item: (-abs(item.delta_cents), item.region_id))
    region_sum = sum(item.delta_cents for item in region_deltas)

    if not current.has_orders:
        notes.append(f"{current.month} 没有任何订单记录，属于“无记录”，不能当作销售额为 0。")
    if not previous.has_orders:
        notes.append(f"{previous.month} 没有任何订单记录；作为基期时无法计算有意义的环比。")
    if current.gross_cents > 0 and current.net_cents == 0:
        notes.append(f"{current.month} 有订单，但退款恰好冲抵毛销售额，净销售额为 0（真零）。")
    if previous.gross_cents > 0 and previous.net_cents == 0:
        notes.append(f"{previous.month} 净销售额为 0（有订单且被退款冲抵），变化率以 0 为基期无定义。")
    if current.net_cents < 0:
        notes.append(f"{current.month} 净销售额为负：已批准退款大于毛销售额。")
    if current.pending_refund_count > 0:
        notes.append(
            f"{current.month} 有 {current.pending_refund_count} 笔待处理退款，未计入退款额；"
            "若后续批准，净销售额会下降。"
        )
    if base_zero and not any("基期" in note for note in notes):
        notes.append("基期指标为 0，变化率无定义。")
    if unsupported is None and delta != 0 and region_sum != delta:
        notes.append(
            f"内部校验异常：地区差额合计 {region_sum} 分与总差额 {delta} 分不一致。"
        )

    return ComparisonResult(
        current=current,
        previous=previous,
        delta_net_cents=delta,
        pct_change=pct_change,
        base_zero=base_zero,
        regions=tuple(region_deltas),
        region_delta_sum_cents=region_sum,
        dimension=normalized_dimension,
        metric=metric,
        notes=tuple(notes),
        unsupported_dimension=unsupported,
    )


def _recompute_month(
    month_sales: MonthSales,
    regions: list[RegionSales],
    region_ids: tuple[str, ...],
) -> MonthSales:
    """按地区过滤重算月份汇总。"""

    kept = [item for item in regions if item.region_id in region_ids]
    gross = sum(item.gross_cents for item in kept)
    refund = sum(item.refund_cents for item in kept)
    orders = sum(item.order_count for item in kept)
    return replace(
        month_sales,
        gross_cents=gross,
        refund_cents=refund,
        net_cents=gross - refund,
        order_count=orders,
        has_orders=orders > 0,
    )
```

### 5.3 逐字段读 `ComparisonResult`（这张表建议抄一遍）

| 字段 | 类型 | 语义 | 常见误用 |
| --- | --- | --- | --- |
| `current` / `previous` | `MonthSales` | 本期/上期的全量汇总（含 9 个字段） | 只看 `net_cents`，忽略 `has_orders` |
| `delta_net_cents` | `int` | 本期指标 − 上期指标，整数分 | 当 `metric="gross_sales"` 时它其实是**毛额差额** |
| `pct_change` | `float \| None` | `delta / abs(上期)`；None = 无定义 | 把 `None` 当 0 或当 100% 打印出来 |
| `base_zero` | `bool` | 上期指标是否为 0（**必须和 `pct_change is None` 一起判断**） | 只判断 `pct_change is None` 就写“无数据” |
| `regions` | `tuple[RegionDelta, ...]` | 按差额绝对值降序的地区差额 | 按 `region_id` 排序后再展示，读者看不到“谁贡献最大” |
| `region_delta_sum_cents` | `int` | 各地区差额之和 | 忘了和 `delta_net_cents` 比对 |
| `dimension` | `str` | 实际使用的维度（`unknown` 已被归一为 `region`） | 直接回显用户原始词 |
| `metric` | `str` | 本次用的指标 | 报告里没写清是净额还是毛额 |
| `notes` | `tuple[str, ...]` | 边界说明（无记录/真零/负净额/pending/校验异常） | 只把 notes 写进日志、不写进报告 |
| `unsupported_dimension` | `str \| None` | 用户问了渠道等不支持的维度时的原始值 | 静默返回空分解，让用户以为“渠道没数据” |

两处**已知局限**（读代码时要注意，别以为是 bug）：

1. `_recompute_month` 只重算 `gross_cents / refund_cents / net_cents / order_count / has_orders`。`pending_refund_count`、`approved_refund_count`、`has_any_refund_records` **仍是全库（全地区）的值**——因为 `RegionSales` 结构里没有这两类计数字段，按地区过滤时无法重算。影响：用 `region_ids` 过滤后，`notes` 里“有 N 笔待处理退款”的 N 可能是全地区的。
2. `RegionDelta` 的字段名带 `_net_` 后缀，但 `metric="gross_sales"` 时字段里装的是毛额（见第 4 节末尾）。

这些是**项目设计选择**（生成器刻意构造出来的演示数据），不是真实业务规律。表中不写具体金额——具体数值在你要跑的库里，请用第 8 节实验查。

| 边界形态 | 位置 | 想让你看到什么 | 生成器里的对应常量 |

### 5.5 实验脚本（完整代码）

保存路径：`教程/实验/13_metrics_check.py`

脚本做五件事：① 用**手写 SQL** 独立算两个月的毛/退/净；② 与项目查询层逐项比对；③ 把跨月退款挖出来看；④ 调 `compare_months` 打印差额、变化率、地区分解与合计校验；⑤ 演示整数分换算与浮点陷阱。

```python
"""单元 13 实验：指标计算、退款归属与差额分解。

保存路径：教程/实验/13_metrics_check.py

运行（在 ops-assistant/ 目录下）：
    uv run python ../教程/实验/13_metrics_check.py
    uv run python ../教程/实验/13_metrics_check.py --current 2026-09 --previous 2026-08
"""

from __future__ import annotations

import argparse
import sqlite3
import sys
from pathlib import Path

#: 教程/实验/13_metrics_check.py → parents[0]=实验, [1]=教程, [2]=仓库根
REPO_ROOT = Path(__file__).resolve().parents[2]
PROJECT_DIR = REPO_ROOT / "ops-assistant"

#: 手写 SQL：故意不用 queries.py，用来独立复核。
GROSS_SQL = """
SELECT COALESCE(SUM(quantity * unit_price_cents), 0) AS gross_cents,
       COUNT(*) AS order_count
FROM orders
WHERE order_date >= ? AND order_date < ?
"""

REFUND_SQL = """
SELECT COALESCE(SUM(amount_cents), 0) AS refund_cents,
       COUNT(*) AS approved_refund_count
FROM refunds
WHERE status = 'approved'
  AND refund_date >= ? AND refund_date < ?
"""

CROSS_MONTH_SQL = """
SELECT refunds.refund_id AS refund_id,
       refunds.amount_cents AS amount_cents,
       refunds.status AS status,
       refunds.refund_date AS refund_date,
       orders.order_id AS order_id,
       orders.order_date AS order_date,
       orders.region_id AS region_id
FROM refunds
JOIN orders ON orders.order_id = refunds.order_id
WHERE substr(orders.order_date, 1, 7) = ?
  AND substr(refunds.refund_date, 1, 7) = ?
ORDER BY refunds.refund_date, refunds.refund_id
"""


def _resolve_db(explicit: Path | None) -> Path:
    """决定要打开哪个数据库文件。"""
    if explicit is not None:
        return explicit
    return PROJECT_DIR / "data" / "ops.db"


def _month_bounds(month: str) -> tuple[str, str]:
    """返回半开区间 [本月 1 号, 次月 1 号)。"""
    year = int(month[:4])
    month_number = int(month[5:7])
    if month_number == 12:
        return f"{month}-01", f"{year + 1:04d}-01-01"
    return f"{month}-01", f"{year:04d}-{month_number + 1:02d}-01"


def cents_to_yuan_text(cents: int) -> str:
    """整数分 → 元，保留 2 位小数；全程整数运算，不经过 float。"""
    sign = "-" if cents < 0 else ""
    value = abs(cents)
    return f"{sign}{value // 100:,}.{value % 100:02d} 元"


def cents_to_wan_text(cents: int) -> str:
    """整数分 → 万元，保留 2 位小数（四舍五入用 +5000 再整除实现）。"""
    sign = "-" if cents < 0 else ""
    value = abs(cents)
    hundredths = (value + 5_000) // 10_000
    return f"{sign}{hundredths // 100:,}.{hundredths % 100:02d} 万元"


def _independent_numbers(
    conn: sqlite3.Connection, month: str
) -> tuple[int, int, int, int]:
    """手写 SQL 独立算 (毛额, 退款额, 净额, 订单数)，单位分。"""
    start, end = _month_bounds(month)
    gross_row = conn.execute(GROSS_SQL, (start, end)).fetchone()
    refund_row = conn.execute(REFUND_SQL, (start, end)).fetchone()
    gross = int(gross_row["gross_cents"])
    refund = int(refund_row["refund_cents"])
    return gross, refund, gross - refund, int(gross_row["order_count"])


def _show_independent(conn: sqlite3.Connection, months: list[str]) -> None:
    """[1] 手写 SQL 的独立计算结果。"""
    print("[1] 手写 SQL 独立计算（不 import queries.py）：")
    for month in months:
        gross, refund, net, orders = _independent_numbers(conn, month)
        print(
            f"    {month}: 毛额 {cents_to_yuan_text(gross)}"
            f" / 退款 {cents_to_yuan_text(refund)}"
            f" / 净额 {cents_to_yuan_text(net)}（订单 {orders} 笔）"
        )


def _cross_check(
    conn: sqlite3.Connection, months: list[str]
) -> list[str]:
    """[2] 独立结果 vs 查询层；返回不一致的月份。"""
    from ops_assistant.data.queries import get_month_sales

    print("[2] 与查询层逐项比对：")
    mismatched: list[str] = []
    for month in months:
        gross, refund, net, orders = _independent_numbers(conn, month)
        sales = get_month_sales(conn, month)
        pairs = (
            ("gross_cents", gross, sales.gross_cents),
            ("refund_cents", refund, sales.refund_cents),
            ("net_cents", net, sales.net_cents),
            ("order_count", orders, sales.order_count),
        )
        bad = [(name, a, b) for name, a, b in pairs if a != b]
        if bad:
            mismatched.append(month)
            for name, mine, theirs in bad:
                print(f"    {month} {name}: 独立 {mine} ≠ 查询层 {theirs}")
        else:
            print(f"    {month} 四项全部一致 ✔")
    return mismatched


def _show_cross_month_refunds(
    conn: sqlite3.Connection, order_month: str, refund_month: str
) -> None:
    """[3] 订单在某月、退款在另一个月的记录。"""
    rows = conn.execute(CROSS_MONTH_SQL, (order_month, refund_month)).fetchall()
    print(f"[3] 订单 {order_month} / 退款 {refund_month} 的跨月退款 {len(rows)} 笔：")
    for row in rows:
        print(
            f"    {row['refund_id']:<16} {row['status']:<8}"
            f" 订单日 {row['order_date']}  退款日 {row['refund_date']}"
            f"  {cents_to_yuan_text(int(row['amount_cents']))}"
        )
    print("    注意：这些金额计入退款月，不改动订单月。")


def _show_comparison(

) -> None:
    """[4] 差额、变化率、地区分解与合计校验。"""
    from ops_assistant.domain.metrics import compare_months

    result = compare_months(conn, current, previous)

    print(f"[4] compare_months(current={current!r}, previous={previous!r}, metric='net_sales')")
    print(f"    本期净额 {cents_to_yuan_text(result.current.net_cents)}"
          f" / 上期净额 {cents_to_yuan_text(result.previous.net_cents)}")
    print(f"    差额 {cents_to_yuan_text(result.delta_net_cents)}")
    if result.base_zero:
        print("    变化率：无定义（基期为 0）；base_zero=True")
    else:
        print(f"    变化率：{result.pct_change:.2%}；base_zero=False")
    print(f"    本期订单 {result.current.order_count} 笔"
          f" / 上期订单 {result.previous.order_count} 笔")

    print("    地区差额（按 |差额| 降序）：")
    for item in result.regions:
        share = "—" if item.share_of_delta is None else f"{item.share_of_delta:.1%}"
        print(
            f"      {item.region_id:<8} {item.region_name:<3}"
            f" 本期 {cents_to_yuan_text(item.current_net_cents):>16}"
            f"  上期 {cents_to_yuan_text(item.previous_net_cents):>16}"
            f"  差额 {cents_to_yuan_text(item.delta_cents):>16}  贡献 {share}"
        )

    ok = result.region_delta_sum_cents == result.delta_net_cents
    print(
        f"    合计校验：Σ地区差额 {cents_to_yuan_text(result.region_delta_sum_cents)}"
        f" = 总差额 {cents_to_yuan_text(result.delta_net_cents)} → {ok}"
    )
    print(f"    维度 {result.dimension!r} / 指标 {result.metric!r}"
          f" / 不支持的维度 {result.unsupported_dimension!r}")
    print("    边界说明（notes）：")
    for note in result.notes:
        print(f"      - {note}")
    if not ok:
        raise SystemExit("合计校验失败：地区差额之和与总差额不一致。")


def _show_units() -> None:
    """[5] 整数分换算与浮点陷阱。"""
    print("[5] 单位换算（整数分）与浮点陷阱：")
    for cents in (1234567, 128000, -123456, 0):
        print(f"    {cents:>10} 分 → {cents_to_yuan_text(cents):>14}"
              f" → {cents_to_wan_text(cents):>12}")
    print(f"    知识库例子：1234567 分 → {cents_to_yuan_text(1234567)}"
          f" → {cents_to_wan_text(1234567)}")
    print("    浮点（预期，未在本环境执行）：")
```

### 5.8 三个“钱”工具函数（供报告层复用）

报告层要把整数分变成人能读的字符串。参考实现（本单元实验脚本里就有完整版）：

```python
def cents_to_yuan_text(cents: int) -> str:
    sign = "-" if cents < 0 else ""
    value = abs(cents)
    return f"{sign}{value // 100:,}.{value % 100:02d} 元"


def cents_to_wan_text(cents: int) -> str:
    sign = "-" if cents < 0 else ""
    value = abs(cents)
    hundredths = (value + 5_000) // 10_000
    return f"{sign}{hundredths // 100:,}.{hundredths % 100:02d} 万元"
```

三处要点：

1. **先取绝对值再格式化，负号单独加**。否则 `-123 // 100 == -2`、`-123 % 100 == 77`，会打出 `-2.77` 这种鬼东西。
2. **四舍五入用 `+5000` 再整除**，不经过 `float`，也就不受 `round()` 偶数舍入的影响。
3. **单位必须出现在结果里**（`元` / `万元`）。报告里“12,345.67”这种不带单位的数字是不可复核的。

## 10. 复盘问题与参考答案、下一步

### Q1：为什么退款要按 `refund_date` 而不是 `order_date` 归属？

**参考**：报表按“发生期”记账。退款是退款当月发生的事件，把它塞回订单月会**改动已经结账的历史数据**，而且只要后续再退，旧月份的数字会继续变，报表永远不稳定。按 `refund_date` 归属的代价是“同一张订单影响两个月”，所以回答用户时必须显式说明这一点。本项目把这个规则写进了 `data/knowledge/02_退款与归属.md`，并在 `queries.py` 的 SQL 常量里落实。

### Q2：上期净额为 0，变化率应该返回什么？

**参考**：返回 `None`，同时 `base_zero=True`，报告写“基期为 0，变化率无定义”。不能写 ∞，不能写 100%，也不能写成 0%——那三种写法都在暗示一个**不存在的比例关系**。还要注意区分零基数的两种来源：上期无记录（`has_orders=False`）与上期真零（有订单但净额 0），两者措辞不同。

### Q3：地区差额之和为什么必须等于总差额？怎么保证？

**参考**：差额分解是“同一个总额换个角度看”，不相等就说明**分解漏了或多算了**，读者会据此做错误归因。保证手段有三层：① `get_region_breakdown` 恒返回全部地区（含无记录的）；② `metrics.py` 补上“只在上月出现”的地区；③ 结果里带 `region_delta_sum_cents`，报告层必须打印合计校验行；代码里还有一条内部校验 note（`region_sum != delta`）。另外，按地区过滤时必须用 `_recompute_month` 重算整月合计，否则校验必然失败。

### Q4：为什么净额不进 SQL，而在 Python 里算？

**参考**：净额是**口径定义**（毛 − 退），不是数据里存的属性。定义只放在一处（`queries.py` 的构造 + `metrics.py` 的 `_metric_value`），改口径只需要改一处；而且放在 Python 里可以被纯单元测试覆盖（构造两个 `MonthSales` 就能测），不必开数据库。代价是每次要传结构体，且“净额”这个字段与它的两个来源存在**冗余**——但这份冗余是刻意的：`net_cents` 必须永远等于 `gross_cents - refund_cents`，这条恒等式本身就是自检点。

### Q5：`RegionDelta` 的 `share_of_delta` 什么时候为 `None`？

**参考**：当总差额 `delta == 0` 时为 `None`（分母为 0，占比无定义）。注意三点：① 分母是**总差额**，不是各地区自己的上期值；② 占比可以为负（该地区在下降而总体在上升），也可以超过 100%（该地区涨幅超过总体，其他地区在拖后腿）；③ `None` 在报告里要写成 `—` 或“无定义”，不能写成 `0%`——`0%` 表示“没有贡献”，含义完全不同。
