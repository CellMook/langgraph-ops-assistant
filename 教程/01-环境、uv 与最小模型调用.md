## 3. 通俗解释与精确技术定义

### 3.1 四个文件，各管一件事

| 文件/目录 | 通俗理解 | 精确含义 | 进 Git 吗 |
| --- | --- | --- | --- |
| `pyproject.toml` | 项目“身份证 + 购物清单” | 项目元数据与依赖声明（含版本范围） | **进** |
| `uv.lock` | 购物小票（精确到哪一批货） | 依赖解析的精确结果（可复现安装） | **进** |
| `.venv/` | 项目专用工具箱 | 虚拟环境（virtual environment），装着解析后的包 | **不进**（`.gitignore`） |
| `.env` | 家里的钥匙串 | 本地环境变量（environment variables），含密钥 | **不进**（只提交 `.env.example`） |

> **项目设计选择（2026-10-20 修订）**：仓库提供真实生成的跨平台 `uv.lock`，应提交版本控制。复现时执行 `uv sync --locked`；需要升级依赖时才主动更新锁文件。参见 [uv 官方锁文件说明](https://docs.astral.sh/uv/concepts/projects/layout/#the-lockfile)。

### 3.2 术语（首次出现双语）

- **虚拟环境（virtual environment）**：一个独立目录，装着这个项目专用的 Python 包，互不污染。
- **依赖解析（dependency resolution）**：把“我要 langchain 1.4.x”翻译成“具体要装哪些包（直接依赖 + 传递依赖）、每个是什么版本”的过程。
- **锁文件（lock file）**：解析结果固化下来的文件，保证下次装出一样的组合。
- **端点（endpoint / base URL）**：服务地址。OpenAI 兼容服务都提供 `/chat/completions` 这类路径。
- **温度（temperature）**：采样随机性参数。本教程统一 `0`，追求可复现的“最可能输出”；它**不能**保证两次输出完全一致。
- **词元（token）**：模型计费和上下文长度的单位，约等于“半个到一个词/字”。中文一个字通常 1～2 个 token（**教学简化**，具体看分词器）。
- **超时（timeout）**：单次请求最多等多久；不设会让程序“卡死”而不是报错。
- **降级（degradation）**：某个可选能力不可用时，程序用更弱但确定的方式继续工作。

### 3.3 为什么本项目“没密钥也能跑”

真实问答需要模型，但**算数字不需要模型**。本项目把职责分成两类：

- **模型负责**：可选的知识原文摘录和非数值措辞增强；独立 Agent 路线可以选择工具。主工作流的意图解析由规则完成。
- **程序负责**：解析时间、查库、算差额、做校验、生成表格、导出文件（必须确定）。

这个设计带来两个好处：没密钥也能演示与测试；有密钥时模型出错也不会污染数字。

> **项目设计选择**：`config.py` 里 `llm_enabled = bool(model) and bool(api_key)`。缺任一条件 → `llm_enabled=False`，日志打 WARNING，**程序继续运行**（纯规则模式）。代价是纯规则模式对“奇怪的问法”更笨，只能澄清而不能灵活理解。

### 3.4 一次调用的完整链条

```
你的 Python 代码
   │  1. 读 .env → 得到 model / base_url / api_key
   ▼
ChatOpenAI 客户端（LangChain 的模型封装）
   │  2. 把消息列表序列化成 HTTP JSON
   ▼
供应商服务（OpenAI / DeepSeek / 本地 Ollama…）
   │  3. 返回 JSON
   ▼
AIMessage（content + tool_calls + usage_metadata）
```

**关键点**：LangChain 不“替你思考”，它只是把 HTTP 请求、重试、结构化解析、工具调用协议这些重复劳动封装起来。所以出错时要能分清是**网络/密钥/端点**问题，还是**代码**问题。

#### 步骤 1：地基——路径与密钥掩码

**这一步解决什么**：所有检查都要用两个东西——**从任何目录启动都不会找错的仓库定位**，以及**能安全贴到聊天窗口的密钥掩码**。再顺手写一个不依赖 python-dotenv 的 `.env` 解析器（自检脚本自己不能依赖"被检查的东西"）。

新建 `教程/我的实验/01_diagnose.py`（参考实现在 `教程/实验/01_diagnose.py`，写完本单元再对照）：

```python
"""环境自检脚本（步骤 1）：路径与密钥掩码。"""

from __future__ import annotations

import shutil
import sqlite3
import sys
from importlib.metadata import PackageNotFoundError, version as dist_version
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parents[2]
PROJECT_ROOT = REPO_ROOT / "ops-assistant"


def mask_secret(value: str | None) -> str:
    """把密钥变成可安全贴到聊天窗口的掩码。"""
    if not value:
        return "未设置"
    if len(value) <= 8:
        return "已设置（长度过短，可能是占位符）"
    return f"已设置（{value[:4]}…{value[-2:]}，长度 {len(value)}）"


def read_env_file(path: Path) -> dict[str, str]:
    """不依赖第三方库解析 .env：按 KEY=VALUE 逐行读取，忽略注释与空行。"""
    values: dict[str, str] = {}
    if not path.is_file():
        return values
    for raw_line in path.read_text(encoding="utf-8").splitlines():
        line = raw_line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        key, _, value = line.partition("=")
        values[key.strip()] = value.strip().strip('"').strip("'")
    return values
```

**逐行讲解**：

- `Path(__file__).resolve().parents[2]`：脚本在 `仓库/教程/实验/`（你的副本在 `教程/我的实验/`，层级相同）下，往上两级是仓库根——**从哪个目录启动都成立**，不依赖当前工作目录。
- `mask_secret` 的三档：未设置 / 过短（多半是没改的占位符，**提前替你发现**）/ 正常（前 4 后 2 + 长度，足够辨认、不足以泄露）。
- `read_env_file` 手写解析：`partition("=") 只切第一个等号`（值里可以带等号）、`strip('"')`/`strip("'")` 去引号——行为对齐 python-dotenv，但不引入依赖。
- 头部的 import 一次备齐（后 5 步都会用到）；sqlite3、importlib.metadata 都是标准库。

#### 步骤 2：最便宜的两项——Python 版本与 uv

**这一步解决什么**：定下**检查函数的统一契约** `(bool, str)`——通过与否 + 一句人话。后面四项全部沿用这个形状，`main()` 才能统一汇总。

```python
def check_python() -> tuple[bool, str]:
    major, minor = sys.version_info[:2]
    ok = (major, minor) >= (3, 11)
    return ok, f"Python {major}.{minor}.{sys.version_info[2]}（要求 >= 3.11）"


def check_uv() -> tuple[bool, str]:
    found = shutil.which("uv")
    if found is None:
        return False, "PATH 中找不到 uv（见本单元 5.1 安装步骤）"
    return True, f"找到 uv：{found}"
```

**逐行讲解**：

- `(major, minor) >= (3, 11)`：**元组比较**天然按字典序逐位比——比手写 `major > 3 or (major == 3 and minor >= 11)` 干净得多。
- `shutil.which("uv")`：标准库的"PATH 探测"，找到返回完整路径、找不到返回 `None`——不真的执行 uv，纯只读。
- 失败消息里带**去处**（"见本单元 5.1"）：报错要给出下一步，这是贯穿全书的习惯。

**运行与观察**（临时验证）：

```python
    print(check_uv())
```

#### 步骤 3：项目骨架——文件在不在

**这一步解决什么**：教程后面所有单元都假设项目骨架存在。检查方式很朴素：**一份关键文件清单，逐个 `is_file()`**。

```python
def check_skeleton() -> tuple[bool, str]:
    required = [
        PROJECT_ROOT / "pyproject.toml",
        PROJECT_ROOT / "src" / "ops_assistant" / "config.py",
        PROJECT_ROOT / "src" / "ops_assistant" / "workflow" / "state.py",
    ]
    missing = [str(p.relative_to(REPO_ROOT)) for p in required if not p.is_file()]
    if missing:
        return False, "缺少项目文件：" + "、".join(missing)
    return True, "项目骨架文件齐全"
```

**逐行讲解**：

- 只列**三个**文件而不是全量比对：pyproject（工程入口）、config（配置层）、workflow/state（第一个图的状态）——缺任何一个，后面的单元都会在中途撞墙；其余文件缺了只影响单个单元。
- `relative_to(REPO_ROOT)`：报路径时显示**相对仓库根**的短路径，错误消息可读。

**运行与观察**（临时验证）：`print(check_skeleton())` → `(True, '项目骨架文件齐全')`；把其中一个文件改名再跑，会得到 `(False, '缺少项目文件：ops-assistant/pyproject.toml')`（记得改回来）。

#### 步骤 4：`.env` 与数据库——含"读得到但读不了"的防呆

**这一步解决什么**：`.env` 检查要**复用**步骤 1 的解析器并只打掩码；数据库检查要用 **SQLite 的只读 URI 模式**——体检脚本绝不能把用户数据库改坏。

```python
def check_env_file() -> tuple[bool, str]:
    env_path = PROJECT_ROOT / ".env"
    example_path = PROJECT_ROOT / ".env.example"
    if not env_path.is_file():
        hint = "先复制 .env.example 为 .env" if example_path.is_file() else "项目里也没有 .env.example"
        return False, f"未找到 {env_path.name}；{hint}"
    values = read_env_file(env_path)
    model = values.get("OPS_MODEL", "")
    key = values.get("OPS_API_KEY", "")
    summary = f"OPS_MODEL={model or '空'}；OPS_API_KEY={mask_secret(key)}"
    return True, summary


def check_database() -> tuple[bool, str]:
    db_path = PROJECT_ROOT / "data" / "ops.db"
    if not db_path.is_file():
        return False, "尚未生成 data/ops.db（运行 scripts/bootstrap.py 之后才会出现）"
    try:
        conn = sqlite3.connect(f"file:{db_path.as_posix()}?mode=ro", uri=True)
        try:
            count = conn.execute("SELECT COUNT(*) FROM orders").fetchone()[0]
            months = conn.execute("SELECT COUNT(DISTINCT substr(order_date, 1, 7)) FROM orders").fetchone()[0]
        finally:
            conn.close()
    except sqlite3.Error as exc:
        return False, f"数据库存在但读取失败：{exc}"
    return True, f"订单 {count} 笔，覆盖 {months} 个月"
```

**逐行讲解**：

- `.env` **存在**就算通过（返回 `True`）：它是"环境项"不是"关键项"——没配密钥也该能开始学习（§5.4 的无密钥路径），所以这里只**报告**内容，不拦人。
- `sqlite3.connect("file:...?mode=ro", uri=True)`：URI 模式 + `mode=ro`，**打开即只读**——文件损坏/被锁时连接或查询抛 `sqlite3.Error`，被 except 接住变成一行可读消息，而不是整个脚本崩溃。
- 内层 `try/finally conn.close()`：查询失败也要关连接；两层各管各的资源纪律。
- `substr(order_date, 1, 7)` 取 `YYYY-MM`：一个 SQL 顺手的月度覆盖统计。

**运行与观察**（临时验证）：

```python
    print(check_database())
```

#### 步骤 5：依赖导入——用 importlib.metadata，不信 `__version__`

**这一步解决什么**：确认核心包能导入、并**可靠地**报版本。这里埋着本单元的一个重要教训（见 §5.6 同款问题）：各包版本属性习惯不一，**唯一可靠的取法是标准库 `importlib.metadata` 按发行版名查**。

```python
def check_imports() -> tuple[bool, str]:
    problems: list[str] = []
    for module_name in ("langchain", "langchain_core", "langgraph"):
        try:
            __import__(module_name)
        except ImportError:
            problems.append(module_name)
            continue
        # 各包版本属性习惯不一（langchain 有 __version__、pydantic 用 VERSION、
        # langgraph 两者都没有），用标准库 importlib.metadata 按发行版名取版本才可靠。
        try:
            ver = dist_version(module_name.replace("_", "-"))
        except PackageNotFoundError:
            ver = "未知版本"
        print(f"    - {module_name} {ver}")
    if problems:
        return False, "无法导入：" + "、".join(problems) + "（先执行 uv sync）"
    return True, "核心依赖可导入"
```

**逐行讲解**：

- 导入失败不抛给用户：收集进 `problems`，最后**一次性**列出并给修复命令（"先执行 uv sync"）——六项检查要每项都有结论，而不是第一项失败就中断。
- `dist_version(module_name.replace("_", "-"))`：**发行版名带连字符**（`langchain-core`），模块名带下划线（`langchain_core`）——两个命名空间不同，必须转换。
- 版本打印直接落在循环里（缩进四格）：它是"过程信息"；返回值才是"结论"——过程与结论分层。

**运行与观察**（临时验证）：在 `uv sync` 完成后运行 `print(check_imports())`：

#### 步骤 6：整合——`main()` 汇总与关键项分流

**这一步解决什么**：把六个检查函数装进一张表，打印汇总，并区分**关键项**（决定退出码）与**环境项**（只提示）——这是"能开始学习"和"配置完整"两条线的分离。

```python
def main() -> int:
    print("== 环境自检（只读检查，不联网）==")
    print(f"仓库根目录：{REPO_ROOT}")
    print(f"项目目录：{PROJECT_ROOT}")

    checks: list[tuple[str, bool, str]] = []
    checks.append(("Python 版本", *check_python()))
    checks.append(("uv 工具", *check_uv()))
    checks.append(("项目骨架", *check_skeleton()))
    checks.append((".env 配置", *check_env_file()))
    checks.append(("数据库", *check_database()))
    checks.append(("依赖导入", *check_imports()))

    print("\n== 检查结果 ==")
    for name, ok, detail in checks:
        flag = "通过" if ok else "未通过"
        print(f"[{flag}] {name}：{detail}")

    key_checks = [item for item in checks if item[0] in {"Python 版本", "项目骨架"}]
    failed_key = [name for name, ok, _ in key_checks if not ok]
    if failed_key:
        print(f"\n结论：关键项未通过（{'、'.join(failed_key)}），先补环境再开始单元 01。")
        return 1

    return 0
```

**逐行讲解**：

- `checks.append(("Python 版本", *check_python()))`：函数返回 `(bool, str)`，星号解包成三元组 `(名字, 通过?, 详情)`——**契约统一，汇总就是一行一项**。
- 关键项只有 Python 版本和项目骨架：它们缺失时**任何单元都跑不了**；`.env`、数据库、依赖缺失只影响部分路径——退出码语义与 §5.4 的无密钥路径对齐。
- 返回 `1`/`0` 而不是抛异常：退出码给**脚本/CI**消费，打印给人看。

### 5.6 实验 A：第一条模型调用（一步步搭出来）

最终脚本有 150 多行，但**不是**让你一次敲完——我们分 **6 步**搭出来：每步只解决一个问题、只有一小段新代码、都能立刻运行看到变化；最后一步整合成完整脚本（与仓库 `教程/实验/01_hello_model.py` 完全一致）。手敲纪律不变，只是从“敲一堵墙”变成“砌六层砖”。每步跑完，按学习契约记下四样东西（命令、预期、实际、卡点）。

建一个空文件 `教程/我的实验/01_hello_model.py`（参考实现在 `教程/实验/01_hello_model.py`），我们从第 1 步开始往里加东西。

#### 步骤 1：找到并读取 `.env`（先确认钥匙在哪，不联网）

**这一步解决什么**：调用模型需要三样东西——模型名、密钥、端点地址——都放在 `.env` 里。先把“能不能读到、读到了什么”变成看得见的输出，再谈调用。没有密钥也应该能跑这一步。

把下面这些敲进 `01_hello_model.py`（这是**临时版**：`main` 只负责打印，第 5 步会替换它）：

```python
"""单元 01 实验 A（步骤 1）：读取 .env 并掩码打印。"""

from __future__ import annotations

import os
from pathlib import Path

from dotenv import load_dotenv

REPO_ROOT = Path(__file__).resolve().parents[2]
ENV_PATH = REPO_ROOT / "ops-assistant" / ".env"


def mask(secret: str | None) -> str:
    """只暴露密钥首 4 位与末 2 位，避免误贴到聊天窗口。"""
    if not secret:
        return "未设置"
    if len(secret) <= 8:
        return "已设置（长度过短）"
    return f"{secret[:4]}…{secret[-2:]}"


def main() -> None:
    if ENV_PATH.is_file():
        load_dotenv(dotenv_path=ENV_PATH, override=False)
    else:
        print(f"[提示] 未找到 {ENV_PATH}，将只用系统环境变量（多半是空 → 规则模式）")
    for key in ("OPS_MODEL", "OPS_MODEL_PROVIDER", "OPS_API_KEY", "OPS_BASE_URL"):
        value = os.getenv(key)
        shown = mask(value) if key == "OPS_API_KEY" else (value or "未设置")
        print(f"{key} = {shown}")


if __name__ == "__main__":
    main()
```

**逐行讲解**（只讲新东西）：

#### 步骤 2：拆开 `provider:model`（纯字符串处理，纸面可验证）

**这一步解决什么**：`OPS_MODEL` 写的是 `deepseek:deepseek-chat`——冒号前是“用哪家供应商”，冒号后才是模型名；`ChatOpenAI` 只认后者。拆分是纯逻辑，先写成一个**不联网的小函数**，拿三组输入验证它。

在 `mask()` 下面加这个函数：

```python
def split_model(raw: str, provider_hint: str) -> tuple[str, str]:
    """按第一个冒号拆分 "provider:model"；没有前缀时用 provider_hint。"""
    cleaned = raw.strip()
    if ":" in cleaned:
        provider, _, model_name = cleaned.partition(":")
        return provider.strip(), model_name.strip()
    return provider_hint.strip(), cleaned
```

再在 `main()` 的打印循环**后面**临时加几行自测：

```python
    print("-- split_model 自测 --")
    for raw, hint in [("deepseek:deepseek-chat", ""), ("gpt-4o-mini", "openai"), ("", "deepseek")]:
        print(f"{raw!r:30} + hint={hint!r:12} -> {split_model(raw, hint)}")
```

**逐行讲解**：

- `str.partition(":")` 返回三段 `(前, 冒号, 后)`，**冒号不存在时返回 `("整个串", "", "")`**——不抛错、不越界，比 `split` 更适合这种“可能没有分隔符”的场景。
- `provider_hint` 的用途：`OPS_MODEL` 不带前缀时（如 `gpt-4o-mini`），供应商回退到 `.env` 里的 `OPS_MODEL_PROVIDER`。
- 为什么拆成一个独立函数而不是塞进主流程：**纯函数好测**——输入输出一目了然，第 3 步和主项目里还要复用它。

**运行与观察**：

```text
-- split_model 自测 --

'gpt-4o-mini'                  + hint='openai'     -> ('openai', 'gpt-4o-mini')
''                             + hint='deepseek'   -> ('deepseek', '')
```

第三组提醒你：空串拆不出模型名——这正是第 3 步要判定的状态之一。自测通过后，那三行临时自测可以删掉（也可以留着，第 6 步整合时会对照删）。

#### 步骤 3：把“能不能调模型”变成一个函数的返回值

**这一步解决什么**：配置有四种典型状态——没写模型名 / 写了模型名但没密钥 / 第三方供应商但没 `base_url` / 齐全。把判定集中到一个函数里，返回“**决定 + 理由**”，`main` 只管照办。这是本项目“**降级而不是崩溃**”设计观的第一次落地。

- `(os.getenv("OPS_API_KEY") or "").strip()` 这串是在防三种脏值：`None`、空串、带空格——真实 `.env` 里三种都常见。

- `provider in {"", "openai"}` 且无 `base_url`：OpenAI 官方端点有默认地址，不需要 `base_url`；**其它供应商（deepseek、本地 ollama 等）必须给**。
- 判定顺序有讲究：先“有没有模型名”再“有没有密钥”再“要不要端点”——从最便宜的检查到最贵的检查。

#### 步骤 4：规则模式——没有密钥也把流程走完

#### 步骤 5：接上真模型（需要密钥；没有就先跳过，第 6 步见）

**这一步解决什么**：一切就绪后，真正的调用只做三件事——构造客户端、组装两条消息、`invoke` 并处理失败。

- `from langchain... import ...` 写在**函数内部**而不是文件顶部：没密钥的用户根本走不到这里，也就不需要装好 langchain 才能跑规则分支——`01_diagnose.py` 的“依赖检查失败但脚本仍可用”同理。

### 5.7 实验 B：模型能力探测（一步步搭出来）

为什么要探测：不同供应商/模型对“工具调用（tool calling）”和“结构化输出（structured output）”的支持程度不同；同一个模型名在不同端点背后也可能是不同版本。**不要假设**。我们分 6 步搭出探测脚本，最终形态与仓库 `教程/实验/01_probe_model.py` 完全一致。建一个空文件开始。

#### 步骤 1：探测框架——把“一次调用”变成“支持/不支持 + 证据”

**这一步解决什么**：三项探测（文本、工具、结构化）都要做同样四件事：执行、计时、抓异常、格式化结果。先写一个公共包装器，后面三项探测就只需要关心“怎么调用”。

新建 `教程/我的实验/01_probe_model.py`（参考实现在 `教程/实验/01_probe_model.py`，写完本单元再对照），敲入：

```python
"""单元 01 实验 B（步骤 1）：探测包装器。"""

from __future__ import annotations

import time


def probe(name: str, fn) -> tuple[bool, str]:
    started = time.perf_counter()
    try:
        detail = fn()
        elapsed_ms = int((time.perf_counter() - started) * 1000)
        return True, f"{detail}（耗时 {elapsed_ms} ms，数值随网络波动）"
    except Exception as exc:
        elapsed_ms = int((time.perf_counter() - started) * 1000)
        return False, f"{type(exc).__name__}: {exc}（耗时 {elapsed_ms} ms）"


if __name__ == "__main__":
    print(probe("立即成功", lambda: "ok"))
    print(probe("必然失败", lambda: (_ for _ in ()).throw(ValueError("测试异常"))))
```

**逐行讲解**：

- `probe(name, fn)` 收一个**函数**而不是结果——调用时机必须由 probe 控制，才能把计时和异常都罩住。
- `time.perf_counter()` 是单调高性能计时器，专用于测耗时（`time.time()` 会被系统对时干扰）。
- `except Exception` 在这里**不是**坏味道：探测的目的就是“把失败变成数据”。这跟实验 A 里“打印异常而不是吞掉”是同一条纪律——异常信息完整保留在返回值里。
- 成功与失败返回同样的 `(bool, str)` 形状，调用方打印时不用分支。

**运行与观察**（`uv run python ../教程/我的实验/01_probe_model.py`，在 `ops-assistant/` 下）：


**这一步解决什么**：最基本的能力是文本生成。配置读取用实验 A 同款技巧的**简化版**——探测脚本只需要“有没有配置”，不需要规则模式分支（没配置就整体跳过）。

加上配置函数（文件头部补 `import os`、`import sys`、`from pathlib import Path`、`from dotenv import load_dotenv`，以及 `REPO_ROOT`/`ENV_PATH` 两个常量——照抄实验 A）：

```python
def main() -> int:

    if config is None:
        print("[跳过] 未配置 OPS_MODEL / OPS_API_KEY，本脚本不联网。")

    from langchain_core.messages import HumanMessage
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model=config["model_name"],
        api_key=config["api_key"],
        base_url=config["base_url"],
        temperature=0.0,
        timeout=60.0,
        max_retries=0,
    )
    print(f"[配置] {config['provider']}:{config['model_name']} @ {config['base_url'] or 'OpenAI 默认'}")

    def probe_text() -> str:
        answer = model.invoke([HumanMessage(content="只回复两个字：收到。")])
        text = (answer.content or "").strip()
        if not text:
            raise ValueError("返回内容为空")
        return f"content={text[:30]!r}"

    ok, detail = probe("文本生成", probe_text)
    print(f"[{'支持' if ok else '不支持/失败'}] 文本生成：{detail}")
    return 0 if ok else 1
```

**逐行讲解**：

- `load_config` 返回 `dict | None`：`None` 表示“没得探测”，直接跳过返回 0——**没有密钥不是错误**。对比实验 A 的 `build_model_config` 返回“决定 + 理由”：那边规则模式是主角，这边跳过即可，工具按需而设。
- `probe_text` 里空内容也要 `raise ValueError`：模型“回了话但内容为空”和“回不了话”同样不可用，探测要把两者都判为不支持。
- `text[:30]!r`：只展示前 30 字符的原始表示——探测输出要短，长篇回复属于 §6.2 实验大输出。

**运行与观察**：无密钥 → `[跳过]` 两行、退出码 0；有密钥 → `[支持] 文本生成：content='收到'（耗时 xxx ms…）`。

#### 步骤 3：探测工具调用——它会不会“申请”

**这一步解决什么**：工具调用是单元 04 以后的地基。判定标准是**模型返回 `tool_calls` 字段了吗**——不是“它说它会”。先给模型一份“工具说明书”。

在 `TOOL_SPEC` 常量（放在 `ENV_PATH` 之后）和探测函数（放在 `probe_text` 之后）：

把 `main()` 末尾的探测调用改成两行：

**逐行讲解**：

- `TOOL_SPEC` 是 JSON Schema：`name` 唯一标识工具，`description` 是**写给模型看的说明书**——写清楚单位与格式，模型填参数才准（单元 04 会正式讲）。
- `bind_tools` 把说明书**递给**模型但不执行任何东西——模型若决定用，会在回复里放 `tool_calls`，这只是“申请”（单元 00 Q2 的区别，第一次亲眼见）。
- `getattr(answer, "tool_calls", None) or []`：有些供应商的响应不带这个字段，防御性读取后统一按“没有”处理。
- 提示词里“不要自己猜”是有意的：不禁止的话，模型可能直接编一个数字而不申请工具，探测就失真了。

**运行与观察**：`[支持] 工具调用：tool_calls[0].name=query_month_sales args={'month': '2026-09'}…`；不支持时你会看到 `ValueError: 模型没有返回 tool_calls…` 被包装成 `[不支持/失败]`——**这就是步骤 1 包装器的价值**。

#### 步骤 4：探测结构化输出——它能不能按 schema 回话

**这一步解决什么**：单元 03 的地基——让模型把自由文本对齐到固定字段。用 pydantic 声明“我要什么”，看模型能不能给。

文件头部补 `from pydantic import BaseModel, Field`，然后加 schema（放在 `TOOL_SPEC` 后）和探测函数（放在 `probe_tool_call` 后）：


**逐行讲解**：

- `Field(description=...)` 不是注释——这些描述会进入给模型的约束，字段含义写得越清楚，抽取越准。
- `with_structured_output(MonthFact)` 的底层实现因供应商而异（有的转成工具调用，有的注入 JSON Schema 指令）——**探测就是帮你确认你的端点走哪条路**。
- `isinstance` 检查看似多余（类型标注说了返回 MonthFact）——但供应商适配层的 bug 会撒谎，探测脚本只信运行时事实。

**运行与观察**：`[支持] 结构化输出：month=2026-09 net=1286500 contains_refund=True…`。

## 10. 复盘问题与参考答案、下一步

### Q1：为什么用 `uv` 而不是 `pip`？

**参考**：`uv` 把“建虚拟环境、解析依赖、装包、锁版本、跑脚本”合成一条命令，且解析速度快、锁文件可复现。对本教程的价值是：**命令少、出错点少**，学习者不需要记 `python -m venv`、`activate`、`pip install -r` 三步。代价是团队必须统一用 `uv`，否则 `uv.lock` 与 `requirements.txt` 会打架。

### Q2：`uv.lock` 为什么重要？为什么不直接提交别人的锁文件？

**参考**：锁文件固定了“依赖树里每个包分别是哪个版本”，保证今天装的和明天装的一样，避免“昨天能跑今天崩”。但锁文件可能包含平台相关标记（Python 版本、系统标记），在别的机器上可能解析失败；本仓库因此要求你自己 `uv lock`。**未验证**：跨平台能否复用取决于具体包；遇到问题以报错为准。

### Q3：模型名写成 `deepseek:deepseek-chat`，谁在解析这个冒号？

**参考**：是**我们自己的代码**在解析（`split_model` 按第一个冒号切分），不是 LangChain 的魔法。项目 `config.py` 也按同样规则处理：有前缀用前缀，否则用 `OPS_MODEL_PROVIDER`。所以 `OPS_MODEL=ollama:qwen2.5:7b` 会得到模型名 `qwen2.5:7b`——这恰好是我们想要的，但必须写清规则，否则维护者会困惑。

### Q4：探测脚本三项都失败，我还要继续学吗？

**参考**：要。单元 06～09 的图、状态、路由、预算、checkpoint 全是确定性代码，可以完全离线完成；单元 10～14 的检索与计算也不依赖模型。模型相关的能力（04、05 的工具循环、11 的语义检索增强）可以后面补。**先拥有确定性的工程能力，再谈模型**，这个顺序比反过来稳。

### Q5：为什么实验 A 里强调“只允许使用用户给出的数字”？

**参考**：这是“防幻觉”的第一道措施——把模型的角色限制为“复述 + 解释”，不让它算。第二道是程序校验（单元 03 用 Pydantic，单元 13 用整数计算）。第三道是人工审批（单元 16）。三层缺一不可；只靠提示词是**教学简化**级别的防护，不是生产级。
