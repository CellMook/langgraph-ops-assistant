## 3. 通俗解释与精确技术定义

### 3.1 四个文件，各管一件事

| 文件/目录 | 通俗理解 | 精确含义 | 进 Git 吗 |
| --- | --- | --- | --- |
| `pyproject.toml` | 项目“身份证 + 购物清单” | 项目元数据与依赖声明（含版本范围） | **进** |
| `uv.lock` | 购物小票（精确到哪一批货） | 依赖解析的精确结果（可复现安装） | **进** |
| `.venv/` | 项目专用工具箱 | 虚拟环境（virtual environment），装着解析后的包 | **不进**（`.gitignore`） |
| `.env` | 家里的钥匙串 | 本地环境变量（environment variables），含密钥 | **不进**（只提交 `.env.example`） |

> **项目设计选择（2026-10-20 修订）**：仓库提供真实生成的跨平台 `uv.lock`，应提交版本控制。复现时执行 `uv sync --locked`；需要升级依赖时才主动更新锁文件。参见 [uv 官方锁文件说明](https://docs.astral.sh/uv/concepts/projects/layout/#the-lockfile)。

### 3.2 术语（首次出现双语）

- **虚拟环境（virtual environment）**：一个独立目录，装着这个项目专用的 Python 包，互不污染。
- **依赖解析（dependency resolution）**：把“我要 langchain 1.4.x”翻译成“具体要装哪些包（直接依赖 + 传递依赖）、每个是什么版本”的过程。
- **锁文件（lock file）**：解析结果固化下来的文件，保证下次装出一样的组合。
- **端点（endpoint / base URL）**：服务地址。OpenAI 兼容服务都提供 `/chat/completions` 这类路径。
- **温度（temperature）**：采样随机性参数。本教程统一 `0`，追求可复现的“最可能输出”；它**不能**保证两次输出完全一致。
- **词元（token）**：模型计费和上下文长度的单位，约等于“半个到一个词/字”。中文一个字通常 1～2 个 token（**教学简化**，具体看分词器）。
- **超时（timeout）**：单次请求最多等多久；不设会让程序“卡死”而不是报错。
- **降级（degradation）**：某个可选能力不可用时，程序用更弱但确定的方式继续工作。

### 3.3 为什么本项目“没密钥也能跑”

真实问答需要模型，但**算数字不需要模型**。本项目把职责分成两类：

- **模型负责**：可选的知识原文摘录和非数值措辞增强；独立 Agent 路线可以选择工具。主工作流的意图解析由规则完成。
- **程序负责**：解析时间、查库、算差额、做校验、生成表格、导出文件（必须确定）。

这个设计带来两个好处：没密钥也能演示与测试；有密钥时模型出错也不会污染数字。

> **项目设计选择**：`config.py` 里 `llm_enabled = bool(model) and bool(api_key)`。缺任一条件 → `llm_enabled=False`，日志打 WARNING，**程序继续运行**（纯规则模式）。代价是纯规则模式对“奇怪的问法”更笨，只能澄清而不能灵活理解。

### 3.4 一次调用的完整链条

```
你的 Python 代码
   │  1. 读 .env → 得到 model / base_url / api_key
   ▼
ChatOpenAI 客户端（LangChain 的模型封装）
   │  2. 把消息列表序列化成 HTTP JSON
   ▼
供应商服务（OpenAI / DeepSeek / 本地 Ollama…）
   │  3. 返回 JSON
   ▼
AIMessage（content + tool_calls + usage_metadata）
```

**关键点**：LangChain 不“替你思考”，它只是把 HTTP 请求、重试、结构化解析、工具调用协议这些重复劳动封装起来。所以出错时要能分清是**网络/密钥/端点**问题，还是**代码**问题。

```dotenv
# A. DeepSeek（OpenAI 兼容）
OPS_MODEL=deepseek:deepseek-chat
OPS_API_KEY=sk-你的密钥

```

```dotenv
# B. OpenAI 官方
OPS_MODEL=openai:gpt-4.1-mini
OPS_API_KEY=sk-你的密钥
OPS_BASE_URL=
```

```dotenv
# C. 本地 Ollama（无需付费，但需要先在本机启动服务并 pull 模型）
```

为什么 C 要把 provider 和模型名拆开写：如果写成 `ollama:qwen2.5:7b`，按“第一个冒号”拆分会得到 provider=`ollama`、模型=`qwen2.5:7b`，其实也能工作；但项目里**按第一个冒号切分**是一条必须说清的约定，否则 `qwen2.5:7b` 这种名字很容易让人以为程序坏了。

> **安全纪律**：`.env` 永远不进 Git；`.env.example` 里只写占位符；日志里只出现掩码（如 `sk-d…9f`）。本项目 `LLMClient` 要求不回显密钥。

### 5.5 实验 A：第一条模型调用（完整代码）

保存路径：`教程/实验/01_hello_model.py`

```python
"""单元 01 实验 A：读 .env → 发一条消息 → 打印回复。

用法（在 ops-assistant 目录执行）：uv run python ../教程/实验/01_hello_model.py
无密钥时自动走“规则降级”分支，不联网、不报错。
"""

from __future__ import annotations

import os
import sys
from pathlib import Path

from dotenv import load_dotenv

REPO_ROOT = Path(__file__).resolve().parents[2]
ENV_PATH = REPO_ROOT / "ops-assistant" / ".env"
TIMEOUT_S = 60.0  # 单次请求超时（秒）；第 8 节实验 8.5 会让你把它改小


def mask(secret: str | None) -> str:
    """只暴露密钥首 4 位与末 2 位，避免误贴到聊天窗口。"""
    if not secret:
        return "未设置"
    if len(secret) <= 8:
        return "已设置（长度过短）"
    return f"{secret[:4]}…{secret[-2:]}"


def split_model(raw: str, provider_hint: str) -> tuple[str, str]:
    """按第一个冒号拆分 "provider:model"；没有前缀时用 provider_hint。"""
    cleaned = raw.strip()
    if ":" in cleaned:
        provider, _, model_name = cleaned.partition(":")
        return provider.strip(), model_name.strip()
    return provider_hint.strip(), cleaned


def build_model_config() -> dict[str, object]:
    """读取并校验配置；返回给 ChatOpenAI 用的参数字典。"""
    if ENV_PATH.is_file():
        load_dotenv(dotenv_path=ENV_PATH, override=False)
    else:
        print(f"[提示] 未找到 {ENV_PATH}，将只用系统环境变量（多半是空 → 规则模式）")

    raw_model = (os.getenv("OPS_MODEL") or "").strip()
    provider_hint = (os.getenv("OPS_MODEL_PROVIDER") or "").strip()
    api_key = (os.getenv("OPS_API_KEY") or "").strip() or os.getenv("OPENAI_API_KEY")
    base_url = (os.getenv("OPS_BASE_URL") or "").strip() or None

    provider, model_name = split_model(raw_model, provider_hint)
    if not model_name:
        return {"enabled": False, "reason": "OPS_MODEL 为空", "timeout_s": TIMEOUT_S}
    if not api_key:
        return {
            "enabled": False,
            "reason": "有 OPS_MODEL 但没有 OPS_API_KEY",
            "timeout_s": TIMEOUT_S,
        }
    if provider in {"", "openai"} and base_url is None:
        pass  # 走 OpenAI 官方默认地址
    elif base_url is None:
        return {
            "enabled": False,
            "reason": f"provider={provider} 需要 OPS_BASE_URL（OpenAI 兼容端点）",
            "timeout_s": TIMEOUT_S,
        }
    return {
        "enabled": True,
        "provider": provider or "openai",
        "model_name": model_name,
        "api_key": api_key,
        "base_url": base_url,
        "timeout_s": TIMEOUT_S,
    }


SYSTEM_PROMPT = (
    "你是一名经营数据分析助手。规则："
    "1) 金额单位是“分”，展示时转成元；"
    "2) 只允许使用用户给出的数字，禁止自行计算或编造；"
    "3) 不确定时直接说“不确定”。"
)

HUMAN_PROMPT = (
    "已知：2026-09 净销售额 1286500 分（毛销售额 1400000 分，已批准退款 113500 分）；"
    "2026-08 净销售额 1190000 分。"
    "请用两句中文复述这两组数字，并说明“净销售额”是否已扣除退款。不要做任何计算。"
)


def rule_mode_answer() -> str:
    """无模型时的确定性回答：模板拼接，绝不编数字。"""
    return (
        "【规则模式】2026-09 净销售额 1286500 分（毛销售额 1400000 分，"
        "已批准退款 113500 分）；2026-08 净销售额 1190000 分。"
        "净销售额 = 毛销售额 − 已批准退款，因此已扣除退款。"
    )


def main() -> int:
    print("== 单元 01 实验 A：第一条模型调用 ==")
    config = build_model_config()

    if not config.get("enabled"):
        print(f"[规则模式] 未启用模型：{config.get('reason')}")
        print(f"[规则模式] 系统提示词长度：{len(SYSTEM_PROMPT)} 字")
        print(f"[规则模式] 用户提示词长度：{len(HUMAN_PROMPT)} 字")
        print("\n----- 回答（预期，未在本环境执行）-----")
        print(rule_mode_answer())
        print("----- 结束 -----")
        print("\n提示：配置 OPS_MODEL / OPS_API_KEY / OPS_BASE_URL 后重跑，可看到真实模型回复。")
        return 0

    print(f"[配置] provider = {config['provider']}")
    print(f"[配置] model    = {config['model_name']}")
    print(f"[配置] base_url = {config['base_url'] or '（OpenAI 默认）'}")
    print(f"[配置] api_key  = {mask(config['api_key'])}")
    print(f"[配置] timeout  = {config['timeout_s']} 秒")

    from langchain_core.messages import HumanMessage, SystemMessage
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model=config["model_name"],
        api_key=config["api_key"],
        base_url=config["base_url"],
        temperature=0.0,
        timeout=config["timeout_s"],
        max_retries=0,
    )

    messages = [SystemMessage(content=SYSTEM_PROMPT), HumanMessage(content=HUMAN_PROMPT)]
    print(f"\n[请求] 共 {len(messages)} 条消息，角色：{[m.type for m in messages]}")

    try:

    print("\n----- 回答 -----")
    print(answer.content)
    print("----- 结束 -----")

    usage = getattr(answer, "usage_metadata", None)

    else:
```

### 5.6 实验 B：模型能力探测（完整代码）

保存路径：`教程/实验/01_probe_model.py`

为什么要探测：不同供应商/模型对“工具调用（tool calling）”和“结构化输出（structured output）”的支持程度不同；同一个模型名在不同端点背后也可能是不同版本。**不要假设**。

```python
"""单元 01 实验 B：探测当前模型是否支持 文本 / 工具调用 / 结构化输出。

用法（在 ops-assistant 目录执行）：uv run python ../教程/实验/01_probe_model.py
无密钥时打印“跳过”并返回 0；有密钥时逐项探测并打印耗时（耗时随网络波动）。
"""

from __future__ import annotations

import os
import sys
import time
from pathlib import Path

from dotenv import load_dotenv
from pydantic import BaseModel, Field

REPO_ROOT = Path(__file__).resolve().parents[2]
ENV_PATH = REPO_ROOT / "ops-assistant" / ".env"

TOOL_SPEC = {
    "type": "function",
    "function": {
        "name": "query_month_sales",
        "description": "查询某个月的净销售额。月份格式必须是 YYYY-MM，金额单位是分。",
        "parameters": {
            "type": "object",
            "properties": {
                "month": {
                    "type": "string",
                    "description": "月份，格式 YYYY-MM，例如 2026-09",
                }
            },
            "required": ["month"],
        },
    },
}


class MonthFact(BaseModel):
    """结构化输出探测用的最小模式。"""

    month: str = Field(description="月份，格式 YYYY-MM")
    net_sales_cents: int = Field(description="净销售额，单位分，整数")
    contains_refund: bool = Field(description="该净销售额是否已扣除退款")


def load_config() -> dict[str, str | None] | None:
    if ENV_PATH.is_file():
        load_dotenv(dotenv_path=ENV_PATH, override=False)
    raw_model = (os.getenv("OPS_MODEL") or "").strip()
    provider_hint = (os.getenv("OPS_MODEL_PROVIDER") or "").strip()
    api_key = (os.getenv("OPS_API_KEY") or "").strip() or os.getenv("OPENAI_API_KEY")
    base_url = (os.getenv("OPS_BASE_URL") or "").strip() or None
    if not raw_model or not api_key:
        return None
    if ":" in raw_model:
        provider, _, model_name = raw_model.partition(":")
    else:
        provider, model_name = provider_hint or "openai", raw_model
    return {
        "provider": provider.strip(),
        "model_name": model_name.strip(),
        "api_key": api_key,
        "base_url": base_url,
    }


def probe(name: str, fn) -> tuple[bool, str]:
    started = time.perf_counter()
    try:
        detail = fn()
        elapsed_ms = int((time.perf_counter() - started) * 1000)
        return True, f"{detail}（耗时 {elapsed_ms} ms，数值随网络波动）"
    except Exception as exc:
        elapsed_ms = int((time.perf_counter() - started) * 1000)
        return False, f"{type(exc).__name__}: {exc}（耗时 {elapsed_ms} ms）"


def main() -> int:
    print("== 单元 01 实验 B：模型能力探测 ==")
    config = load_config()
    if config is None:
        print("[跳过] 未配置 OPS_MODEL / OPS_API_KEY，本脚本不联网。")
        print("       没有密钥是允许的：后续单元 06～09 完全不需要模型也能学完。")
        return 0

    from langchain_core.messages import HumanMessage
    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(
        model=config["model_name"],
        api_key=config["api_key"],
        base_url=config["base_url"],
        temperature=0.0,
        timeout=60.0,
        max_retries=0,
    )
    print(f"[配置] {config['provider']}:{config['model_name']} @ {config['base_url'] or 'OpenAI 默认'}")

    def probe_text() -> str:
        answer = model.invoke([HumanMessage(content="只回复两个字：收到。")])
        text = (answer.content or "").strip()
        if not text:
            raise ValueError("返回内容为空")
        return f"content={text[:30]!r}"

    def probe_tool_call() -> str:
        bound = model.bind_tools([TOOL_SPEC])
        answer = bound.invoke(
            [HumanMessage(content="2026 年九月的净销售额是多少？请调用工具查询，不要自己猜。")]
        )
        calls = getattr(answer, "tool_calls", None) or []
        if not calls:
            raise ValueError("模型没有返回 tool_calls（可能不支持工具调用）")
        first = calls[0]
        return f"tool_calls[0].name={first.get('name')} args={first.get('args')}"

    def probe_structured() -> str:
        structured = model.with_structured_output(MonthFact)
        result = structured.invoke(
            [
                HumanMessage(
                    content=(
                        "从这句话里抽取结构化信息：2026 年九月净销售额 1286500 分，"
                        "该数字已扣除退款。"
                    )
                )
            ]
        )
        if not isinstance(result, MonthFact):
            raise TypeError(f"返回类型是 {type(result).__name__}，不是 MonthFact")
        return f"month={result.month} net={result.net_sales_cents} contains_refund={result.contains_refund}"

    results = [
        ("文本生成", probe_text),
        ("工具调用", probe_tool_call),
        ("结构化输出", probe_structured),
    ]

    failures = 0
    print("\n== 探测结果 ==")
    for label, fn in results:
        ok, detail = probe(label, fn)
        print(f"[{'支持' if ok else '不支持/失败'}] {label}：{detail}")
        if not ok:
            failures += 1

    print("\n== 结论 ==")
    if failures == 0:
        print("三项都通过。可以按教程完整学习；注意模型行为仍可能波动。")
    else:
        print(f"有 {failures} 项失败。请按第 8 节排查；失败不妨碍继续学单元 06～09。")
    return 1 if failures else 0


if __name__ == "__main__":
    sys.exit(main())
```

## 10. 复盘问题与参考答案、下一步

### Q1：为什么用 `uv` 而不是 `pip`？

**参考**：`uv` 把“建虚拟环境、解析依赖、装包、锁版本、跑脚本”合成一条命令，且解析速度快、锁文件可复现。对本教程的价值是：**命令少、出错点少**，学习者不需要记 `python -m venv`、`activate`、`pip install -r` 三步。代价是团队必须统一用 `uv`，否则 `uv.lock` 与 `requirements.txt` 会打架。

### Q2：`uv.lock` 为什么重要？为什么不直接提交别人的锁文件？

**参考**：锁文件固定了“依赖树里每个包分别是哪个版本”，保证今天装的和明天装的一样，避免“昨天能跑今天崩”。但锁文件可能包含平台相关标记（Python 版本、系统标记），在别的机器上可能解析失败；本仓库因此要求你自己 `uv lock`。**未验证**：跨平台能否复用取决于具体包；遇到问题以报错为准。

### Q3：模型名写成 `deepseek:deepseek-chat`，谁在解析这个冒号？

**参考**：是**我们自己的代码**在解析（`split_model` 按第一个冒号切分），不是 LangChain 的魔法。项目 `config.py` 也按同样规则处理：有前缀用前缀，否则用 `OPS_MODEL_PROVIDER`。所以 `OPS_MODEL=ollama:qwen2.5:7b` 会得到模型名 `qwen2.5:7b`——这恰好是我们想要的，但必须写清规则，否则维护者会困惑。

### Q4：探测脚本三项都失败，我还要继续学吗？

**参考**：要。单元 06～09 的图、状态、路由、预算、checkpoint 全是确定性代码，可以完全离线完成；单元 10～14 的检索与计算也不依赖模型。模型相关的能力（04、05 的工具循环、11 的语义检索增强）可以后面补。**先拥有确定性的工程能力，再谈模型**，这个顺序比反过来稳。

### Q5：为什么实验 A 里强调“只允许使用用户给出的数字”？

**参考**：这是“防幻觉”的第一道措施——把模型的角色限制为“复述 + 解释”，不让它算。第二道是程序校验（单元 03 用 Pydantic，单元 13 用整数计算）。第三道是人工审批（单元 16）。三层缺一不可；只靠提示词是**教学简化**级别的防护，不是生产级。
