## 3. 通俗解释与精确技术定义

### 3.1 一句话比喻

把 `data/knowledge/` 想成一个图书馆：

- **文档加载（document loading）** = 把书搬进来、登记书名（`LoadedDoc`）。
- **切分（splitting）** = 把每本书拆成一张张索引卡（`Chunk`），每张卡片 400 字左右。
- **重叠（overlap）** = 相邻卡片留 60 字重复内容，避免一句话被切断后两张卡都读不懂。
- **检索（retrieval）** = 拿着问题去卡片堆里找最相关的几张（`SearchHit`）。
- **引用（citation）** = 在回答后面写“这段话出自第几本书第几张卡”（`chunk_id`）。
- **关键词基线（keyword baseline）** = 最笨但最可靠的找法：**问题里的词和卡片里的词对上多少**。

### 3.2 精确技术定义（术语首现双语）

| 术语 | 英文 | 精确含义 | 本项目中的例子 |
| --- | --- | --- | --- |
| 文档加载 | document loading | 把外部资料读成内存对象，保留来源路径 | `load_documents(Path("data/knowledge"))` |
| 文档对象 | `LoadedDoc` | `doc_id` / `title` / `path` / `text` 四个字段的不可变对象 | `doc_id="02_退款与归属"` |
| 知识块 | chunk | 检索与引用的最小单位，带稳定 id 与起始偏移 | `Chunk(chunk_id="02_退款与归属#1", start=612)` |
| 块大小 | `chunk_size` | 单个块的最大字符数 | 规格固定 400 |
| 块重叠 | `chunk_overlap` | 相邻块重复的字符数 | 规格固定 60 |
| 分隔符 | separators | 递归切分时按顺序尝试的断点 | `["\n\n", "\n", "。", "！", "？", "；", "，", "、", " ", ""]` |

## 5. 文件、完整代码、配置与命令

### 5.1 加载：`loaders.py`（完整核心代码）

文件：`ops-assistant/src/ops_assistant/knowledge/loaders.py`

```python
"""知识文档加载：从知识目录读取 Markdown 与纯文本文件。
只读取 .md/.txt、使用 UTF-8、按文件名排序，保证构建结果可复现。
本模块不修改文件内容，也不递归子目录（知识目录约定为扁平结构）。
"""

from __future__ import annotations

from pathlib import Path

from .models import LoadedDoc

# 允许的文件扩展名（小写比较）。
SUPPORTED_SUFFIXES: frozenset[str] = frozenset({".md", ".txt"})

# 标题兜底长度，避免把超长首行整段塞进 title。
_FALLBACK_TITLE_MAX_CHARS = 80


def _extract_title(text: str, fallback: str) -> str:
    """提取文档标题：优先第一个 Markdown 标题，其次首个非空行。"""
    for line in text.splitlines():
        stripped = line.strip()
        if stripped.startswith("#"):
            title = stripped.lstrip("#").strip()
            if title:
                return title
    for line in text.splitlines():
        stripped = line.strip()
        if stripped:
            return stripped[:_FALLBACK_TITLE_MAX_CHARS]
    return fallback


def load_documents(docs_dir: Path) -> list[LoadedDoc]:
    """加载目录下的全部 Markdown/文本文档。

    异常：
        NotADirectoryError: 路径存在但不是目录。
        OSError: 读取文件失败（例如权限不足）。
        UnicodeDecodeError: 文件不是合法 UTF-8。
    """
    directory = Path(docs_dir)
    if not directory.exists():
        return []
    if not directory.is_dir():
        raise NotADirectoryError(f"知识目录不是文件夹：{directory}")

    files = sorted(
        (
            path
            for path in directory.iterdir()
            if path.is_file() and path.suffix.lower() in SUPPORTED_SUFFIXES
        ),
        key=lambda path: path.name,
    )

    documents: list[LoadedDoc] = []
    for path in files:
        text = path.read_text(encoding="utf-8")
        doc_id = path.stem
        documents.append(
            LoadedDoc(
                doc_id=doc_id,
                title=_extract_title(text, doc_id),
                path=str(path),
                text=text,
            )
        )
    return documents
```

行为清单（每条都对应上面一段代码）：

| 情况 | 结果 | 依据 |
| --- | --- | --- |
| 目录不存在 | 返回 `[]`，不报错 | `if not directory.exists(): return []` |
| 路径是文件不是目录 | `NotADirectoryError` | `if not directory.is_dir()` |
| 文件不是 UTF-8 | `UnicodeDecodeError`（原始异常） | `path.read_text(encoding="utf-8")` |
| 目录里有 `.pdf` / `.docx` | 被忽略 | `SUPPORTED_SUFFIXES` 只含 `.md` / `.txt` |
| 目录里有子文件夹 `sub/` | 被忽略（**不递归**） | `path.is_file()` 过滤 |
| 多篇文档 | 按**文件名升序** | `sorted(文件列表, key=lambda path: path.name)` |
| `doc_id` | 文件名去掉扩展名 | `path.stem` |
| `title` | 第一个 `#` 行；否则首个非空行；否则文件名 | `_extract_title` |

> **官方事实**：LangChain 生态里“文档加载”统一抽象为“load → `Document`（含 `page_content` 与 `metadata`）”。本项目没有直接用 `langchain_community` 的一堆 loader，而是自己写 40 行读文件（**项目设计选择**）：只有 `.md` / `.txt`、只需要 UTF-8、只想要可复现的排序，自写比引入依赖更可控。
>
> **未验证**：官方语义检索教程里加载 PDF / 网页的示例代码依赖额外包；本项目不装、也不评估这些路径。

### 5.2 切分：`splitter.py`（完整核心代码）

文件：`ops-assistant/src/ops_assistant/knowledge/splitter.py`

```python
"""知识块切分：使用 langchain_text_splitters 的递归字符切分器。
优先按段落、中文句号/逗号等分隔符切分，默认 chunk_size=400、overlap=60。
"""

from __future__ import annotations

from langchain_core.documents import Document
from langchain_text_splitters import RecursiveCharacterTextSplitter

from .models import Chunk, LoadedDoc

DEFAULT_CHUNK_SIZE = 400
DEFAULT_CHUNK_OVERLAP = 60

# 中文优先的分隔符顺序：段落 → 换行 → 中文句末标点 → 逗号 → 空格。
SEPARATORS: list[str] = ["\n\n", "\n", "。", "！", "？", "；", "，", "、", " ", ""]


def split_documents(
    docs: list[LoadedDoc],
    chunk_size: int = DEFAULT_CHUNK_SIZE,
    chunk_overlap: int = DEFAULT_CHUNK_OVERLAP,
) -> list[Chunk]:
    """把原始文档切分为可检索的知识块。"""
    if not isinstance(chunk_size, int) or isinstance(chunk_size, bool) or chunk_size <= 0:
        raise ValueError("chunk_size 必须为正整数")
    if not isinstance(chunk_overlap, int) or isinstance(chunk_overlap, bool):
        raise ValueError("chunk_overlap 必须为非负整数")
    if chunk_overlap < 0 or chunk_overlap >= chunk_size:
        raise ValueError("chunk_overlap 必须满足 0 <= chunk_overlap < chunk_size")

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        separators=list(SEPARATORS),
        keep_separator=True,
        add_start_index=True,
        length_function=len,
    )

    chunks: list[Chunk] = []
    for doc in docs:
        if not doc.text.strip():
            continue
        source = Document(
            page_content=doc.text,
            metadata={"doc_id": doc.doc_id, "title": doc.title, "path": doc.path},
        )
        pieces = splitter.split_documents([source])
        for index, piece in enumerate(pieces):
            text = piece.page_content
            if not text.strip():
                continue
            start = int(piece.metadata.get("start_index", 0))
            metadata = {
                "doc_id": doc.doc_id,
                "title": doc.title,
                "path": doc.path,
                "start": str(start),
            }
            chunks.append(
                Chunk(
                    chunk_id=f"{doc.doc_id}#{index}",
                    doc_id=doc.doc_id,
                    title=doc.title,
                    text=text,
                    start=start,
                    metadata=metadata,
                )
            )
    return chunks
```

三个必须理解的点：

1. **递归**：切分器先尝试 `\n\n`（段落）；某段仍超过 400 字符，就降级用 `\n`、再降级用 `。`、`，`，最后才硬切。这就是“递归字符切分（recursive character splitting）”的含义。
2. **`keep_separator=True`**：保留标点，否则 `。` 会被吃掉，中文句子读起来断裂。
3. **`add_start_index=True`**：让每个块带上在原文中的起始偏移，存进 `Chunk.start`；引用定位靠它。

> **官方事实**：`RecursiveCharacterTextSplitter` 由 `langchain-text-splitters` 包提供，用 `separators` 顺序递归尝试，用 `chunk_size` / `chunk_overlap` 控制块大小与重叠（来源：官方语义检索教程与本项目锁定的 `langchain-text-splitters==1.1.3` 公开 API）。
>
> **未验证**：具体边界行为（例如一个 900 字符段落最终被切成几块、重叠落在哪个字上）依赖版本实现，本环境未执行核对；请以你运行 5.6 实验得到的真实块数为准。

### 5.3 分词：`tokenize()`（完整代码）

文件：`ops-assistant/src/ops_assistant/knowledge/embeddings.py`（节选）

```python
import re

# 中文连续片段与英文/数字 token 的切分规则。
_CJK_RUN = re.compile(r"[\u4e00-\u9fff]+")
_ASCII_TOKEN = re.compile(r"[a-z0-9]+")


def tokenize(text: str) -> list[str]:
    """把文本切分为检索 token。

    规则：
        - 中文连续片段切成所有相邻 2-gram；单字片段保留该单字。
        - 英文与数字转小写后按连续字母/数字切分（如 "2026-09" -> "2026"、"09"）。
        - 保留重复 token（哈希向量按出现次数累加；关键词检索会自行去重）。
    """
    if not text:
        return []
    lowered = text.lower()
    tokens: list[str] = []
    for run in _CJK_RUN.findall(lowered):
        if len(run) == 1:
            tokens.append(run)
            continue
        tokens.extend(run[index : index + 2] for index in range(len(run) - 1))
    tokens.extend(_ASCII_TOKEN.findall(lowered))
    return tokens
```

### 5.4 关键词基线：`keyword_search()`（完整代码 + 公式）

文件：`ops-assistant/src/ops_assistant/knowledge/retrieve.py`（节选）

```python
KEYWORD_TITLE_WEIGHT = 1.5
DEFAULT_TOP_K = 4


def keyword_search(self, query: str, *, k: int = DEFAULT_TOP_K) -> list[SearchHit]:
    """关键词基线检索。

    分数公式：
        score = (正文命中数 + 1.5 * 标题命中数) / sqrt(查询 token 数 * 正文 token 数)

    返回：
        list[SearchHit]：完全无命中时返回空列表。
    """
    if not isinstance(k, int) or isinstance(k, bool) or k <= 0:
        raise ValueError("k 必须为正整数")
    text = (query or "").strip()
    if not text:
        return []

    query_tokens = set(tokenize(text))
    if not query_tokens:
        return []

    query_size = len(query_tokens)
    scored: list[SearchHit] = []
    for position, chunk in enumerate(self.index.chunks):
        body = self._body_tokens[position]
        title = self._title_tokens[position]
        body_overlap = len(query_tokens & body)
        title_overlap = len(query_tokens & title)
        if body_overlap == 0 and title_overlap == 0:
            continue
        numerator = body_overlap + KEYWORD_TITLE_WEIGHT * title_overlap
        denominator = math.sqrt(query_size * max(1, len(body)))
        score = numerator / denominator
        scored.append(SearchHit(chunk=chunk, score=score, method="keyword"))

    scored.sort(key=lambda hit: (-hit.score, hit.chunk.chunk_id))
    return scored[:k]
```

逐项解释：

| 组成 | 作用 | 为什么这么设计 |
| --- | --- | --- |
| `set(tokenize(query))` | 去重 | 同一句话里“退款”出现 10 次不该加权 10 倍（否则长文档总赢） |
| `body_overlap` | 正文命中数 | 基础相关性 |
| `title_overlap × 1.5` | 标题命中加权 | 标题命中通常比正文偶然命中更有意义，但又不该压倒正文 |
| `sqrt(query_size × len(body))` | 长度归一化 | 不除以长度，长块必然占便宜；除以长度又过度惩罚长块，开方是折中（**教学简化**） |
| `if body_overlap == 0 and title_overlap == 0: continue` | 无命中直接丢弃 | 规格要求“完全无命中返回空列表”，不能靠浮点 0 分混进来 |
| `sort(key=(-score, chunk_id))` | 同分稳定排序 | 同一份资料多次检索顺序必须一致（可复现） |

**手算演示（教学简化：用假设值讲清公式）**：假设查询 `退款算在哪个月` 有 6 个 token，某块的正文有 120 个不同 token，其中与查询重合 4 个，标题又重合 1 个（“退款”）：

```text
score = (4 + 1.5 × 1) / sqrt(6 × 120) = 5.5 / 26.83 ≈ 0.205
```

记住这个量级（**0.1～0.3**）：单元 11 的“资料不足”阈值 `SCORE_THRESHOLD = 0.15` 就落在这个区间里，所以阈值定得高一点、低一点，行为会明显不同。

> **官方事实**：`工程规格.md` 5.4 规定的公式是“命中 token 数 / sqrt(查询 token 数 × 块 token 数)，标题命中加权 1.5”。
>
> **项目设计选择**：`method="keyword"` 是基线，存在的意义是**给向量检索一个不需要模型、不需要网络的对照物**。工程上先有基线再上模型，才说得清“模型到底带来了多少提升”。

### 5.5 引用：`citation()` 与 `make_snippet()`

文件：`ops-assistant/src/ops_assistant/knowledge/models.py`（节选）

```python
SNIPPET_MAX_CHARS = 160


def make_snippet(text: str, max_chars: int = SNIPPET_MAX_CHARS) -> str:
    """把知识块正文压缩成单行摘要，用于报告与工具返回。"""
    if max_chars <= 0:
        raise ValueError("max_chars 必须为正整数")
    compact = " ".join(text.split())
    if len(compact) <= max_chars:
        return compact
    return compact[: max_chars - 1].rstrip() + "…"


@dataclass(frozen=True)
class SearchHit:
    chunk: Chunk
    score: float
    method: str

    def citation(self) -> dict[str, Any]:
        """返回可直接 JSON 序列化的引用信息。"""
        return {
            "doc_id": self.chunk.doc_id,
            "title": self.chunk.title,
            "chunk_id": self.chunk.chunk_id,
            "snippet": make_snippet(self.chunk.text),
        }
```

要点：

- `snippet` 做了空白归一化（`" ".join(text.split())`），所以报告里不会出现换行把表格打散。
- 截断时用 `…`（单字符）而不是三个点，避免和“省略关键实现”的写法混淆。
- 引用**必须能回到原文**：拿到 `chunk_id = "02_退款与归属#3"` 后，可以用 `KnowledgeBase.get_chunk("02_退款与归属#3")` 取回完整块（单元 11 讲 `get_chunk` 与 `citation_ids`）。

```python
    print("块数：", len(chunks))
    if chunks:
        average = sum(len(chunk.text) for chunk in chunks) / len(chunks)

            )

    """第三段：关键词检索 + 手算校验。"""
    print("\n== 第三段：关键词基线 ==")
    for query in QUERIES:
        hits = kb.keyword_search(query, k=3)
        print(f"\n查询：{query}  命中={len(hits)}")
        for hit in hits:
            print(
                f"  score={hit.score:.4f} method={hit.method} {hit.chunk.chunk_id}"
                f" | {make_snippet(hit.chunk.text, 48)}"
            )

    print("\n-- 手算校验：第一条分数是否等于公式 --")
    hits: list[SearchHit] = kb.keyword_search(QUERIES[0], k=1)
    if not hits:
        print("  查询无命中，无法手算；请确认文档里确实有“退款算在哪个月”这类表述。")
        return
    target = hits[0]
    position = next(
        index
        for index, chunk in enumerate(kb.index.chunks)
        if chunk.chunk_id == target.chunk.chunk_id

    print("  程序：", round(target.score, 4))
    print("  权重：", KEYWORD_TITLE_WEIGHT)


def show_citation(kb: KnowledgeBase) -> None:

    print("\n== 第四段：引用信息 ==")

    if not hits:
        print("  无命中，跳过。")
        return
    citation = hits[0].citation()
    for key, value in citation.items():
        print(f"  {key}: {value}")


def main() -> int:

    docs = show_documents(settings)
    if not docs:
        print("[失败] 知识目录为空或不存在：请确认 data/knowledge/ 下有 .md 或 .txt 文档。")

    print("切分参数：", DEFAULT_CHUNK_SIZE, "/", DEFAULT_CHUNK_OVERLAP)

    print("      差值就是关键词基线的天花板；单元 11 用向量与混合检索再比一次。")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

**要理解的点**：加载器对“目录不存在”是宽容的，因为首次运行 `bootstrap.py` 时目录可能还没建；但**宽容不等于正确**，空知识库必须能被回答层识别出来。

### 实验 8.2：非 UTF-8 文件

把一个 `.md` 用 GBK（ANSI）另存为 `data/knowledge/99_gbk.md`，重跑实验。

预期（未在本环境执行）：`load_documents` 抛 `UnicodeDecodeError`；如果通过 `bootstrap.py` 触发，会看到中文提示“请确认 data/knowledge/ 下至少有 1 篇 .md/.txt 文档，且文件为 UTF-8 编码”。

**要理解的点**：Windows 记事本默认编码可能不是 UTF-8。“文件能打开”不等于“程序能读”。修复办法：另存为 UTF-8（不带 BOM 更稳）。

### 实验 8.3：文档放进子目录

新建 `data/knowledge/sub/05_子目录.md`，重跑实验。

预期（未在本环境执行）：文档数**仍然是 4**，`sub/` 被忽略。

**要理解的点**：这是**项目设计选择**（扁平目录）。如果你需要子目录，要么改 `load_documents` 用 `rglob`（并处理 `doc_id` 冲突：两个子目录都叫 `01_指标口径.md` 时 `chunk_id` 会撞车），要么在入库前把文件拍平。

### 实验 8.4：超长无标点段落

造一个 2000 字、**没有任何标点**的 `.md`（用一句话重复拼接），观察它被切成几块、每块长度如何。

预期（未在本环境执行）：会退化到分隔符列表最后一个 `""`（按字符硬切），得到若干接近 400 字符的块，且相邻块之间有 60 字符重叠。

**要理解的点**：递归切分器在“没有可依赖的断点”时只能硬切；引用片段可能从词中间断开，报告读起来会别扭。写业务文档时**保留标点与换行**，检索质量会明显更好。

### 实验 8.5：数字与英文 token 的假命中

```python
from ops_assistant.knowledge.embeddings import tokenize

print(tokenize("2026-05"))
print(tokenize("2026-09"))
```

预期（未在本环境执行）：两次都得到 `['2026', '05']` 与 `['2026', '09']`，其中 `2026` 完全重合。

**要理解的点**：关键词检索会把“2026-05”和“2026-09”判成“有一个 token 相同”。在只有 21 个月的数据集里这不是大问题，但换成“订单号只差一位”的场景就会假命中。改进方向：保留连字符作为 token 边界信息，或在打分时降低纯数字 token 的权重。

### 实验 8.6：同义改写为什么必然掉分（本单元最重要的失败）

```python
hits_a = kb.keyword_search("退款算在哪个月", k=3)
hits_b = kb.keyword_search("退钱算在哪个月", k=3)
print(max((hit.score for hit in hits_a), default=0.0))
print(max((hit.score for hit in hits_b), default=0.0))
```

预期（未在本环境执行）：第一句 top_score 明显更高；第二句可能只有极低分或空列表。

**要理解的点**：关键词检索只看**字面 token 重合**。“退款”和“退钱”是两个不同的 token，交集为空。这不是 bug，而是基线的定义边界；单元 11 用向量检索与混合检索来缓解它——同时你会看到哈希向量也只能解决一部分。

## 10. 复盘问题与参考答案、下一步

### Q1：为什么先做关键词基线，而不是直接上向量检索？

**参考**：因为基线给了你三个可比较的东西：**不需要模型、不需要网络、结果完全确定**。有了它，单元 11 才能回答“向量检索到底带来了多少提升”“混合检索是不是真的更好”。工程上先有对照组，再加变量；没有基线的“效果不错”只是感觉。

### Q2：400/60 这两个数字是怎么来的？

**参考**：`工程规格.md` 5.4 的规定值，属于**项目设计选择**。400 字符大致覆盖两三个业务要点（中文 400 字约等于一段说明），60 字符重叠约为 15%，足以避免一句话被切断后两块都读不懂。它不是普适真理：长条款文档可能用 800/100，短问答对可能用 200/0。判断标准是“块里能否独立支撑一句引用”。

### Q3：标题权重为什么是 1.5，不是 10？

**参考**：标题是人工写的摘要，命中标题确实更有信息量；但如果权重过大（比如 10），查询里出现“数据字典”四个字就会让整篇 `04_数据字典.md` 的所有块全部冲到前面，正文细节被淹没。1.5 的效果是“轻微加分、不改变量级”。这是**可调参数**，练习 7.3 就是让你感受它的影响；生产里应该用带标注的评估集去调，而不是拍脑袋（单元 20 才具备这个条件）。

### Q4：`doc_id` 为什么用文件名，而不是 `doc-001` 这种编号？

**参考**：文件名是**人类可读且天然唯一**的标识。报告里出现 `[02_退款与归属#1]`，运营人员一眼知道去查哪份文档；如果显示 `[doc-002#1]`，还要再查一次映射表。代价是**改名等于改 id**，会导致旧报告里的 `chunk_id` 失效——所以知识文档一旦发布，文件名就应视为稳定契约。

### Q5：本单元这套东西，在真实业务里最容易踩的坑是什么？

**参考**：三个高频坑。第一，**文档不规范**（没有标题、没有标点、把表格截图当正文），切分后每块都读不懂；第二，**目录不干净**，把草稿、会议记录、导出文件一起丢进 `data/knowledge/`，检索出来的“依据”不可用；第三，**把关键词分数当置信度**，它只是一个重合度指标，0.2 不代表“20% 正确”。本项目用“引用可回查 + 资料不足显式回答”来对冲第三条，前两条需要文档治理，代码解决不了。
