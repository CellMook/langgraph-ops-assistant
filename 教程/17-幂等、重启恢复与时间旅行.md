## 3. 通俗解释与精确技术定义

**先讲人话。**

- **幂等**：同一件事做两遍，结果和做一遍一样。按一次电梯按钮和按三次，电梯都来一次。
- **重启恢复**：服务挂了，重启后用户刷新页面，会话还在、还能继续审批。
- **时间旅行**：把图的执行历史倒回去看，甚至从某个历史点重新往下跑。

**再给定义。**

- **幂等（Idempotent）**：对同一输入重复执行，系统状态与副作用只发生一次（或结果等价）。
- **可恢复（Durable execution）**：把执行进度持久化到外部存储，进程重启后能从最后一个检查点继续。
- **replay（重放）**：从历史检查点重新执行；**fork（分叉）**：修改某个历史点的状态后从那里继续，产生新分支。

**本项目的三个决定：**

| 决定 | 内容 | 理由 |
| --- | --- | --- |
| ① 副作用集中 | 只有 `export_node` 写文件 | `review_node` 里 `interrupt()` 之前的代码在恢复后会重跑，写在那里会重复写 |
| ② 原子写 | 临时文件 + `os.replace` | 半截文件比没有文件更糟 |
| ③ 固定文件名 | `report-<thread_id>.md` | 同一会话重复导出天然覆盖到同一路径，不需要"去重表" |

【项目设计选择】这不是唯一做法。另一种常见做法是"每次导出生成带时间戳的新文件 + 数据库记录当前有效版本"，代价是要多维护一张表。

## 4. 在主项目中的位置

- `workflow/nodes.py`：`review_node`（纯计算 + `interrupt`）、`export_node`（唯一落盘）；

## 5. 文件、完整代码、配置与命令

保存为 `教程/实验/17_idempotent_restart.py`（在 `ops-assistant` 目录下运行）：

```python
"""实验 17：验证导出幂等、重启恢复与时间旅行。"""

from __future__ import annotations

from pathlib import Path

from ops_assistant.config import load_settings
from ops_assistant.workflow.persistence import AppRuntime

QUESTION = "2026 年九月销售额比八月变化多少？按地区分解差额，并说明销售额是否扣除了退款。"


def main() -> None:
    settings = load_settings()

    # ---- 1) 第一次运行：跑到审批中断 ----
    first = AppRuntime.create(settings)  # 默认用 SqliteSaver
    try:
        turn = first.invoke_turn(QUESTION)
        thread_id = turn["thread_id"]
        print("状态：", turn["status"])
        print("报告字符数：", len(turn["report"]))
        approved_once = first.resume_turn(thread_id, "approve")
        approved_twice = first.resume_turn(thread_id, "approve")
        print("第一次导出：", approved_once["export_path"])
        print("第二次导出：", approved_twice["export_path"])
        print("路径相同：", approved_once["export_path"] == approved_twice["export_path"])

        # 导出目录里这个 thread 只应有一个文件
        export_dir = Path(settings.export_dir)
        files = sorted(path.name for path in export_dir.glob(f"report-{thread_id}*.md"))
        print("导出文件列表：", files)

        # ---- 2) 时间旅行：看历史快照 ----
        config = {"configurable": {"thread_id": thread_id}}
        history = list(first.graph.get_state_history(config))
        print("历史快照数量：", len(history))
        for snapshot in history[:5]:
            # next 表示"如果继续执行，下一个要跑的节点"
            print("  checkpoint:", snapshot.config["configurable"].get("checkpoint_id"), "next:", snapshot.next)
    finally:
        first.close()

    # ---- 3) 模拟重启：新的进程实例读同一个检查点 ----
    second = AppRuntime.create(settings)
    try:
        reloaded = second.read_thread(thread_id)
        print("重启后状态：", reloaded["status"])
        print("重启后导出路径：", reloaded["export_path"])
        again = second.resume_turn(thread_id, "approve")
        print("重启后重复审批路径相同：", again["export_path"] == reloaded["export_path"])
    finally:
        second.close()


if __name__ == "__main__":
    main()
```

运行：

```powershell

uv run python ..\教程\实验\17_idempotent_restart.py
```

## 8. 失败与边界实验

1. **用内存检查点重启**：把 `AppRuntime.create(settings)` 改成 `AppRuntime.create(settings, use_memory_checkpointer=True)`，再"重启"读状态。
   - 预期：抛 `ThreadNotFoundError`（进程内存里的状态没了）。结论：`InMemorySaver` 只适合测试。
2. **并发重复审批**：在两个终端同时对同一 thread 执行 `resume approve`。
   - 预期：`AppRuntime` 内部有 `threading.Lock`，同一进程内串行化；跨进程并发没有加锁，可能出现竞争——这是**已知限制**（单 worker 部署）。
3. **审批后再提问**：对已 `approved` 的 thread 继续 `invoke_turn("那华东地区呢？", thread_id=...)`。
   - 预期：进入新一轮（新的一轮可以再次审批），旧导出文件保留。
4. **检查点文件被删**：`approved` 之后删除 `data/checkpoints.db` 再 `read_thread`。
   - 预期：`ThreadNotFoundError`；但导出文件仍在，说明"业务产物"和"执行状态"是两套存储。
5. **导出目录不可写**：把 `data/exports` 改成只读。
   - 预期：`export` 节点失败，`status = failed`，`errors` 里有文件系统错误；**不应**出现"状态已批准但没有文件"而不报错。

## 10. 复盘问题与参考答案、下一步

**Q1：为什么不能把写文件放在 `review_node` 里 `interrupt()` 之前？**
A：恢复时 LangGraph 会从 `review_node` 开头重新执行，`interrupt()` 之前的代码会再跑一遍，导致重复写文件（即使覆盖也可能写坏）。

**Q2：重复 `approve` 为什么不会生成两份文件？**
A：两层保证：文件名固定为 `report-<thread_id>.md`（覆盖同一路径）；`resume_turn` 检测到无待处理中断且已导出时直接返回既有结果。

**Q3：时间旅行能回滚业务数据吗？**
A：不能。它回滚的是**图的执行状态**（检查点）。已经写到磁盘的报告、已经写进数据库的记录不会被自动撤销；需要额外实现补偿逻辑。

**Q4：如果要在导出前发一封邮件，应该放哪？**
A：放在 `export_node` 成功之后，并且要有"已发送"标记（数据库或状态字段）+ 幂等键（thread_id），否则重试会重复发信。
