## 3. 通俗解释与精确技术定义

### 3.1 一句话比喻

- **embedding** = 给每个知识块生成一枚“指纹”。指纹相同/相近，说明两块内容相关。
- **哈希向量（本项目默认）** = 一枚**只看字面**的指纹：用了哪些 token、各出现几次。它不懂“退款”和“退钱”是一个意思。
- **余弦相似度** = 两枚指纹的夹角：同向为 1，垂直为 0。因为向量都做过 L2 归一化，夹角余弦恰好等于点积。
- **混合检索（hybrid）** = 两个人同时找：一个按字面（关键词），一个按指纹（向量），各挑 4 条，然后合并投票。
- **证据阈值（0.15）** = “至少要有这么像，我才承认有依据”。低于它就回答“现有资料不足以回答”。
- **引用校验** = 模型写完答案后，程序逐条检查 `[chunk_id]` 是否真的存在、是否在本次给它的资料里；不通过就丢掉模型答案、改用模板。

### 3.2 精确技术定义

| 术语 | 英文 | 精确含义 | 本项目中的例子 |
| --- | --- | --- | --- |
| 向量化 | embedding | 把文本映射为定长浮点向量 | `HashingEmbeddings(dim=512)` |
| 维度 | dimension | 向量长度；哈希向量由配置决定 | 默认 512（`DEFAULT_EMBEDDING_DIM`） |
| 文档向量 | document embedding | 建索引时批量调用 | `embeddings.embed_documents(texts)` |
| 查询向量 | query embedding | 检索时单条调用 | `embeddings.embed_query(query)` |
| 归一化 | L2 normalization | 除以向量长度，使点积等于余弦 | `norm = sqrt(sum(v²))` |
| 余弦相似度 | cosine similarity | `dot(a,b) / (‖a‖·‖b‖)`，范围约 `[-1, 1]` | `_cosine_similarity` |
| 向量索引 | vector index | 块 + 向量 + 元信息的打包 | `VectorIndex` / `data/knowledge_index.json` |
| 检查点版本 | schema version | 索引格式版本，便于未来兼容 | `INDEX_SCHEMA_VERSION = 1` |
| 检索模式 | search mode | `vector` / `keyword` / `hybrid` | `VALID_SEARCH_MODES` |
| 融合 | fusion | 两路分数加权合并去重 | `_fuse_hits`，0.5 + 0.5 |
| 证据阈值 | score threshold | 低于即“资料不足” | `SCORE_THRESHOLD = 0.15` |
| 引用校验 | citation validation | 引用必须真实存在于给定块中 | `_validate_citations` |
| 资料不足 | insufficient | 显式拒答，不做推断 | `KnowledgeAnswer.insufficient` |

### 3.3 业务例子：同一个问题，三种模式各看到什么

问题：`退款算在哪个月`

| 模式 | 依赖 | 能回答吗 | 为什么 |
| --- | --- | --- | --- |
| `keyword` | 字面 token 重合 | 通常能 | 文档里就有“退款算在哪个月”这句话 |
| `vector`（哈希） | token 集合的余弦 | 通常能，但分数与关键词接近 | 哈希向量本质也是 token 计数，只是换了表示 |
| `hybrid` | 两路各取 k 后加权 | 通常能，且分数高于单路 | 两路都命中同一块时，0.5 + 0.5 相加 |

问题：`退钱算哪个月`（同义改写）

| 模式 | 结果 | 原因 |
| --- | --- | --- |
| `keyword` | 分数很低或 0 | “退钱”不在文档里 |
| `vector`（哈希） | 分数很低或 0 | 哈希向量不看语义，`退钱` 与 `退款` 是两个不同的 token |
| `hybrid` | 可能仍判“资料不足” | 两路都弱，融合后仍不过 0.15 |

> **教学简化**：本项目的向量检索**不能**解决同义改写。它存在的价值是“让你在没有 API Key 的情况下把整条 RAG 流水线跑通、看清接口”，以及作为接入真实 embedding 模型前的占位实现。
>
> **项目设计选择**：真实 embedding 通过 `OpenAICompatEmbeddings` 接入（`EMBEDDING_MODEL` / `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY`），失败时自动回退哈希向量并把原因写进索引 `meta.embedding_fallback_reason`。为什么保留哈希向量？因为教学环境无密钥、离线、可复现；索引里会明确记录类型，避免把“教学向量”误当“语义能力”。

### 5.1 向量化：`HashingEmbeddings`（完整代码）

文件：`ops-assistant/src/ops_assistant/knowledge/embeddings.py`（节选）

```python
DEFAULT_EMBEDDING_DIM = 512

HASHING_NOTE = (
    "HashingEmbeddings 是确定性教学向量：对中文 2-gram 与英文/数字 token 做 blake2b 哈希映射后累加并 L2 归一化。"
    "它不理解语义，同义改写（例如“退款”与“退钱”）不会命中，不代表真实 embedding 模型的效果。"
)


def _hash_index(token: str, dim: int) -> int:
    """把 token 稳定映射到 [0, dim) 的维度下标。

    使用 blake2b 摘要的整数值取模；同一 token 在任何进程、任何机器上结果一致。
    """
    digest = hashlib.blake2b(token.encode("utf-8")).digest()
    return int.from_bytes(digest, "big") % dim


class HashingEmbeddings:
    """确定性哈希向量（教学用，不是语义模型）。

    实现方式：token -> blake2b 哈希 -> 维度下标，逐 token 累加计数，
    最后做 L2 归一化，使余弦相似度等价于点积。
    """

    def __init__(self, dim: int = DEFAULT_EMBEDDING_DIM) -> None:
        if not isinstance(dim, int) or isinstance(dim, bool) or dim <= 0:
            raise ValueError("dim 必须为正整数")
        self.dim = dim

    def embed_documents(self, texts: list[str]) -> list[list[float]]:
        return [self._embed(text) for text in texts]

    def embed_query(self, text: str) -> list[float]:
        return self._embed(text)

    def _embed(self, text: str) -> list[float]:
        """内部实现：词袋计数后做 L2 归一化。"""
        vector = [0.0] * self.dim
        for token in tokenize(text or ""):
            vector[_hash_index(token, self.dim)] += 1.0
        norm = math.sqrt(sum(value * value for value in vector))
        if norm > 0.0:
            return [value / norm for value in vector]
        return vector
```

三句话看懂：

1. `tokenize` 把文本拆 token（单元 10 已讲），中文 2-gram、英文数字按连续字符。
2. 每个 token 用 `blake2b` 算哈希、取模落到 512 个桶之一，桶里计数 +1。所以这个向量本质上是**词频直方图**（bag of tokens）。
3. 除以 L2 范数后，余弦相似度退化成点积，查询向量与块向量的分数只需做一次点积，快且好解释。

自己验证一下“它不懂语义”：

```python
from ops_assistant.knowledge.embeddings import HashingEmbeddings

model = HashingEmbeddings(dim=512)
a = model.embed_query("退款")
b = model.embed_query("退钱")
c = model.embed_query("退款额")
dot = lambda x, y: sum(i * j for i, j in zip(x, y))
print("cos(退款, 退钱) =", round(dot(a, b), 4))
print("cos(退款, 退款额) =", round(dot(a, c), 4))
```

预期（未在本环境执行）：

```text
cos(退款, 退钱) = 0.0
cos(退款, 退款额) = 0.7071
```

`0.0` 是因为“退款”与“退钱”没有任何共享 token；`0.7071` 是因为“退款额”的 token 里包含“退款”（`1/√2 ≈ 0.7071`）。**这就是哈希向量的能力上限：字面重合，不是语义相近。**

> **官方事实**：embedding 接口在 LangChain 中统一为 `embed_documents(texts)` 与 `embed_query(text)` 两个方法（来源：官方语义检索教程使用的 embedding 抽象；本项目的 `OpenAICompatEmbeddings` 直接包装 `langchain_openai.OpenAIEmbeddings`）。
>
> **未验证**：不同厂商的向量维度、归一化方式不同；本项目只对“哈希向量”保证 L2 归一化，远端返回的向量按原样使用。

### 5.2 索引：`VectorIndex`（完整核心代码）

文件：`ops-assistant/src/ops_assistant/knowledge/index.py`（节选）

```python
INDEX_SCHEMA_VERSION = 1

# 向量保存精度：8 位小数足够稳定，也避免 JSON 体积过大。
_VECTOR_DECIMALS = 8


@dataclass
class VectorIndex:
    chunks: list[Chunk]
    vectors: list[list[float]]
    meta: dict[str, Any] = field(default_factory=dict)

    def __len__(self) -> int:
        return len(self.chunks)

    @classmethod
    def build(
        cls,
        chunks: list[Chunk],
        embeddings: Any,
        *,
        meta: dict[str, Any] | None = None,
    ) -> "VectorIndex":
        texts = [chunk.text for chunk in chunks]
        vectors = embeddings.embed_documents(texts) if texts else []
        if len(vectors) != len(chunks):
            raise ValueError(
                f"向量数量与知识块数量不一致：{len(vectors)} != {len(chunks)}"
            )
        # 统一按保存精度取整，保证“内存索引”与“落盘后重新加载”的检索分数完全一致。
        normalized_vectors = [
            [round(float(value), _VECTOR_DECIMALS) for value in vector]
            for vector in vectors
        ]
        if normalized_vectors:
            dimension = len(normalized_vectors[0])
            for position, vector in enumerate(normalized_vectors):
                if len(vector) != dimension:
                    raise ValueError(
                        "向量维度不一致："
                        f"vectors[0] 为 {dimension} 维，vectors[{position}] 为 {len(vector)} 维"
                    )
        return cls(chunks=list(chunks), vectors=normalized_vectors, meta=dict(meta or {}))

    def search(self, query: str, k: int, embeddings: Any) -> list[SearchHit]:
        if not isinstance(k, int) or isinstance(k, bool) or k <= 0:
            raise ValueError("k 必须为正整数")
        if not self.chunks:
            return []

        query_vector = [float(value) for value in embeddings.embed_query(query)]
        scored: list[SearchHit] = []
        for chunk, vector in zip(self.chunks, self.vectors, strict=False):
            score = _cosine_similarity(query_vector, vector)
            if score > 0.0:
                scored.append(SearchHit(chunk=chunk, score=score, method="vector"))
        scored.sort(key=lambda hit: (-hit.score, hit.chunk.chunk_id))
        return scored[:k]

    def save(self, path: Path) -> None:
        """把索引原子写入 JSON 文件。"""
        target = Path(path)
        target.parent.mkdir(parents=True, exist_ok=True)
        meta = dict(self.meta)
        meta.setdefault("schema_version", INDEX_SCHEMA_VERSION)
        meta["chunk_count"] = len(self.chunks)
        payload = {
            "meta": meta,
            "chunks": [_chunk_to_dict(chunk) for chunk in self.chunks],
            "vectors": [
                [round(value, _VECTOR_DECIMALS) for value in vector]
                for vector in self.vectors
            ],
        }
        temp_path = target.with_name(target.name + ".tmp")
        temp_path.write_text(
            json.dumps(payload, ensure_ascii=False, separators=(",", ":")),
            encoding="utf-8",
        )
        os.replace(str(temp_path), str(target))


def _cosine_similarity(left: list[float], right: list[float]) -> float:
    if len(left) != len(right):
        raise ValueError(
            f"向量维度不一致：查询 {len(left)} 维，索引 {len(right)} 维；"
            "请删除旧索引后重新运行 bootstrap.py 重建"
        )
    dot = 0.0
    left_norm = 0.0
    right_norm = 0.0
    for left_value, right_value in zip(left, right, strict=True):
        dot += left_value * right_value
        left_norm += left_value * left_value
        right_norm += right_value * right_value
    if left_norm <= 0.0 or right_norm <= 0.0:
        return 0.0
    return dot / (math.sqrt(left_norm) * math.sqrt(right_norm))
```

四个设计点：

| 设计 | 代码位置 | 解决的问题 |
| --- | --- | --- |
| 8 位小数取整 | `build` 与 `save` | 内存索引与落盘重载后的分数**逐位一致**，测试才能断言精确值 |
| 维度一致性校验 | `build` 与 `_cosine_similarity` | 换 embedding 模型后旧索引维度不匹配，**立刻报错并提示重建**，不产生垃圾分数 |
| 原子保存 | `save`（`.tmp` + `os.replace`） | 写盘中途崩溃不会留下“半个索引”，`load` 不会读到半个 JSON |
| 只存 `chunks`/`vectors`/`meta` | `save` 的 `payload` | 索引里**没有任何密钥**；`meta` 只记录类型、维度、模型名与切分参数 |

`load` 的校验规则（省略代码、用表格说清，你可以在源文件读到完整实现）：

| 校验 | 失败时 |
| --- | --- |
| 文件是合法 JSON 且顶层为对象 | `ValueError: 索引文件不是合法 JSON` / `顶层必须是 JSON 对象` |
| `chunks` 与 `vectors` 都是数组、长度相等 | `ValueError: 缺少 chunks 或 vectors 数组` / `数量不一致` |
| 每个 chunk 的必填字段是字符串、`start` 是整数 | `ValueError: chunks[i].字段 必须是…` |
| 每个 vector 元素是数字（且不是 bool） | `ValueError: vectors[i] 含非数字元素` |

> **官方事实**：LangChain 官方的向量库会负责持久化；本项目**没有**引入向量数据库，而是自己写 JSON 索引（**项目设计选择**）：知识库只有 4 篇文档、几十个块，暴力余弦足够快，而且 JSON 可读、可 diff、可手工检查——教学价值远高于性能。
>
> **关于 `zip(..., strict=...)`**：Python 3.10+ 的 `zip` 支持 `strict` 参数。`search` 里用 `strict=False`（向量缺失时优雅返回空结果，由上层降级为关键词检索）；`_cosine_similarity` 里用 `strict=True`（维度不一致直接抛错，上面 `load` 的维度校验兜底）。两个方向相反的选择都是刻意的：**可降级的路径宽容，必须一致的路径严格**。
>
> **未验证**：块数上千后暴力检索的耗时未在本环境测量；届时应换 FAISS / Chroma / pgvector 等。

### 5.3 检索：三种模式与融合（完整代码）

文件：`ops-assistant/src/ops_assistant/knowledge/retrieve.py`（节选）

```python
VALID_SEARCH_MODES = ("vector", "keyword", "hybrid")


def search(
    self,
    query: str,
    *,
    k: int = DEFAULT_TOP_K,
    mode: str = "vector",
) -> list[SearchHit]:
    if mode not in VALID_SEARCH_MODES:
        raise ValueError(f"不支持的检索模式：{mode!r}；可选：{', '.join(VALID_SEARCH_MODES)}")
    if not isinstance(k, int) or isinstance(k, bool) or k <= 0:
        raise ValueError("k 必须为正整数")

    text = (query or "").strip()
    if not text:
        return []
    if mode == "keyword":
        return self.keyword_search(text, k=k)

    try:
        vector_hits = self.index.search(text, k, self.embeddings)
    except Exception as exc:
        logger.warning("向量检索失败，降级为关键词检索：%s", redact_secret(str(exc)))
        return self.keyword_search(text, k=k)

    if mode == "vector":
        return vector_hits
    keyword_hits = self.keyword_search(text, k=k)
    return _fuse_hits(keyword_hits, vector_hits, k)


def _fuse_hits(
    keyword_hits: list[SearchHit],
    vector_hits: list[SearchHit],
    k: int,
) -> list[SearchHit]:
    """融合关键词与向量两路结果。

    规则（可解释的教学简化）：
        - 关键词分数本身已是 0~1 量级的重合度，直接截断到 [0, 1] 后乘 0.5；
        - 向量余弦分数直接乘 0.5；
        - 同一 chunk_id 的分数据相加，去重后按总分排序。
        这里不使用“按本次最高分归一化”，否则任何一次关键词命中都会得到 0.5，
        会让 0.15 的证据阈值失去意义。
    """
    if not keyword_hits and not vector_hits:
        return []

    merged: dict[str, SearchHit] = {}

    for hit in keyword_hits:
        normalized = min(1.0, max(0.0, hit.score))
        merged[hit.chunk.chunk_id] = SearchHit(
            chunk=hit.chunk,
            score=0.5 * normalized,
            method="hybrid",
        )

    for hit in vector_hits:
        contribution = 0.5 * max(0.0, hit.score)
        existing = merged.get(hit.chunk.chunk_id)
        if existing is None:
            merged[hit.chunk.chunk_id] = SearchHit(
                chunk=hit.chunk,
                score=contribution,
                method="hybrid",
            )
        else:
            merged[hit.chunk.chunk_id] = SearchHit(
                chunk=existing.chunk,
                score=existing.score + contribution,
                method="hybrid",
            )

    ranked = sorted(merged.values(), key=lambda hit: (-hit.score, hit.chunk.chunk_id))
    return ranked[:k]
```

**手算演示（教学简化：假设值）**：某块关键词分 0.20、向量余弦 0.30，两路都命中：

```text
hybrid = 0.5 × clamp(0.20) + 0.5 × 0.30 = 0.10 + 0.15 = 0.25
```

如果它只在向量路命中（关键词 0 条）：`hybrid = 0.5 × 0.30 = 0.15`，**刚好压在阈值上**。这解释了为什么混合检索的绝对分值不能和纯向量分值直接比较——**`method` 不同，分数含义不同**，报告里必须带上 `method`。

> **项目设计选择**：融合不做“按本次最高分归一化”。很多教程喜欢 `score / max_score`，看着整齐，但会让每次检索的第一名都变成 1.0，`0.15` 阈值就永远拦不住“瞎命中”。本项目宁可分数不可比，也要保住“资料不足”的判断力。
>
> **官方事实**：三种模式名与 `k` 的语义见 `工程规格.md` 5.4；实现与规格一致。

### 5.4 问答：模板答案、模型改写、引用校验（完整代码）

文件：`ops-assistant/src/ops_assistant/knowledge/qa.py`（节选）

```python
SCORE_THRESHOLD = 0.15
MAX_HITS = 4

_CITATION_PATTERN = re.compile(r"\[([^\[\]\s]+#[0-9]+)\]")


def _validate_citations(text: str, hits: list[SearchHit]) -> bool:
    """校验模型输出中的引用。

    规则：
        - 至少要有一个 [chunk_id] 形式的引用；
        - 每个引用 id 都必须真实存在于索引，且必须是本次提供的知识块；
        - 不允许出现索引中不存在的伪造 id。
    """
    cited = set(_CITATION_PATTERN.findall(text))
    if not cited:
        return False
    allowed = {hit.chunk.chunk_id for hit in hits}
    return cited.issubset(allowed)


def answer_from_knowledge(
    question: str,
    kb: KnowledgeBase,
    llm: Any | None = None,
) -> KnowledgeAnswer:
    """基于本地知识库回答问题。

    流程：
        1. 用 hybrid 模式检索最多 4 个知识块；
        2. 无命中或最高分 < 0.15 -> insufficient=True，明确写“现有资料不足以回答”；
        3. 有证据 -> 先用模板答案兜底，再尝试模型改写；
        4. 模型改写必须通过引用校验（id 必须真实存在且在本次给定块内），否则回退模板。
    """
    text = (question or "").strip()
    if not text:
        return KnowledgeAnswer(
            answer=(
                "现有资料不足以回答：问题为空。"
                "请提供具体业务问题，例如“退款是否计入当月销售额？”。"
            ),
            citations=(),
            hits=(),
            insufficient=True,
            mode="template",
        )

    hits = kb.search(text, k=MAX_HITS, mode="hybrid")
    top_score = max((hit.score for hit in hits), default=0.0)
    if not hits or top_score < SCORE_THRESHOLD:
        return KnowledgeAnswer(
            answer=_insufficient_answer(text, kb),
            citations=(),
            hits=tuple(hits),
            insufficient=True,
            mode="template",
        )

    fallback = build_template_answer(hits)
    answer, mode = _llm_rewrite(text, hits, llm, fallback)
    citations = tuple(hit.citation() for hit in hits)
    return KnowledgeAnswer(
        answer=answer,
        citations=citations,
        hits=tuple(hits),
        insufficient=False,
        mode=mode,
    )
```

`_llm_rewrite` 的失败回退规则（实现比上面长，但逻辑只有六条）：

| 情况 | 结果 `mode` | 日志 |
| --- | --- | --- |
| `llm is None` | `template` | 无 |
| `llm.enabled` 为假 | `template` | 无 |
| 既没有 `invoke_text` 也没有 `invoke` | `template` | WARNING |
| 调用抛异常 | `template` | WARNING（异常文本经 `redact_secret` 脱敏） |
| 返回空文本 | `template` | WARNING |
| 引用校验不通过 | `template` | WARNING（只记前 120 字符） |
| 全部通过 | `llm` | 无 |

模板答案长什么样（`build_template_answer`）：

```text
根据本地知识库检索结果（仅基于下列资料，未做额外推断）：
1. [02_退款与归属#1] 退款按 refunds.refund_date（退款发生日期）所在月份归集，不按订单月份，也不按审批月份。…
2. [01_指标口径#1] 退款额 = Σ 已批准退款金额；已批准退款会从毛销售额中扣除。…
以上引用来自本地知识库文档，完整口径请查看对应原文。
```

“资料不足”长什么样（`_insufficient_answer`）：

```text
现有资料不足以回答“公司食堂几点开饭”。
已检索的知识文档：01_指标口径（指标口径说明（演示口径））、02_退款与归属（退款规则与归属口径（演示口径））、…。
检索最高分低于阈值 0.15 或没有任何命中，因此不作推断。建议改用更具体的业务词（例如“退款归属”“净销售额口径”“地区说明”），或补充知识文档后重新运行 bootstrap.py 重建索引。
```

> **官方事实**：LangChain 的 RAG 教程同样把“检索 → 上下文 → 生成”分开；官方也建议在提示词里约束“只依据提供的上下文”。
>
> **项目设计选择**：本项目**不信任模型**。模型只负责“把资料改写成通顺句子”，引用真实性由程序校验，判“资料不足”的决定权在程序（阈值）而不是模型。这是企业知识问答与 demo 的核心差别：**demo 追求答得漂亮，企业追求答得可核对**。
>
> **未验证**：真实模型（DeepSeek/OpenAI）在引用格式上的遵循率未在本环境测试；本单元用替身模型验证的是“校验逻辑本身”。

```python
"""单元 11 实验：向量检索、引用与“资料不足”。

用法（在 ops-assistant 目录执行）：
    uv run python ../教程/实验/11_vector_citation.py

实验做的事：
    1) 打印索引统计（embedding 类型/维度/模型/切分参数）；
    2) 用三个同义/近义查询对比 keyword / vector / hybrid；
    3) 用模板答案演示引用结构；
    4) 用"教学替身模型"验证：合法引用被接受、伪造引用被打回；
    5) 用一个离题问题触发"现有资料不足以回答"。

from typing import Any

class StaticRewriteLLM:
    """教学替身：冒充“模型”，输出完全由脚本控制，便于验证引用校验。"""

    enabled = True

    def __init__(self, text: str) -> None:

    def invoke_text(self, messages: list[Any], temperature: float = 0) -> str:
        return self.text


def demo_semantic_gap() -> None:
    """第一段：哈希向量只看字面重合。"""
    print("\n-- 哈希向量不是语义模型 --")
    model = HashingEmbeddings(dim=512)
    pairs = (("退款", "退钱"), ("退款", "退款额"), ("销售额", "销售金额"))

        a = model.embed_query(left)
        b = model.embed_query(right)
        cosine = sum(x * y for x, y in zip(a, b))
        print(f"  cos({left!r}, {right!r}) = {round(cosine, 4)}")


def show_index_stats(kb: KnowledgeBase) -> None:
    """第二段：索引统计。"""

    print("\n== 索引统计 ==")
    print("文档数：", stats["doc_count"], "块数：", stats["chunk_count"])
    print(
        "embedding：",
        stats["embedding_type"],
        "维度：",
        stats["embedding_dim"],
        "模型：",
        stats["embedding_model"],
    )
    print("切分：", stats["chunk_size"], "/", stats["chunk_overlap"])
    print("索引文件：", stats["index_path"])
    for item in stats["documents"]:
        print(f"  - {item['doc_id']} | {item['title']} | 块数 {item['chunk_count']}")

    """第三段：三种模式对比。"""
    print(f"\n查询：{question}")
    for mode in VALID_SEARCH_MODES:
        hits = kb.search(question, k=MAX_HITS, mode=mode)
        top = hits[0] if hits else None
        top_score = round(top.score, 4) if top is not None else 0.0
        top_chunk = top.chunk.chunk_id if top is not None else "（无命中）"
        print(
            f"  mode={mode:<7} 命中={len(hits)} top_score={top_score} top={top_chunk}"
        )

    """打印一次问答结果的完整结构。"""
    answer = answer_from_knowledge(question, kb, llm)
    print(f"\n问题：{question}")
    print("insufficient：", answer.insufficient, " mode：", answer.mode)
    print("答案：")
    for line in answer.answer.splitlines():
        print("  ", line)
    if answer.citations:
        print("引用：")
        for item in answer.citations:
            print(f"   - {item['chunk_id']} | {item['title']} | {item['snippet']}")

    for question in GOOD_QUESTIONS:
        answer = answer_from_knowledge(question, kb)
        if not answer.insufficient:

    return None

        return 0

    print("\n== 模板答案与引用 ==")
    show_answer(demo_question, kb)

    print("\n== 模型改写与引用校验（教学替身，不调用真实模型） ==")

    print("\n== 资料不足 ==")
    show_answer(OUT_OF_SCOPE_QUESTION, kb)

        hits = kb.search(question, k=MAX_HITS, mode="hybrid")
        top_score = max((hit.score for hit in hits), default=0.0)
        verdict = "资料不足" if top_score < SCORE_THRESHOLD else "有依据"
        print(f"  {question}：top_score={round(top_score, 4)} → {verdict}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

## 10. 复盘问题与参考答案、下一步

### Q1：既然哈希向量也是“查 token”，那它和关键词检索有什么区别？为什么还要两路都做？

**参考**：关键词检索按“重合 token 的个数”打分，并对标题加权、按块长度开方归一化；哈希向量是“词频直方图 + 余弦”，**考虑词频、用向量夹角表示整体相似度**。两者对“短查询 vs 长块”“重复 token”的敏感度不同，融合能互补。更重要的是：两路共用同一个接口，向量那一路随时可以换成真实 embedding 模型，而代码不用改——这是**接口设计**的价值，不是算法的价值。

### Q2：为什么融合不做“按本次最高分归一化”？

**参考**：归一化会把每次检索的第一名都变成 1.0（或 0.5 加权后的固定值），于是 `top_score < 0.15` 这个条件永远不会成立，“资料不足”就永远触发不了。本项目宁可让分数“不可跨查询比较”，也要保住阈值判断力。代价是：你不能说“今天的检索质量是 0.42”，只能看命中结构、引用与评估集（单元 20）。

### Q3：为什么引用校验要求“必须出现在本次给定的块里”，而不只是“索引里存在”？

**参考**：因为模型可能引用一篇**真实存在但与本问题无关**的文档。这样引用看着有出处，实际是误导。限定“本次给定块”后，模型的引用范围被锁死在检索结果内，用户点开引用就能看到“模型是在这段资料上说的这句话”。这是最小权限原则在 RAG 里的应用：**给什么，才能引什么**。

### Q4：`load_or_build` 的兼容性判断为什么这么复杂？

**参考**：索引是磁盘上的缓存，而配置随时会变（换模型、改维度、改切分）。如果无脑复用，就会出现“用 512 维查询向量去比 384 维索引向量”的维度错误，或者“换模型后用旧块向量算新查询”的语义错配。`_is_compatible` 的三条规则（类型、远端模型名、哈希维度）覆盖了本项目全部配置面；远端场景不做维度探测是**性能取舍**（避免每次启动发请求）。判断不出来时宁可重建——重建成本是几秒，错配成本是“答案悄悄变错”。

### Q5：本单元最容易高估或低估的是什么？

**参考**：**高估**哈希向量的语义能力（它就是个词频指纹，同义改写必挂，`HASHING_NOTE` 写进索引就是防这个）；**低估**“资料不足”这条规则的价值。企业问答里，答案错误比没有答案贵得多：一个“现有资料不足以回答”能省掉一次错误的经营决策，而一个自信的错误答案不会自己暴露。0.15 阈值、引用可回查、模板兜底，三件事合起来才是“可信”。
