## 3. 通俗解释与精确技术定义

### 3.1 一句话比喻

- **LLM（大语言模型，Large Language Model）** = 一个“很会写字但不会查账”的实习生，你给它材料它写得漂亮，你让它算数字它可能编。
- **Tool（工具）** = 你给实习生配的计算器和数据库查询权限。它只能“申请使用”，真正按按钮的是你的程序。
- **Workflow（工作流）** = 你写死的流程：先查数、再核对、再写报告、最后等领导签字。
- **Agent（智能体）** = 你只写目标，让它自己决定下一步做什么、用哪个工具。
- **State（状态）** = 这单任务的工作台账，谁都能读、谁都能加一行。
- **Graph（图）** = 把“步骤”画成节点、把“下一步去哪”画成箭头的一张流程图，交给引擎按图执行。
- **Checkpointer（检查点存储）** = 流程走到一半按“存档”，断电后能读档继续。
- **Thread（会话线程）** = 存档槽位的名字。同一个 thread 才共享历史，不同 thread 互相看不见。

### 3.2 精确技术定义（术语首现双语）

| 术语 | 英文 | 精确含义 | 本项目中的例子 |
| --- | --- | --- | --- |
| 消息 | message | 模型交互的最小单位，有角色（system/human/ai/tool）与内容 | 用户问“2026 年九月销售额比八月变化多少？” |
| 提示词 | prompt | 发给模型的完整输入，通常由多条消息拼成 | 系统消息里写“金额单位是分” |
| 工具 | tool | 带名称、说明、参数结构的函数，模型可请求调用 | `query_month_sales(month)` |
| 工具调用请求 | tool call | 模型输出的一种结构化请求，**不是执行** | `{"name": "query_month_sales", "args": {"month": "2026-09"}}` |
| 状态 | state | 图执行期间共享的字典，节点返回部分更新 | `data_result`、`budget`、`trace` |
| 节点 | node | 一个接收状态、返回部分更新的普通函数 | `understand`、`compute` |
| 边 | edge | 固定的下一步指向 | `START → understand` |
| 条件边 | conditional edge | 由纯函数决定下一步去哪 | `understand --clarify--> clarify` |
| 规约器 | reducer | 决定同名状态字段如何合并（覆盖还是追加） | `trace` 用 `operator.add` 追加 |
| 检查点 | checkpoint | 某个执行步的状态快照，可读、可恢复 | 审批前存一次，重启后继续 |
| 会话线程 | thread | 隔离检查点与历史的标识 | `thread_id="demo"` |
| 检索增强生成 | RAG（Retrieval-Augmented Generation） | 先查资料再回答，并给出引用 | 查“退款归属”规则文档 |
| 评估 | evaluation | 用预先定义的标准检查输出对不对 | 用标准答案比对差额数字 |

### 3.3 业务例子（全教程贯穿）

一句真实问法：

> “2026 年九月销售额比八月变化多少？按地区分解差额，并说明销售额是否扣除了退款。那华东地区呢？”

要回答它，程序必须处理这些事（后面单元逐个拆开）：

1. 解析时间：九月 = `2026-09`，八月 = `2026-08`（**缺年份必须澄清**）。
2. 解析指标：“销售额”默认是**净销售额** = 毛销售额 − 已批准退款。
3. 查数：两个月汇总 + 5 个地区分解。
4. 算差额：总差额、地区差额、变化率；基期为 0 时变化率**无定义**。
5. 处理边界：无记录 ≠ 0；有订单但净额真 0；退款跨月归属到退款发生月；负净额要展示。
6. 查口径：退款是否扣、按什么时间归属（查知识库文档并引用）。
7. 生成报告、等人工批准、导出文件、记住“华东”这轮追问。

注意最后一问“那华东地区呢？”——它**没有时间词**。人靠上下文补全，程序要么靠历史状态补全，要么澄清。这就是后面要讲的状态与记忆。

### 3.4 三类说法必须分清（举例）

- **官方事实**：`StateGraph`、`START`、`END` 来自 `langgraph.graph`，官方 Graph API 文档这么写。
- **教学简化**：本项目知识库用“确定性哈希向量”代替真实语义向量模型，让没有密钥的机器也能跑；生产应换成真实 embedding 模型并评估召回率。教程会明确写“教学简化”。
- **项目设计选择**：金额全程用整数“分”存和算，展示时才转元/万元；代价是所有展示函数都要做单位转换，好处是绝不出现 `0.1+0.2` 的浮点误差。
- **未验证**：任何“运行后输出如下”的内容，若没在你机器上跑过，一律标注“预期（未在本环境执行）”。**本教程全体作者都没有在写作环境里执行过项目代码**：该环境无法启动进程，所以所有输出都是预期值，必须由你本人在自己机器上核对。

### 5.2 诊断脚本（完整代码）

保存路径：`教程/实验/00_diagnose.py`（在仓库根目录新建 `教程/实验/` 文件夹）。

这个脚本只读检查：Python 版本、`uv` 是否在 PATH、项目骨架是否存在、`.env` 与密钥是否配置（**只打印掩码，不打印明文**）、数据库是否已生成、依赖是否能导入。**不安装、不联网、不调用模型。**

```python
"""课程起点诊断脚本：只读检查本机是否具备继续学习的条件。

用法（在 ops-assistant 目录执行）：uv run python ../教程/实验/00_diagnose.py
说明：不安装依赖、不联网、不调用模型；密钥只打印掩码；退出码 0 表示关键项通过。
"""

from __future__ import annotations

import shutil
import sqlite3
import sys
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parents[2]
PROJECT_ROOT = REPO_ROOT / "ops-assistant"


def mask_secret(value: str | None) -> str:
    """把密钥变成可安全贴到聊天窗口的掩码。"""
    if not value:
        return "未设置"
    if len(value) <= 8:
        return "已设置（长度过短，可能是占位符）"
    return f"已设置（{value[:4]}…{value[-2:]}，长度 {len(value)}）"


def read_env_file(path: Path) -> dict[str, str]:
    """不依赖第三方库解析 .env：按 KEY=VALUE 逐行读取，忽略注释与空行。"""
    values: dict[str, str] = {}
    if not path.is_file():
        return values
    for raw_line in path.read_text(encoding="utf-8").splitlines():
        line = raw_line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        key, _, value = line.partition("=")
        values[key.strip()] = value.strip().strip('"').strip("'")
    return values


def check_python() -> tuple[bool, str]:
    major, minor = sys.version_info[:2]
    ok = (major, minor) >= (3, 11)
    return ok, f"Python {major}.{minor}.{sys.version_info[2]}（要求 >= 3.11）"


def check_uv() -> tuple[bool, str]:
    found = shutil.which("uv")
    if found is None:
        return False, "PATH 中找不到 uv（见单元 01 第 5 节安装步骤）"
    return True, f"找到 uv：{found}"


def check_skeleton() -> tuple[bool, str]:
    required = [
        PROJECT_ROOT / "pyproject.toml",
        PROJECT_ROOT / "src" / "ops_assistant" / "config.py",
        PROJECT_ROOT / "src" / "ops_assistant" / "workflow" / "state.py",
    ]
    missing = [str(p.relative_to(REPO_ROOT)) for p in required if not p.is_file()]
    if missing:
        return False, "缺少项目文件：" + "、".join(missing)
    return True, "项目骨架文件齐全"


def check_env_file() -> tuple[bool, str]:
    env_path = PROJECT_ROOT / ".env"
    example_path = PROJECT_ROOT / ".env.example"
    if not env_path.is_file():
        hint = "先复制 .env.example 为 .env" if example_path.is_file() else "项目里也没有 .env.example"
        return False, f"未找到 {env_path.name}；{hint}"
    values = read_env_file(env_path)
    model = values.get("OPS_MODEL", "")
    key = values.get("OPS_API_KEY", "")
    summary = f"OPS_MODEL={model or '空'}；OPS_API_KEY={mask_secret(key)}"
    return True, summary


def check_database() -> tuple[bool, str]:
    db_path = PROJECT_ROOT / "data" / "ops.db"
    if not db_path.is_file():
        return False, "尚未生成 data/ops.db（运行 scripts/bootstrap.py 之后才会出现）"
    try:
        conn = sqlite3.connect(f"file:{db_path.as_posix()}?mode=ro", uri=True)
        try:
            count = conn.execute("SELECT COUNT(*) FROM orders").fetchone()[0]
            months = conn.execute("SELECT COUNT(DISTINCT substr(order_date, 1, 7)) FROM orders").fetchone()[0]
        finally:
            conn.close()
    except sqlite3.Error as exc:
        return False, f"数据库存在但读取失败：{exc}"
    return True, f"订单 {count} 笔，覆盖 {months} 个月"


def check_imports() -> tuple[bool, str]:
    problems: list[str] = []
    for module_name in ("langchain", "langchain_core", "langgraph"):
        try:
            module = __import__(module_name)
        except ImportError:
            problems.append(module_name)
            continue
        version = getattr(module, "__version__", "未知版本")
        print(f"    - {module_name} {version}")
    if problems:
        return False, "无法导入：" + "、".join(problems) + "（先执行 uv sync）"
    return True, "核心依赖可导入"


def practice_dict() -> None:
    """D1 练习：读字典、返回新字典，不修改入参。"""
    record = {"month": "2026-09", "net_cents": 123456}
    updated = {**record, "region": "R_EAST"}
    print(f"    原字典未被修改：{record}")
    print(f"    新字典：{updated}")


def main() -> int:
    print("== 课程起点诊断（只读检查，不联网）==")
    print(f"仓库根目录：{REPO_ROOT}")
    print(f"项目目录：{PROJECT_ROOT}")

    checks: list[tuple[str, bool, str]] = []
    checks.append(("Python 版本", *check_python()))
    checks.append(("uv 工具", *check_uv()))
    checks.append(("项目骨架", *check_skeleton()))
    checks.append((".env 配置", *check_env_file()))
    checks.append(("数据库", *check_database()))
    checks.append(("依赖导入", *check_imports()))

    print("\n== 检查结果 ==")
    for name, ok, detail in checks:
        flag = "通过" if ok else "未通过"
        print(f"[{flag}] {name}：{detail}")

    print("\n== D1 小练习参考实现 ==")
    practice_dict()
```

## 8. 失败与边界实验（至少 3 个）

### 实验 8.1：在错误目录运行

```powershell
cd "D:\MySpace\LangChain学习路线"
uv run python 教程/实验/00_diagnose.py
```

预期（未在本环境执行）：`uv` 可能报“找不到 pyproject.toml”或使用了一个空的临时环境，随后脚本报 `无法导入：langchain…`。

**要理解的点**：脚本用 `Path(__file__)` 定位路径，所以它能正确定位仓库；失败的是**依赖环境**，不是路径。这两类错误必须分开排查。

### 实验 8.2：`.env` 存在但没有 key

把 `.env` 里的 `OPS_API_KEY=` 留空（保留 `OPS_MODEL`）。

预期（未在本环境执行）：`.env 配置` 一行显示 `OPS_API_KEY=未设置`，脚本不崩、不报错退出。

**要理解的点**：本项目设计是“模型缺失 = 降级为纯规则模式”，不是“启动失败”。这条设计在后面单元 01 会用 `llm_enabled=False` 复现。

### 实验 8.3：`.env` 用 GBK 保存

用记事本把 `.env` 另存为“ANSI”编码，再运行脚本。

预期（未在本环境执行）：`read_text(encoding="utf-8")` 抛 `UnicodeDecodeError`，脚本以非 0 退出。

**要理解的点**：文本文件编码错误是 Windows 上最高频的“玄学错误”。修法：用 VS Code 右下角把编码改成 `UTF-8` 再保存；或者代码里改用 `errors="replace"` 并明确记录（但那是掩盖问题，不推荐）。

### 实验 8.4：数据库存在但表结构不对

如果 `data/ops.db` 是一个空 SQLite 文件（0 字节或没有 `orders` 表）。

预期（未在本环境执行）：`check_database()` 捕获 `sqlite3.Error`，输出 `数据库存在但读取失败：no such table: orders`，而不是抛出一大段堆栈。

**要理解的点**：“文件存在”和“数据可用”是两件事。后面的图表状态也一样：有 checkpoint ≠ 有正确结果。

## 10. 复盘问题与参考答案、下一步

### Q1：为什么本教程把“22 个单元”拆成六阶段，而不是直接讲项目？

**参考**：项目里同时存在五种难度不同的东西：模型调用、结构化约束、工具循环、图编排、持久化与人工审批。一次性塞进去，初学者只能复制粘贴，出错时无法定位是哪一层的问题。分阶段的价值是**每阶段结束你都有一个可独立验证的能力**（比如阶段三结束，你能不靠项目独立写出带预算和存档的图）。代价是学完前五个阶段之前，你看不到完整项目——这是**教学简化**。

### Q2：“工具调用请求”和“工具执行”有什么区别？为什么必须分清？

**参考**：模型输出的 `tool_calls` 只是一个 JSON 结构的**申请**，程序必须校验参数、真正调用函数、把结果作为 `ToolMessage` 送回模型，模型才可能继续。把“模型说它查过了”当成“工具已执行”，是 Agent 项目里最典型的造假来源。本项目在设计上要求每个工具返回 `{"ok": true/false, ...}` 并附 `sources`（SQL 与参数），就是为了让“到底执行没执行”可审计。

### Q3：为什么金额要用整数“分”，而不是浮点“元”？

**参考**：浮点数无法精确表示 0.1，累加几十万笔订单会出现分位误差，而财务口径必须分毫不差。本项目所有 `*_cents` 字段都是 `INTEGER`，展示时才除以 100；变化率这类除法结果是 `float`，只在展示层使用并保留固定小数位。这是**项目设计选择**，代价是每个展示函数都必须处理单位与负数。

### Q4：“九月销售额”为什么不直接当成 2026-09？

**参考**：数据范围是 `2025-01`～`2026-09`，跨了两个年度，“九月”可能指 2025-09 或 2026-09。本项目规定：问题缺年份时 `needs_clarification=True`，澄清话术里必须包含数据范围。宁可多问一句，也不要猜——猜错会让整份报告的数字全错，而且很难被发现。

### Q5：为什么教程要求反复说“未验证”？

**参考**：因为**未验证的确定性**是最容易被面试官击穿的地方。写“已通过全部测试”但拿不出记录，比写“本次环境无法执行，命令与检查点如下”要糟糕得多。本教程的写作环境确实无法启动进程（`pwsh` 返回 `0xC0000142`），所以全体输出标注“预期”。你自己跑通之后，可以把它改成“我本机实测”，并附上你的输出片段——那才是你的证据。
