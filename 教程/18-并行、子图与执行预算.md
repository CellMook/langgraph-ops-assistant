## 3. 通俗解释与精确技术定义

**人话**：

- 并行 = 两条支路可以同时干活，最后汇合。
- 子图 = 把一坨节点打包成一个"大节点"，父图不用关心里面细节。
- 预算 = 给这一轮设一个"最多走几步、最多调几次工具"的上限，超了就停。

**定义**：

- **superstep**：Pregel 式执行的一轮；同一轮里被触发的节点可以并行执行，全部完成后进入下一轮。
- **join（汇合）**：普通多入边可能在不同 superstep 分别触发汇合；等待指定上游全部完成使用 `builder.add_edge(["a", "b2"], "join")` 屏障。
- **子图**：编译后的图可以当作父图的一个节点；父子之间通过状态（或显式输入输出转换）传递数据。
- **预算（budget）**：在状态里维护计数，每个节点进入前检查；超限时写一个终止状态并由路由送到统一 `fail` 出口。

**本项目为什么"只用并行思想、不做多 Agent 并行"？**

【项目设计选择】主链路是严格串行的业务口径：先解析、再检索、再取数、再计算、再审批。这里没有"两个专家各说各话再投票"的空间——数字必须唯一。并行只在两个地方有意义：前端同时展示（表格/图）和未来的"多地区独立查询"。把串行口径硬拆成多 Agent，会增加不确定性和调试成本，属于"为了用框架而用框架"。

## 4. 在主项目中的位置

- `workflow/graph.py`：10 个节点、4 处条件路由、`export/clarify/fail → END`；没有并行分支（有意为之）。

## 5. 文件、完整代码、配置与命令

保存为 `教程/实验/18_parallel_subgraph_budget.py`：

```python
"""实验 18：并行分支 + reducer、子图、预算耗尽。"""

from __future__ import annotations

import dataclasses
import operator
from typing import Annotated, TypedDict

from langgraph.graph import END, START, StateGraph

from ops_assistant.config import load_settings
from ops_assistant.workflow.persistence import AppRuntime

QUESTION = "2026 年九月销售额比八月变化多少？按地区分解差额，并说明销售额是否扣除了退款。"


# ---------- 1) 并行：两个分支各写一个字段，用 reducer 合并 ----------
class ParallelState(TypedDict, total=False):
    question: str
    notes: Annotated[list[str], operator.add]   # reducer：追加而不是覆盖


def branch_sql(state: ParallelState) -> dict:
    return {"notes": ["sql: 查了 2026-09 与 2026-08 的月度汇总"]}


def branch_doc(state: ParallelState) -> dict:
    return {"notes": ["doc: 检索了指标口径与退款归属"]}


def join(state: ParallelState) -> dict:
    return {"notes": [f"join: 共收到 {len(state.get('notes') or [])} 条上游结果"]}


def build_parallel_graph():
    builder = StateGraph(ParallelState)
    builder.add_node("sql", branch_sql)
    builder.add_node("doc", branch_doc)
    builder.add_node("join", join)
    # START 同时连两条边：两条分支在同一 superstep 被触发
    builder.add_edge(START, "sql")
    builder.add_edge(START, "doc")
    builder.add_edge("sql", "join")
    builder.add_edge("doc", "join")
    builder.add_edge("join", END)
    return builder.compile()


# ---------- 2) 子图：把两个节点打包成一个节点 ----------
class SubState(TypedDict, total=False):
    value: int
    log: Annotated[list[str], operator.add]


def increment(state: SubState) -> dict:
    return {"value": int(state.get("value") or 0) + 1, "log": ["subgraph: +1"]}


def double(state: SubState) -> dict:
    return {"value": int(state.get("value") or 0) * 2, "log": ["subgraph: *2"]}


def build_subgraph():
    builder = StateGraph(SubState)
    builder.add_node("increment", increment)
    builder.add_node("double", double)
    builder.add_edge(START, "increment")
    builder.add_edge("increment", "double")
    builder.add_edge("double", END)
    return builder.compile()


class ParentState(TypedDict, total=False):
    value: int
    log: Annotated[list[str], operator.add]


def parent_start(state: ParentState) -> dict:
    return {"value": int(state.get("value") or 0), "log": ["parent: 开始"]}


def build_parent_graph():
    sub = build_subgraph()
    builder = StateGraph(ParentState)
    builder.add_node("start", parent_start)
    builder.add_node("calc", sub)          # 子图直接当一个节点用
    builder.add_edge(START, "start")
    builder.add_edge("start", "calc")
    builder.add_edge("calc", END)
    return builder.compile()


def main() -> None:
    # --- 并行 ---
    parallel = build_parallel_graph()
    result = parallel.invoke({"question": "demo"})
    print("并行分支写入的 notes：")
    for note in result["notes"]:
        print("  -", note)

    # --- 子图 ---
    parent = build_parent_graph()
    sub_result = parent.invoke({"value": 5})
    print("子图执行后 value =", sub_result["value"], "（期望 (5+1)*2 = 12）")
    print("子图 log =", sub_result["log"])

    # --- 预算耗尽 ---
    settings = load_settings()
    tight = dataclasses.replace(settings, max_steps=2)
    runtime = AppRuntime.create(tight, use_memory_checkpointer=True)
    try:
        turn = runtime.invoke_turn(QUESTION)
        print("预算受限时的状态：", turn["status"])
        print("错误信息：", turn["errors"])
    finally:
        runtime.close()


if __name__ == "__main__":
    main()
```

## 7. 修改练习

**练习 1（把 reducer 拿掉，改坏它）**：把 `notes` 的注解改成 `list[str]`，重跑。

- 预期现象：同一 superstep 并行写默认单值字段会抛 InvalidUpdateError；
- 结论：并行 + 非 reducer 字段 = 静默丢数据。这正是本项目 `sources` 的已知风险。

**练习 2（子图换映射）**：让子图接收父图的一个嵌套字段（例如 `payload: {"value": 5}`），自己在子图入口/出口做转换。

- 目的：体会"父子状态不是自动同名映射"，需要显式适配。

**练习 3（预算调优）**：把 `max_steps` 从 2 调到 12，观察状态从 `budget_exceeded` 变成 `awaiting_approval`；再把 `max_tool_calls` 调到 1。

- 预期：`max_tool_calls=1` 时在 `data` 节点被拦下，`errors` 里同样是 `BUDGET_EXCEEDED`。

## 8. 失败与边界实验

1. **两个分支写同一非 reducer 字段**：把 `value` 同时写 int（一个 +1、一个 *2）→ 同一 superstep 会抛 `InvalidUpdateError`，不会随机覆盖。结论：并行字段必须有 reducer 或只让一个分支写。
2. **子图里再嵌套子图**：可以，但调试成本陡增；用 `stream(..., "updates")` 看每层输出，别靠猜。
3. **预算设成 0**：环境变量 OPS_MAX_STEPS=0 会被范围校验拒绝；合法 OPS_MAX_TOOL_CALLS=0 则应阻断工具并返回 budget_exceeded，不得变成默认 8。
4. **并行分支抛异常**：一个分支 `raise`，整轮失败；LangGraph 不会"部分成功继续"。若要容错，分支内部自己 `try/except` 并写 `errors`（本项目 `errors` 就是 reducer）。
5. **把主工作流改成并行**：试着让 `knowledge` 和 `data` 并行——应在 understand 之后分叉。两支共同依赖 understand 不妨碍并行；仍须处理共享 SQLite 连接、sources 合并和真正的汇合屏障。本项目选择串行以减少复杂度。

## 10. 复盘问题与参考答案、下一步

**Q1：LangGraph 的并行是线程/协程并行吗？**
A：不是"你写 `async` 就并行"。它是按 superstep 调度：同一轮被触发的节点可以并发执行；具体并发实现由执行器决定。业务正确性不应依赖"谁先跑完"。

**Q2：join 节点会不会被执行两次？**
A：通常不会：它在一轮里被触发一次，输入是各上游已合并的状态。但具体触发语义与版本相关，本单元标注为〔未验证〕，请以 `stream` 输出确认。

**Q3：预算为什么不用 `recursion_limit` 就够？**
A：`recursion_limit` 是最后一道保险（超了会抛异常）；预算是在业务层提前、可控地停下，并给出可操作错误信息（"调高 OPS_MAX_STEPS 或缩小问题范围"）。两者职责不同。

**Q4：什么情况下值得拆多 Agent？**
A：任务可分解为**目标不同、工具不同、可独立评估**的子任务，且允许结果有不确定性（例如"研究员 + 审查员"）。如果子任务共享同一套口径且要求数字唯一，拆多 Agent 只会增加不一致风险。
